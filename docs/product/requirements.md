# 📋 요구사항 명세서 — SFOOD IT Editor

## 🎯 서비스 개요
- 사내 직원이 개인 문서를 Markdown으로 작성해 Confluence에 보관하고, 원할 때 Tech Blog 등 외부 뷰어에 게시할 수 있게 하는 사내 전용 문서 작성·게시 도구다.
- 기존에는 sfood-it-tech-blog(Viewer, 게시된 글을 읽는 뷰어) 저장소에 작성 기능이 함께 있었으나, 작성/게시 책임을 이 프로젝트로 분리했다.
- 핵심 사용자는 사내 직원이며, 특히 Tech Blog에 글을 쓰는 필자다. 다만 Confluence Space 자체는 IT팀 외 직원도 접근할 수 있다는 전제를 둔다.
- 해결하려는 문제: 필자가 초안을 편하게 작성·보관하다가, 본인이 원하는 시점에만 선택적으로 외부에 공개(게시)할 수 있는 워크플로가 필요하다. 초안 상태에서는 작성자 본인 외 누구에게도 보이지 않아야 한다.

## ✅ 핵심 기능 목록
- AX Auth(사내 MS 계정)를 통한 로그인
- 개인 문서함 — 로그인한 사용자가 작성한 문서 목록 조회
- 문서 작성·수정·삭제 (Markdown 기반)
- 문서에 이미지 첨부
- 문서 태그 지정 (다중 태그, 자유 텍스트)
- 게시 설정 — 게시 여부, 공개 경로(slug), 메타 설명, 노출 대상 뷰어 지정
- 초안-게시 생명주기 — 초안은 작성자 외 다른 직원에게 숨겨지고, 게시하면 Confluence Space 구성원 누구나 조회 가능해짐
- (참고, 이 프로젝트 범위 밖) 게시된 문서에 대한 댓글 — 별도 Viewer 프로젝트가 자체 기능으로 제공. 이 프로젝트는 댓글이 Confluence에 저장되는 구조만 정의한다.
- **사용자 계정 정보 관리(2026-09-03 추가)** — 로그인한 이메일만으로는 "누구인지" 알 수 없던 문제를 해소한다. 신규 가입자는 첫 로그인 직후 온보딩 팝업에서 이름·팀을 입력하고, 이후에도 계정 정보 팝업으로 언제든 수정할 수 있다. 계정 표시는 이제 "이름(이메일)" 형식을 쓴다. 계정별 접속 허용 여부(Y/N)를 관리자가 통제할 수 있는 필드도 함께 둔다 — 신규 가입자는 기본 허용(Y)이며, 관리자가 필요한 계정만 개별적으로 차단(N)한다. 차단된 계정은 MS 로그인(AX Auth) 자체는 성공하더라도 `/editor` 메인 화면에는 진입할 수 없다.
- **최상단 계정 관리 페이지(2026-09-03 추가)** — 전체 계정(이메일·이름·팀·접속 허용 여부)을 한 곳에 모아 검색할 수 있는 페이지. 페이지 공유 기능의 "공유 대상 검색"과 관리자의 계정 상태 확인에 공용으로 쓰인다.
- **페이지 공유(2026-09-03 추가)** — 문서 작성자가 다른 사내 계정을 검색해 문서를 공유하면, 공유받은 사람도 그 문서를 조회·편집할 수 있다(별도의 읽기 전용 공유는 이번 범위 밖). 공유받은 문서는 문서함 사이드바 상단에 별도 영역으로 분리해 보여준다.
- **문서 폴더 구조(2026-09-07 추가, 계획 단계)** — [Confluence·Notion 비교 리포트](https://claude.ai/code/artifact/5b088947-cb55-4370-8b61-176510385f84)에서 지적된 가장 뚜렷한 격차를 해소한다. 현재는 계정 폴더 1개 아래 모든 문서가 다중 태그로만 분류되어, 문서 수가 늘어날수록 "이 문서들이 하나의 세트다"라는 관계를 표현할 방법이 없다. 사용자가 자유롭게 폴더를 만들고 문서를 그 안에 배정·이동할 수 있게 한다(폴더는 문서당 최대 1개, 태그와는 다른 축). 상세 계획은 [prd.md의 Phase 7](./prd.md#-단계별-개발-계획) 참고.

## 🗄️ 데이터 요구사항
자체 데이터베이스 없이 Confluence Cloud를 유일한 저장소로 사용한다.
- 문서 본문 원본(Markdown) — Confluence content property(`sourceMarkdown`). Confluence 페이지 본문(storage format)은 렌더링용 산출물이고, 편집 원본은 별도로 보관한다.
- 작성자 식별 — content property(`authorMeta.actualAuthorEmail`). 실제 Confluence 쓰기는 공용 서비스 계정으로 이루어지므로, 진짜 작성자는 이 property로만 구분한다.
- 게시 메타데이터 — content property(`publishMetadata`): 공개 여부, 게시 시각, 노출 대상 뷰어별 slug·메타 설명 (뷰어가 늘어나도 확장 가능한 구조).
- 태그 — Confluence 네이티브 페이지 라벨(label) 기능을 그대로 사용.
- 댓글 작성자 식별 — 댓글(footer comment) content에 딸린 content property(`commenterMeta`: email, name, isEmployee). 다른 프로젝트(Viewer)가 쓰고 읽는다.
- **계정 정보(2026-09-03 추가)** — 계정 폴더 content property(`accountMeta`): 이름, 팀, 접속 허용 여부(Y/N), 온보딩 완료 시각. 별도 DB 없이 기존 계정 폴더 구조를 그대로 확장한다.
- **계정 관리 인덱스(2026-09-03 추가)** — Space 최상단에 별도로 둔 "계정 관리" 페이지의 content property(`accountIndex`): 전체 계정의 이메일·이름·팀·접속 허용 여부·계정 폴더 ID 목록. 계정 정보가 바뀔 때마다 갱신되며, 계정 검색(공유 대상 검색 포함)의 유일한 조회 대상이다(Space 전체 스캔 없음).
- **공유 정보(2026-09-03 추가)** — 문서 content property(`sharingMeta`): 공유 대상 이메일 목록, 마지막 수정자(이메일·이름·수정 시각). 공유받은 사람 쪽에서 목록을 빠르게 조회할 수 있도록, 공유 대상 계정 폴더의 content property(`sharedDocumentRefs`)에도 문서 참조를 함께 기록한다.

## 🔗 외부 연동·알림 요구사항
- **Confluence Cloud REST API** — 서비스 계정(Basic Auth, API 토큰)으로 문서 저장소 역할을 한다.
- **AX Auth(사내 공통 인증 서비스)** — 로그인 시작 URL 제공, 로그인 토큰 검증(대행 SSO). 메일 발송 기능도 제공하나, 현재 실제로 호출되는 곳은 없고 향후(예: 댓글 알림) 사용을 염두에 두고 준비돼 있다.
- **Slack Incoming Webhook** — Confluence 연동 실패 등 운영 이상 감지 시 알림.

## 🗓️ 우선순위와 일정
- 1차: Confluence 콘텐츠 구조 확정 및 구현 — 초안/게시 생명주기, 숨김 메커니즘, 태그, 게시 메타데이터의 뷰어별 확장, 댓글 저장 구조. (완료)
- 2차: 개인 에디터 기능 강화 — 2026-08-27 프로덕션 준비도 감사로 상세 요구사항이 도출되어 [prd.md의 Phase 4](./prd.md#-단계별-개발-계획)로 반영됨(37개 세부 항목). 진행 방식은 [CLAUDE.md](../../CLAUDE.md)의 "작업 루틴" 참고.
- 3차: 사용자 계정 관리 + 페이지 공유 — 2026-09-03 사용자와의 대화로 범위·핵심 결정 사항을 확정하고 [prd.md의 Phase 5·6](./prd.md#-단계별-개발-계획)으로 반영됨. 신규 가입자 기본 접속 허용(Y), 관리자의 접속 권한 변경은 이번 단계에서는 별도 화면 없이 수동 스크립트로 운영, 계정 검색은 최상단 "계정 관리" 페이지 기반, 동시 편집 충돌은 기존 버전 충돌 감지(P0-3)에 마지막 수정자 표시만 추가하는 것으로 범위를 정했다.
- 4차: 문서 폴더 구조 — 2026-09-07 [Confluence·Notion 비교 리포트](https://claude.ai/code/artifact/5b088947-cb55-4370-8b61-176510385f84)를 근거로 [prd.md의 Phase 7](./prd.md#-단계별-개발-계획)로 반영됨. 폴더는 문서당 최대 1개(태그와 다른 축), 중첩 최대 5단계, 기존 문서는 전부 "미분류"로 시작(자동 마이그레이션 없음), 문서 이동은 드래그앤드롭 없이 "이동" 메뉴로 먼저 구현하는 것으로 범위를 정했다. 핵심 데이터 모델(실제 Confluence 페이지 트리 vs property 기반 가상 구조)은 아직 결정되지 않아 [Issue #65](https://github.com/sfood-pioneer-1st/sfood-it-editor/issues/65)로 등록해 두었다.
- 목표 일정: 미정
