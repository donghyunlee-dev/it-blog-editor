# P17-25: 제목·본문 입력 영역 왼쪽 위치·폭 불일치 수정 — task

## 배경
사용자 리포트: "지금 제목 입력 div와 내용 입력하는 div의 왼쪽 위치와 가로 width 폭이
다른 것 같아. 확인해서 문제를 찾고 개선 방향을 세워줘."

같은 요청에 포함된 두 번째 항목("라이트 모드 배경/입력 모드 화이트 색감이 너무
오래된 스타일 — 노션/컨플루언스 색감 참고해 보완")은 조사 결과 `--color-background`
/`--color-surface`/`--color-border`가 이 프로젝트 코드가 아니라 `@sfood/ui`가 내려주는
디자인 시스템 토큰(CLAUDE.md "UI 컴포넌트" 절 — 이 토큰들을 프로젝트 CSS에서
하드코딩·재정의하지 않는다)이라, 그대로 진행하면 그 규칙과 정면으로 충돌한다는 것을
발견했다. 사용자에게 처리 방향(①이번만 예외로 프로젝트 CSS에서 재정의 ②디자인
시스템 쪽에 변경 요청 ③토큰 값은 그대로 두고 사용법만 조정 ④보류)을 확인한 결과
**"일단 보류"**를 선택해, 이번 task는 첫 번째 항목(위치·폭 불일치)만 다룬다.

## 원인 조사
Playwright 없이 임시 라우트(`/dev-preview-editor-canvas`, AX Auth 게이트 밖 — 검증
후 즉시 삭제)로 `DocumentEditor`를 직접 마운트해 `getBoundingClientRect()`/
`getComputedStyle()`로 실측했다.

- 제목(`<textarea aria-label="제목">`): `-mx-2 w-full ... px-2` — 포커스 시에만
  배경이 살짝 넓게 깔리도록 패딩을 같은 크기의 음수 마진으로 상쇄하는 기존 패턴
  (주석 "박스도 테두리도 없는 캔버스라..." 참고).
- 본문(`RichTextEditor.tsx`의 `.ProseMirror`): 같은 상쇄 패턴이지만 마진/패딩이
  12px(0.75rem)이고, `width`를 명시하지 않아 브라우저 기본값(`width: auto`, block
  요소)을 쓴다.
- **차이**: `width: auto`인 `.ProseMirror`는 음수 마진(-12px×2)만큼 박스 자체가
  저절로 넓어져(944px, 부모 920px + 24px) 좌우 테두리가 정확히 부모 컬럼의 양쪽
  끝에 맞춰진다. 반면 제목 textarea는 `w-full`(`width: 100%` = 920px로 **고정**)이라
  음수 마진(-8px×2)을 줘도 박스가 넓어지지 않고 그 자리에서 옆으로 밀리기만 한다 —
  왼쪽은 우연히 부모 왼쪽 끝과 맞아떨어지지만(마진 -8 + 패딩 8 = 0 상쇄), 오른쪽은
  박스 자체 폭이 늘지 않아 부모 오른쪽 끝보다 16px(패딩 8px×2) 짧아진다.
- 실측(1009px 뷰포트, 본문 컬럼 920px 기준): 제목 텍스트 영역 `44.5px ~ 948.5px`
  (폭 904px) vs 본문 텍스트 영역 `44.5px ~ 964.5px`(폭 920px). **왼쪽 시작 위치는
  이미 같았고(44.5px), 사용자가 느낀 차이는 실제로는 오른쪽 폭(16px)이었다.**

## 수용 기준 (Acceptance Criteria)
- [x] 제목 입력 영역과 본문 입력 영역의 텍스트 시작 x좌표가 같다(기존에도 같았음 —
      회귀 없음을 확인).
- [x] 제목 입력 영역과 본문 입력 영역의 텍스트 가용 폭(width)이 같다 — 좁은 화면
      (Normal 920px)·넓은 화면(Wide 1200px) 모두에서.
- [x] 포커스 시 배경이 넓어지는 기존 UX(레이아웃이 움직이지 않는 낙관적 하이라이트)는
      그대로 유지된다.

## 결정이 필요한 사항
- 색상(2번 요청)은 위 "배경" 절에서 설명한 CLAUDE.md 충돌로 사용자에게 직접 확인 —
  **"일단 보류"**로 결정됨. 이 task의 범위에서 제외한다. 재개하려면 위 4가지 방향
  중 하나를 다시 선택해야 한다.

## 범위 밖
- 라이트 모드 배경/표면 색상 변경(위 "결정이 필요한 사항" 참고, 보류).
- `.ProseMirror`/본문 쪽 수치를 바꾸는 것 — 본문은 기존에도 의도한 대로 동작하고
  있었으므로, 제목 쪽만 본문에 맞춘다(반대 방향이 아니다).
