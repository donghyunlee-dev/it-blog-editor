# P17-25: 제목·본문 입력 영역 왼쪽 위치·폭 불일치 수정 — 구현 결과 보고서

## 구현 내용
`DocumentEditor.tsx`의 `TitleTextarea`가 쓰던 `w-full`(`width: 100%`, 부모 컬럼 폭에
고정된 값)을 `w-[calc(100%+1rem)]`로 바꿨다. `-mx-2`(음수 마진 8px×2)로 포커스 시
배경만 넓게 깔리게 하는 기존 트릭은 `width: auto`인 요소(본문의 `.ProseMirror`)에서만
음수 마진만큼 박스가 저절로 넓어진다 — `width: 100%`처럼 값이 고정된 요소는 마진을
줘도 자리만 옮겨갈 뿐 넓어지지 않아, 제목 텍스트의 오른쪽 끝이 본문보다 16px(패딩
8px×2) 짧아지는 실제 버그였다. `calc(100% + 1rem)`으로 마진이 줄이는 만큼을 폭에
미리 더해 본문과 동일하게 좌우 대칭으로 확장되도록 맞췄다.

두 번째 요청(라이트 모드 배경/입력 모드 색감을 노션·컨플루언스풍으로 개선)은 조사
결과 관련 토큰(`--color-background`/`--color-surface`/`--color-border`)이 이
프로젝트 코드가 아니라 `@sfood/ui`가 내려주는 디자인 시스템 값이라, CLAUDE.md
"UI 컴포넌트" 절의 "@sfood/ui가 이미 값을 제공하는 토큰을 프로젝트 CSS에서
하드코딩·재정의하지 않는다" 규칙과 충돌한다는 것을 발견했다. 사용자에게 처리
방향을 확인한 결과 **"일단 보류"**로 결정돼 이번 구현 범위에서 제외했다(`task.md`
"결정이 필요한 사항" 참고).

## 자체 검토 (Self-Review)
### 긍정 사항
- 추측으로 CSS 값을 바꾸지 않고, 임시 디버그 라우트(P17-21에서 쓰던 것과 같은
  패턴)로 실제 `getBoundingClientRect()`/`getComputedStyle()`을 찍어 정확한 원인
  (`width: 100%` vs `width: auto`의 음수 마진 확장 차이)을 먼저 확인한 뒤 고쳤다.
- 색상 요청이 조직 규칙(CLAUDE.md)과 충돌한다는 것을 발견했을 때 임의로 규칙을
  어기거나 무시하지 않고, 구체적인 선택지 4개를 제시해 사용자가 직접 결정하게 했다.

### 주의사항
- 색상 개선은 보류 상태로 남아 있다 — 사용자가 나중에 재개하려면 `task.md`의 4가지
  방향 중 하나를 다시 선택해야 한다.
- `/editor/[pageId]`가 AX Auth(MS SSO) 로그인 뒤에 있어 실제 로그인 세션에서의
  최종 화면은 이 세션에서 직접 보지 못했다 — 임시 라우트에서의 실측 검증으로
  대체했다(검증 후 즉시 삭제, 빌드 결과에 남지 않음을 확인).

### 우려사항
- 없음 — 클래스 하나(`w-full` → `w-[calc(100%+1rem)]`)만 바꿨고, 실측으로 좌우
  정확히 일치함을 확인했다. 관련 테스트(DocumentEditor 46개) 전부 통과.
