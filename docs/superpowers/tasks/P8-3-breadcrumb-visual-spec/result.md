# P8-3: 브레드크럼 시각 스펙 정의 — 결과

## 커밋
- `6c75977` feat: 브레드크럼 항목 간 간격을 8px로 조정 (P8-3)

## 변경 파일
- `src/components/editor/DocumentEditor.tsx` — 브레드크럼 `nav`(바깥)와 각 폴더 `span`(안쪽,
  구분자 `/` + 링크를 감싸는 그룹) 둘 다 `gap-1`(4px) → `gap-2`(8px)로 변경했다. 두 곳을
  같은 값으로 맞춰야 구분자·링크가 전체 시퀀스에서 균등하게 8px씩 벌어진다. 주석으로
  design.md의 나머지 3개 값(폰트 13px, 색 #595959, margin-bottom:16px)을 왜 적용하지
  않았는지 근거를 남겼다(자세한 내용은 `task.md`).
- `src/components/editor/DocumentEditor.test.tsx` — 새 테스트 1개: 브레드크럼 `nav`와 폴더
  세그먼트에 `gap-2` 클래스가 있고 옛 `gap-1`은 없음을 확인.

## 자체 검토
- **긍정**: "레퍼런스 값을 그대로 베낀다"가 아니라, 이 프로젝트가 이미 갖고 있는 더 상위
  규칙(전역 타이포 스케일 잠금, 토큰 우선 원칙, 고정 헤더 높이)과 대조해 실제로 적용
  가능한 값만 골라 반영했다 — P8-7이 같은 이유로 타이포 스케일 전체를 보류한 것과 일관된
  판단 기준이다.
- **주의사항**: 이번 변경으로 브레드크럼이 레퍼런스와 픽셀 단위로 완전히 같아지지는
  않는다(폰트 14px vs 13px, 색 `#6b7280` vs `#595959`) — 이는 의도된 결과이고, task.md에
  "왜 다른 채로 두는지"를 명시했다.
- **우려사항**: AX Auth 로그인 제약으로 이 세션에서는 실제 브라우저로 간격 변화를
  스크린샷으로 확인하지 못했다(P7-7·P8-1·P8-4·P8-6과 동일한 한계) — Tailwind 클래스
  적용 여부로 대신 검증했다.
