# P8-3: 브레드크럼 시각 스펙 정의

## 배경
support.claude.com/ko 벤치마킹(`docs/product/design.md` "벤치마킹" 절 "5. 본문 콘텐츠 상단")에서
레퍼런스 브레드크럼의 실측값(13px/400, 색 `#595959`, 항목 간 `gap:8px`+구분자,
`margin-bottom:16px`)을 기록했고, PRD는 이 값을 P7-7(문서 편집 화면 브레드크럼, 이미 완료)의
시각 스펙으로 채택해 별도 스타일 보정 커밋으로 적용하라고 계획했다.

관련 PRD 항목: `docs/product/prd.md`의 **P8-3**(Phase 8, 에디터 UI 레이아웃 벤치마킹).

## 수용 기준 (Acceptance Criteria)
- [x] design.md의 실측 스펙 4가지(폰트 크기/색/항목 간 gap/margin-bottom) 각각에 대해
      이 프로젝트에 그대로 적용 가능한지 판단하고, 적용하거나 적용하지 않은 이유를 명시한다.
- [x] 실제로 적용 가능한 값(항목 간 gap)은 `DocumentEditor.tsx`의 브레드크럼에 반영한다.
- [x] 회귀 테스트로 새 간격이 적용됨을 고정한다.
- [x] 기존 P7-7 브레드크럼 테스트(4개)에 회귀가 없다.

## 결정이 필요한 사항
없음 — 아래 3가지는 이미 이 프로젝트에 존재하는 더 상위의 확정된 규칙(design.md "2. 사이즈"
표, CLAUDE.md 하드코딩 금지 규칙)에 따라 판단할 수 있는 구현 디테일이라 GitHub Issue 없이
직접 정했다(P8-7이 타이포 스케일 전체를 "이번 Phase에서 바꾸지 않는다"고 결론 낸 것과 같은
근거).

1. **폰트 크기 13px는 적용하지 않는다.** design.md "2. 사이즈" 표가 "헤더 버튼/링크"를
   명시적으로 `text-sm`(14px)로 고정하고 "표 밖의 임의 값을 새로 쓰지 않는다"고 못박아
   뒀다 — 브레드크럼은 이 표의 "UI 크롬" 범주에 해당하므로, 벤치마크 실측값(13px)보다
   이 프로젝트가 이미 확정한 전역 타이포 규칙이 우선한다(허용 오차 범위, P8-7이 본문
   타이포 스케일을 그대로 둔 것과 같은 판단 기준).
2. **색상 `#595959`를 하드코딩하지 않는다.** CLAUDE.md 규칙(`@sfood/ui`가 이미 값을 제공하는
   토큰을 별도로 하드코딩·재정의하지 않는다)에 따라, 이미 이 브레드크럼에 쓰이고 있는
   `text-muted`(`--color-muted`, `#6b7280`) 토큰을 그대로 유지한다. 정확히 같은 색은 아니지만
   (허용 오차 범위) 대응하는 의미론적 토큰이 이미 있는데 임의 hex를 새로 도입하는 것은
   프로젝트 규칙 위반이다.
3. **`margin-bottom:16px`는 적용하지 않는다.** 레퍼런스는 브레드크럼이 제목 위에 별도 행으로
   쌓여 있어 그 값이 "브레드크럼과 제목 사이 수직 간격"을 뜻하지만, 이 프로젝트의 브레드크럼은
   고정 높이(`h-14`) 헤더 바 안에 뒤로가기 버튼과 나란히 배치돼 있어(P7-7의 기존 설계) 구조
   자체가 다르다 — 여기에 `margin-bottom`을 주면 헤더 높이가 깨진다(design.md "헤더(공통)"
   절의 `h-14` 고정 결정과 충돌). 헤더 재구조화는 Phase 8의 범위 밖이다.

## 범위 밖
- 브레드크럼을 레퍼런스처럼 헤더 바깥(제목 위 별도 행)으로 재배치하는 것 — 헤더 구조 변경은
  Phase 8 범위 밖(design.md "범위 밖" 절 — "헤더 높이 변경... 이미 유사해 불필요").
- 폰트 크기·색상 변경(위 "결정이 필요한 사항" 참고).
