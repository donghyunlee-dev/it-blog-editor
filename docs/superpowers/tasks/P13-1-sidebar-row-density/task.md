# P13-1: 사이드바 문서함 행 밀도·들여쓰기 조정

## 배경
사용자가 폴더 2~3개·문서 10개 미만으로 실사용 테스트를 하던 중(2026-09-14, 캡처로 확인)
"문서가 10개도 안 되는데 리스트 영역의 2/3이 찬다"고 지적했다. 코드 실측 결과 폴더 행·문서
행 모두 `py-2`(상하 8px, P8-2에서 문서 행과 높이를 맞추려고 `py-1.5`에서 올린 값)를 쓰고 있어
`text-sm`(줄높이 20px) 대비 padding 비중이 커 한 행이 36px를 차지했고, 검색창·새 문서 버튼·
`nav` 패딩·폴더 라벨 여백이 트리 진입 전에 겹겹이 쌓여 있었다.

추가로 "폴더와 페이지 사이 간격도 넓고 폴더 안의 페이지 리스트라는 느낌이 안 난다"는 지적이
있었는데, 실측 결과 행 사이 간격(`gap-0.5`, 2px)은 이미 최소 수준이었고 원인은 오히려
들여쓰기(depth당 14px)가 폴더 아이콘 폭에 비해 작아 하위 문서가 폴더 안에 담긴 것처럼 보이지
않는 데 있었다.

선택(활성) 상태의 배경색(핑크, `.sidebar-row-active`)이 위아래로 넓어 보인다는 지적도 있었는데,
이 배경은 행 자체(`Link`)에 적용되므로 행 padding을 줄이면 함께 줄어든다 — 사용자도 이를
확인하고 별도 판단 없이 기존 제안대로 진행하도록 확정했다.

## 수용 기준 (Acceptance Criteria)
- [ ] 폴더 행·문서 행(사이드바 트리, 공유받은 문서 목록 포함)의 상하 padding이 `py-2`(8px)에서
      `py-1.5`(6px)로 줄어, 선택 시 배경색(핑크) 높이도 함께 줄어든다.
- [ ] 들여쓰기 폭이 depth당 14px에서 20px로 늘어, 폴더 안에 문서가 담겨 있다는 시각적 위계가
      더 뚜렷해진다.
- [ ] 검색 입력·새 문서 버튼·`nav`·"폴더" 라벨 등 트리 진입 전 고정 영역의 padding/margin을
      줄여, 실제 목록이 시작되기 전에 쌓이는 여백을 줄인다.
- [ ] "이동" 버튼 등 행 padding에 맞춰 정렬되던 보조 요소도 새 padding에 맞게 함께 조정된다.
- [ ] 기존 회귀 테스트가 모두 통과한다(행 텍스트·클릭 동작 등 기능은 변경하지 않는다).

## 결정이 필요한 사항
없음 — 구체적인 축소 방향(행 padding, 들여쓰기 폭, 상단 여백)은 사용자가 대화 중 확인하고
"진행해줘"로 직접 확정했다.

## 범위 밖
- 폴더 하위 목록에 세로 가이드라인(왼쪽 보더)을 추가하는 안은 이번 범위에서 제외한다 — 부모
  아이콘 위치에 정확히 맞추려면 실제 화면에서 반복 조정이 필요한데, 이 세션은 AX Auth 로그인
  제약으로 `/editor` 화면을 직접 열어볼 수 없어 시각적 미세조정을 검증할 방법이 없다. 대신
  들여쓰기 폭 확대(14→20px)만으로 위계를 우선 개선하고, 가이드라인은 사용자가 이번 변경을
  실제로 확인한 뒤 필요하면 별도 작업으로 진행한다.
- 사이드바 태그 필터 제거(P12-1)·태그 입력 위치 변경(P12-2) — 별도 PR, 이번 작업과 무관.
- "새 문서" 버튼 자체의 크기(1차 액션이라 별도 판단 필요) — 이번 범위는 버튼을 감싸는 wrapper의
  padding만 줄인다.
