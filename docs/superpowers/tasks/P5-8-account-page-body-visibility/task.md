# P5-8: 계정 폴더·계정 관리 페이지 본문에 사람이 읽을 수 있는 스냅샷 표시

## 배경
사용자(관리자)가 실제 Confluence에서 자기 계정 폴더 페이지와 "계정 관리" 페이지를 직접
열어봤는데 본문에 아무 정보도 없어 확인이 안 된다고 지적했다(2026-09-04). 이 프로젝트는
"Confluence는 아무도 직접 열어보지 않는 DB일 뿐"이라는 전제로 실제 데이터를 페이지 본문이
아니라 content property(`accountMeta`/`accountIndex`)에만 저장해왔다 — 관리자가 직접
Confluence에서 눈으로 확인하려는 경우는 애초에 고려하지 않은 설계였다.

사용자가 관리자로서 이 값을 Confluence에서 직접 확인하고 싶다고 명시적으로 요청해, 두 종류의
페이지(계정 폴더, "계정 관리")의 본문에 property 값을 사람이 읽을 수 있는 표로 함께
그려주기로 했다. **property가 여전히 유일한 진짜 데이터이고, 본문은 매번 다시 그리는
참고용 스냅샷이다** — 본문을 직접 수정해도 반영되지 않고, 다음 property 갱신 시점에
다시 덮어써진다.

## 수용 기준 (Acceptance Criteria)
- [ ] 계정 폴더 페이지(`accountMeta`가 바뀔 때마다 — 생성/온보딩/정보 수정/접속 권한 변경)
      본문이 이름·팀·접속 허용 여부·온보딩 완료 시각을 담은 표로 갱신된다.
- [ ] "계정 관리" 페이지(`accountIndex`가 바뀔 때마다) 본문이 전체 계정 목록(이메일·이름·팀·
      접속 허용 여부)을 담은 표로 갱신된다.
- [ ] 이름·팀처럼 사용자가 자유 입력한 값은 HTML로 이스케이프해서 넣는다 — 다른 사람이
      이름/팀에 HTML 특수문자를 넣어도 본문 구조가 깨지거나 임의 마크업이 삽입되지 않는다.
- [ ] 본문 갱신이 실패해도(네트워크 오류 등) accountMeta/accountIndex 저장 자체(진짜 데이터)
      는 그대로 성공한다 — 본문은 어디까지나 부가 기능이다.
- [ ] 실제 Confluence 인스턴스에서 계정 폴더·계정 관리 페이지를 직접 열어(또는 API로 body를
      조회해) 표가 정상적으로 나타나는지 확인한다.

## 결정이 필요한 사항
없음 — "본문에 property 스냅샷을 사람이 읽을 수 있게 보여준다"는 방식 자체가 사용자의
명시적 요청이고, 세부 구현(HTML escape, 실패해도 무시)은 기존 코드베이스 관례를 그대로
따르는 구현 세부사항이다.

## 범위 밖
- 본문을 진짜 데이터 소스로 바꾸는 것(여전히 property가 기준) — 본문은 참고용 스냅샷일 뿐,
  본문을 직접 편집해도 property에 반영되지 않는다.
- 공유 대상 목록(`sharingMeta`/`sharedDocumentRefs`)에도 같은 걸 적용하는 것 — 이번 요청은
  계정 폴더·계정 관리 페이지에 한정됐다.
