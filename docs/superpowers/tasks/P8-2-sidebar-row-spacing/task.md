# P8-2: 사이드바 목록 행 간격/비율 재조정

## 배경
- `docs/product/prd.md` Phase 8(support.claude.com/ko 벤치마킹 후속) 체크리스트 항목. `docs/product/design.md` "벤치마킹 — support.claude.com/ko 문서 뷰어 레이아웃 실측 비교" 절의 "4. 좌측 사이드바" 표가 근거다.
- 실측 결과: 레퍼런스는 목록 항목 패딩이 `padding: 8px`(전방향 균등)이고 항목 radius가 12px인데, 이 프로젝트는 `py-1.5 pl-2 pr-3`(6px/8px/12px, 비대칭)와 `rounded-btn`(`--radius-btn` = `--radius-md` = 8px)을 쓰고 있었다.

## 수용 기준 (Acceptance Criteria)
- [x] 문서 목록 행 패딩을 레퍼런스(8px 전방향)에 맞춰 재산정한다.
- [x] 목록 항목 radius를 레퍼런스(12px)에 맞춰 재검토·조정한다.
- [x] 활성 항목 표시 방식(브랜드색 배경 믹스)은 그대로 유지한다 — 레퍼런스보다 대비가 안전해 변경 불필요(design.md에 이미 명시된 결정).
- [x] 변경 전/후 스크린샷(또는 그에 준하는 시각 비교) 확인.
- [x] 기존 태그 필터(P1-1a)·정렬(P1-1b)·페이지네이션(P1-1c) 렌더링에 회귀 없음 — 자동화 테스트로 고정.

## 결정이 필요한 사항
없음 — 다음 두 가지는 GitHub Issue 없이 기존 코드/디자인 토큰을 근거로 직접 정했다(P1-6a/b, P7-5 등과 같은 "순수 UX/구현 디테일" 판단 근거):
1. **어느 행에 적용하는가**: design.md의 "이 프로젝트 현재 값" 인용(`py-1.5 pl-2 pr-3`)은 문자 그대로는 "공유받은 문서" 행의 클래스와 일치한다. 하지만 폴더 트리(P7-4~10) 도입 이후 일반 문서 행은 `<li>`의 inline style로 왼쪽 들여쓰기를 옮기며 `py-1.5 pr-3`(pl 없음)로 갈라졌다 — 두 변형 모두 이번 조정 대상으로 삼는다(레퍼런스가 말하는 "목록 항목"이 문서 종류를 구분하지 않기 때문). 폴더 토글 행도 세로 패딩(`py-1.5`→`py-2`)만 함께 맞췄다 — 손대지 않으면 같은 트리 안에서 문서 행만 8px, 폴더 행만 6px로 높이가 어긋나는 새로운 불일치가 생기기 때문이다(폴더 행의 오른쪽 패딩·모서리 반경은 이미 아래 2번 판단으로 함께 조정된다).
2. **12px radius를 어떤 클래스로 표현하는가**: 이 프로젝트의 디자인 토큰(`@sfood/ui`)에는 `--radius-btn`(8px)만 있고 12px 전용 버튼 토큰은 없다 — 대신 `--radius-card`(12px, `rounded-card` 유틸리티)가 정확히 그 값이다. `rounded-card`는 이미 이 코드베이스에서 카드가 아닌 요소(드롭다운 메뉴 `TagInput.tsx`, 안내 박스 `PublishForm.tsx`/`WelcomeForm.tsx`)에도 "12px가 필요한 곳"이라는 이유로 재사용되고 있어, 같은 관례를 따라 사이드바 행에도 그대로 적용한다 — 외부 패키지(`@sfood/ui`)의 토큰 이름을 새로 만들거나 임의 픽셀값(`rounded-[12px]`)을 하드코딩하지 않는다.

## 범위 밖
- 폴더/문서 행의 오른쪽 액션 아이콘 버튼(하위 폴더 추가·이름변경·삭제·이동, 전부 `p-1` 크기의 작은 버튼)의 radius는 그대로 둔다 — 그만큼 작은 요소에서는 8px/12px 차이가 거의 눈에 띄지 않고, "목록 항목"(행 자체)과 "행 안의 보조 버튼"은 design.md 표가 말하는 대상이 다르다고 판단했다.
- 좌/우 바깥 여백(`px-6`)·사이드바 폭(220~440px 리사이즈)은 design.md가 이미 "변경 불필요"로 명시했다(P8-1/P8-2 범위 밖).
