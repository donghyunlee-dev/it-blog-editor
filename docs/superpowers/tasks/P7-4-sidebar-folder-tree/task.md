# P7-4: 사이드바 폴더 트리 UI

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-1~3(폴더 데이터 모델·CRUD·문서 배정 API)이 끝나 `folders.ts`의 `listFolders(accountFolderId)`로 폴더 트리를, `DocumentSummary.folderId`로 각 문서의 소속을 조회할 수 있다 — 이 항목은 그 데이터를 사이드바(`EditorSidebar.tsx`)에 실제로 그린다.
- 폴더를 만들고 이름 바꾸고 삭제하는 UI(P7-5), 문서를 폴더로 옮기는 UI(P7-6)는 아직 없다 — 지금은 폴더가 있다면(API를 직접 호출해 만든 경우) 그 구조를 사이드바에 올바르게 "보여주는" 것까지만 다룬다.

## 수용 기준 (Acceptance Criteria)
- [ ] `editor/layout.tsx`가 `listFolders(folder.accountFolderId)`를 함께 조회해 `EditorShell` → `EditorSidebar`로 내려준다.
- [ ] 폴더가 없는 계정(현재 대부분의 사용자 — P7-5가 아직 없어 폴더를 만들 UI 자체가 없음)은 기존과 완전히 동일하게 렌더링된다(회귀 없음) — 폴더 트리 관련 UI 자체가 나타나지 않는다.
- [ ] 폴더가 있으면 계층형 트리로 렌더링된다 — 하위 폴더는 들여쓰기로 표시되고, `parentId` 관계를 그대로 반영한다.
- [ ] 각 폴더는 펼침/접힘 토글이 가능하고, 상태는 `localStorage`에 유지된다(사이드바 폭 조절 기능이 쓰는 `try/catch` + 2-pass 마운트 패턴을 그대로 재사용). 기본값은 펼침(expanded) — 폴더가 있어도 처음엔 기존 "다 보이는" 경험과 최대한 비슷하게 시작한다.
- [ ] 폴더에 속한 문서는 그 폴더를 펼쳤을 때만 보이고, `folderId: null`(미분류) 문서는 폴더 트리와 별도인 "미분류" 섹션에 모인다(폴더가 하나라도 있을 때만 이 레이블이 보인다 — 폴더가 아예 없으면 기존처럼 레이블 없이 문서 목록이 바로 나온다).
- [ ] 기존 태그 필터(P1-1a)·검색·정렬(P1-1b)은 트리 전체에 그대로 적용된다 — 필터링된 결과만 트리 각 위치에 나뉘어 보인다.
- [ ] 기존 페이지네이션(P1-1c, "더 보기")은 **미분류 섹션에만** 적용된다 — 폴더 안 문서는 이번 범위에서 전부 보여준다(폴더 안까지 페이지네이션하는 것은 과설계로 판단, 아래 "범위 밖" 참고).

## 결정이 필요한 사항
없음 —가치 판단이 필요 없는 순수 UX 구현 디테일들(펼침 기본값, 페이지네이션 범위, 미분류 레이블 노출 조건)이라 P1-6a와 같은 근거로 GitHub Issue 없이 직접 정한다. 폴더는 문서당 최대 1개라는 데이터 모델 자체는 이미 Phase 7 핵심 결정으로 확정돼 있다.

## 범위 밖
- 폴더 생성·이름변경·삭제 UI는 P7-5, 문서를 폴더로 옮기는 UI는 P7-6, 편집 화면 브레드크럼은 P7-7이 각각 다룬다 — 이 항목은 "있는 폴더를 보여주기"까지다.
- 빈 폴더 전용 안내 문구(EmptyState)는 P7-8의 몫이다 — 이번엔 문서가 없는 폴더는 펼쳐도 그냥 빈 채로 둔다.
- 검색/필터로 문서가 전부 걸러진 폴더를 트리에서 숨기는 "스마트 필터링"은 하지 않는다 — 폴더는 필터 결과와 무관하게 항상 보인다(구조 탐색 요소로서의 폴더와, 그 안 내용에 대한 필터를 분리해서 생각한다).
- 키보드 방향키 트리 탐색·WAI-ARIA `tree`/`treeitem` 패턴은 P7-10이 명시적으로 맡는다(P2-1a~c 선례와 같은 순서 — 먼저 기능, 나중에 접근성 보강). 이번엔 네이티브 `<button>`이 기본 제공하는 Tab/Enter/Space만으로 충분하다.
