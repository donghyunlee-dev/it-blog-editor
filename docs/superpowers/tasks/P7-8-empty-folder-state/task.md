# P7-8: 빈 폴더 상태 UI

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-4가 사이드바 폴더 트리를 만들 때 "빈 폴더 전용 안내 문구는 P7-8이 맡는다 — 지금은 펼쳐도 그냥 빈 채로 둔다"고 의도적으로 범위 밖에 남겨뒀다. 지금은 하위 폴더도 문서도 없는 폴더를 펼치면 그냥 아무것도 없는 채로 남는다 — 사용자가 "이 폴더가 원래 비어 있는 건지, 뭔가 안 불러와진 건지" 구분할 방법이 없다.
- 원문 수용 기준: "`EmptyState`로 '이 폴더에는 아직 문서가 없습니다' 안내(문서함 미선택 상태의 기존 `EmptyState` 패턴 재사용)."

## 수용 기준 (Acceptance Criteria)
- [x] 하위 폴더도, 문서도 전혀 없는 폴더를 펼치면 그 안에 `EmptyState`(제목 "이 폴더에는 아직 문서가 없습니다.")를 보여준다.
- [x] 직속 문서는 없어도 하위 폴더가 있으면(구조적으로 비어 있지 않음) 이 안내를 보여주지 않는다.
- [x] 검색어·태그 필터로 그 폴더의 문서가 "지금 안 보일 뿐"인 경우에는 이 안내를 보여주지 않는다 — 실제로 문서가 있는 폴더에 "아직 문서가 없다"고 잘못 알리면 안 된다(P1-1a/b 필터와의 상호작용을 P7-4가 이미 그리던 것과 동일한 원칙으로 정확하게 유지).
- [x] 폴더가 접혀 있으면 이 안내도 다른 자식들과 마찬가지로 보이지 않는다.

## 결정이 필요한 사항
없음 — 안내 문구는 원문 수용 기준에 그대로 명시돼 있고, "필터로 가려진 것"과 "진짜로 비어 있는 것"을 구분하는 판단 기준(원본 `documents` 기준으로 그 폴더에 문서가 배정된 적 있는지)은 P7-4가 이미 "미분류" 레이블 노출 조건 등에서 쓴 것과 같은 종류의 순수 UX 정확성 판단이라 GitHub Issue 없이 직접 정한다(P7-5~7 task.md와 같은 근거).

## 범위 밖
- 빈 폴더에 "여기로 문서 이동하기" 같은 바로가기 액션을 추가하는 것(원문 수용 기준에 없음 — 이미 P7-6의 문서 행 "이동" 버튼이 이 역할을 한다).
- 키보드 방향키 트리 탐색·WAI-ARIA `tree`/`treeitem` 패턴은 P7-10의 몫이다.
