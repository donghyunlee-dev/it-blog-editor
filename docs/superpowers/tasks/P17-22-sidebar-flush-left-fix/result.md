# P17-22: 사이드바를 다시 항상 왼쪽에 고정 — 구현 결과 보고서

## 구현 내용
- P17-18이 도입한 "워크스페이스(사이드바+본문+TOC) 전체 최대폭(1800px)+중앙 정렬"
  구조를 제거하고, 사이드바는 다시 항상 화면 왼쪽 끝에 고정되는 원래 구조로
  되돌렸다.
- 넓은 모니터에서 본문 좌우로 커지는 빈 공간 문제(P17-18의 원래 목표)는 범위를
  좁혀 다시 해결했다 — 본문(`{children}`)과 TOC 레일을 하나의 `flex` 컨테이너로
  묶고 그 컨테이너에만 `max-w-[1300px]`를 씌운 뒤, 사이드바 오른쪽 남은 공간
  (`flex-1`) 안에서 그 묶음만 `justify-center`로 가운데 정렬한다.
- 이 구조 변경으로 함께 되돌린 것: 사이드바 폭 조절 드래그(`event.clientX` 그대로
  사용), 접힌 사이드바를 펴는 버튼(`fixed`).

## 자체 검토 (Self-Review)
### 긍정 사항
- 사용자에게 "오른쪽도 대칭인지", "사이드바까지 포함할지"를 명확히 확인한 뒤
  진행해, 이 회귀의 정확한 범위(사이드바까지 포함시킨 것이 문제였지, "넓은
  화면 여백 방지" 자체는 여전히 유효한 목표)를 정확히 파악하고 그만큼만
  고쳤다 — P17-18을 통째로 되돌리지 않고 핵심 가치는 지켰다.
- 임시 디버그 페이지에서 2200px(최대폭 초과)와 1440px(최대폭 이하) 두 경우
  모두 실측해, 넓은 화면에서는 사이드바가 x=8(자체 패딩만)에서 시작하고 본문+TOC
  묶음이 대칭(양쪽 322px)으로 가운데 정렬되며, 일반 화면에서는 TOC가 정확히
  화면 오른쪽 끝(1440px)에 닿아 P17-18 이전과 동일하게 보임을 확인했다.

### 주의사항
- 본문+TOC 묶음의 최대폭(1300px)은 여전히 구현 디테일로 직접 정한 값이다 —
  실사용 중 이 값이 좁거나 넓게 느껴지면 추가 조정이 필요할 수 있다.
- 이 회귀가 애초에 왜 "대칭이 아니라 왼쪽에만" 나타났는지(순수 `mx-auto`라면
  항상 대칭이어야 한다)는 정확한 근본 원인을 재현해 확인하지 못했다 — 구조
  자체를 사용자가 원하는 방향(사이드바 고정)으로 다시 설계해 문제를 우회했다.
  향후 비슷한 "전체를 감싸 가운데 정렬" 시도를 할 때는 이 세션처럼 로그인
  게이트 뒤 실제 화면에서 먼저 검증하는 것이 안전하다.
