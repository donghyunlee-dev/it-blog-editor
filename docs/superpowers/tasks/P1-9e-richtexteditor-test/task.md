# P1-9e: `RichTextEditor.tsx` 테스트를 추가한다

## 배경
- 2026-08-27 [프로덕션 준비도 감사](https://claude.ai/code/artifact/87302c07-68d6-42ed-8712-9345547cb659)에서 나온 항목이다. P0-4b/P1-7a/P1-7c/P1-7d 작업 중 기능별로 테스트가 이미 상당히 누적됐지만(`src/components/editor/RichTextEditor.test.tsx`), 다음 두 영역은 지금까지 한 번도 검증된 적이 없다.
  1. **기본 렌더링/onChange 배선** — 컴포넌트가 `content`를 그대로 그리고 편집 시 `onChange`를 호출하는지, 지금까지 어떤 테스트도 직접 확인한 적이 없다.
  2. **텍스트 서식 버블 메뉴(`EditorBubbleMenu`)** — 굵게/기울임/취소선/글자색/하이라이트/링크 버튼이 전부 한 번도 클릭돼 본 적이 없다. 이 메뉴는 텍스트를 실제로 "선택"해야 뜨는데(ProseMirror의 `TextSelection`이 비어있지 않아야 함), 이 프로젝트의 기존 테스트는 전부 노드 선택(표·이미지)이나 초기 커서 위치에 의존해왔지 실제 텍스트 드래그 선택을 재현한 적이 없다. jsdom/happy-dom에서 `Range` + `document.dispatchEvent(new Event("selectionchange"))`로 네이티브 텍스트 선택을 흉내 내면 ProseMirror가 이를 인식한다는 것을 스파이크 테스트로 직접 확인했다.
  3. **이미지 업로드 성공 경로의 실제 삽입 결과** — 기존 P0-4b 테스트(`uploadImage` 호출 여부만 확인)를 확장해, 실제로 이미지 노드가 문서에 삽입되고 `onChange`로 전달되는지까지 검증한다.

## 수용 기준 (Acceptance Criteria)
- [x] `content` prop으로 넘긴 문서가 그대로 렌더링된다.
- [x] 텍스트를 선택하면 서식 버블 메뉴가 뜨고, 굵게/기울임/취소선 버튼을 클릭하면 각각의 마크가 토글되며 `onChange`가 그 결과 문서로 호출된다(실제 키보드 타이핑을 contentEditable에서 재현하는 것은 jsdom/happy-dom에서 신뢰하기 어려워, `onChange` 배선 확인은 이 서식 토글 상호작용에 얹어서 함께 검증한다 — 별도의 "타이핑 시뮬레이션" 테스트는 두지 않는다).
- [x] 글자색 팔레트에서 색상을 고르면 선택한 텍스트에 색상이 적용되고, "지우기"를 고르면 해제된다.
- [x] 하이라이트 팔레트에서 색상을 고르면 하이라이트가 적용되고, 해제도 가능하다.
- [x] 링크 팝오버에서 안전한 URL(`https://...`)을 적용하면 링크 마크가 붙는다.
- [x] 링크 팝오버에서 안전하지 않은 스킴(`javascript:`)을 적용하면 토스트로 거부되고 링크가 붙지 않는다.
- [x] 드래그앤드롭으로 이미지를 업로드하면(30장 미만) 업로드 완료 후 실제로 이미지 노드가 문서에 삽입되고 `onChange`에 반영된다(기존 P0-4b 테스트는 `uploadImage` 호출 여부만 확인했던 공백을 메운다).
