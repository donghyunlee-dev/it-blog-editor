# P14-1: 사이드바 문서 행 "이동" 버튼을 컨텍스트 메뉴(⋯)로 전환

## 배경
사이드바 문서 행마다 "다른 폴더로 이동" 아이콘 버튼이 상시(호버 시) 노출되는데, 사용자가
Notion·Confluence·Google Drive 등 여러 서비스를 비교한 뒤(2026-09-14) "기능이 추가될 때마다
헤더나 행에 아이콘을 새로 넣는 대신, `⋯`(더보기) 하나로 모아 컨텍스트 메뉴에서 확장하는
방식"으로 바꾸기로 했다. 확인 결과 `@sfood/ui`에 정확히 이 용도의 `DropdownMenu`
(`trigger` + `DropdownItem[]`, `label`/`onClick`/`icon`/`danger`/`divider` 지원) 컴포넌트가
이미 있고, 같은 패키지의 `FileExplorer.itemActions`도 동일한 패턴(항목별 우측 액션 메뉴)을
이미 쓰고 있어 그대로 재사용하기로 했다.

범위는 사용자가 명시적으로 좁혔다 — 에디터 헤더(삭제·이력 버튼)는 이번에 건드리지 않고,
폴더 행(하위 폴더 추가·이름변경·삭제 아이콘 3개)도 "폴더가 아직 많지 않다"는 이유로 이번에
진행하지 않는다. **사이드바 "내 문서" 목록의 문서 행만** 대상이다.

## 수용 기준 (Acceptance Criteria)
- [ ] 문서 행의 기존 "다른 폴더로 이동" 아이콘 버튼이 `⋯`(더보기) 트리거로 바뀐다 — 클릭하면
      `@sfood/ui`의 `DropdownMenu`가 열리고, 항목은 지금은 "다른 폴더로 이동" 1개뿐이다.
- [ ] 트리거는 기존과 같은 방식(평소엔 숨겨져 있다가 행에 마우스를 올리거나 키보드 포커스가
      들어오면 나타남, `group-hover`/`group-focus-within`)으로 노출된다.
- [ ] "다른 폴더로 이동" 클릭 시 동작(기존 `setMoveDocumentTarget(document)` 호출, 이동 대상
      모달 열기)은 그대로 유지된다.
- [ ] 이동 가능한 폴더가 하나도 없을 때(`flatFolderOptions.length === 0`)는 기존과 동일하게
      메뉴 트리거 자체를 렌더링하지 않는다.
- [ ] 에디터 헤더(삭제·이력 버튼), 폴더 행의 액션 아이콘은 이번 범위에서 변경하지 않는다.
- [ ] 기존 회귀 테스트가 모두 통과하고, "이동" 버튼을 찾던 테스트는 새 트리거/메뉴 흐름에
      맞게 갱신된다.

## 결정이 필요한 사항
없음 — 범위(문서 행만, 헤더·폴더 행 제외)와 사용할 컴포넌트(`@sfood/ui`의 `DropdownMenu`)를
사용자가 대화 중 직접 확정했다.

## 범위 밖
- 에디터 헤더의 "삭제"·"이력" 버튼을 컨텍스트 메뉴로 옮기는 작업 — 사용자가 이번엔 하지
  않기로 했다("헤더에 ... 을 추가하는 건 안 해도 돼"). 헤더 버튼을 나중에 제거하게 되면
  남는 버튼들의 정렬(`justify-between`, 구분선 위치 등)을 그때 다시 조정해야 한다는 점을
  사용자가 미리 언급했다 — 이번 작업 범위는 아니지만 다음 단계를 위해 기록해 둔다.
- 폴더 행의 하위 폴더 추가/이름변경/삭제 아이콘을 메뉴로 통합하는 작업 — "폴더는 아직 많지
  않다"는 이유로 보류.
- 컨텍스트 메뉴 항목 추가(현재는 "다른 폴더로 이동" 1개만) — 향후 기능이 늘어날 때 이 메뉴에
  항목을 추가하는 것이 이번 작업의 목적이지만, 지금 당장 새 항목을 만들지는 않는다.
