# P7-6: 문서를 폴더로 이동하는 UI

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-3(도메인 함수 `setDocumentFolder`/API `PUT /api/editor/documents/{pageId}/folder`)과 P7-4(사이드바 폴더 트리 조회)·P7-5(폴더 생성/이름변경/삭제)가 끝나, 문서를 폴더에 배정하는 백엔드와 폴더 자체를 관리하는 UI는 이미 있다 — 하지만 **기존 문서를 다른 폴더로 옮기는 UI 자체가 아직 없다**(새로 만들 때 폴더를 고르는 기능도 이 PRD 범위에는 없다).
- 원문 수용 기준: `"이동" 메뉴/모달(대상 폴더 선택)로 먼저 구현한다. 드래그앤드롭은 범위 밖(위 핵심 결정 참고, 후속 Phase 후보).`

## 수용 기준 (Acceptance Criteria)
- [x] 사이드바의 각 문서 행에 "이동" 액션이 있다(P7-5의 폴더 행 액션 버튼과 같은 원칙 — 평소엔 숨겨져 있다가 행에 마우스를 올리거나 키보드 포커스가 들어오면 나타난다).
- [x] "이동"을 누르면 대상 폴더를 고르는 `Modal`(+`FormField`+`Select`)이 뜬다. 옵션에는 "미분류"(현재 상태로 되돌리기)와, 계정의 모든 폴더가 트리 깊이만큼 들여쓴 이름으로 나열된다.
- [x] 저장하면 `PUT /api/editor/documents/{pageId}/folder`(P7-3에서 이미 만든 API)를 `{ folderId: string | null }` 바디로 호출한다. 성공/실패는 `Toast`로 안내한다(CLAUDE.md 규칙).
- [x] 저장 성공 시 `router.refresh()`로 서버 컴포넌트가 최신 `documents`를 다시 내려주게 한다(P7-5의 `onSaved` 선례와 동일 패턴).
- [x] 계정에 폴더가 하나도 없으면 "이동" 버튼 자체를 숨긴다(미분류 문서를 미분류로만 옮길 수 있는 건 의미가 없다 — P7-4가 "폴더 없는 계정은 기존과 동일" 원칙을 지킨 것과 같은 이유).

## 결정이 필요한 사항
없음 — "이동" 버튼 위치(문서 행, hover-reveal), 대상 폴더 목록 표시 방식(들여쓴 flat `<select>`)은 P7-5가 이미 확립한 패턴을 그대로 잇는 순수 UX 구현 디테일이라 GitHub Issue 없이 직접 정한다(P7-5 task.md와 같은 근거).

## 범위 밖
- 드래그앤드롭으로 옮기는 기능(PRD 핵심 결정에 따라 후속 Phase 후보).
- 여러 문서를 한 번에 선택해 이동하는 다중 선택/일괄 이동(원문 수용 기준에 없음).
- 편집 화면 자체에서 이동하는 진입점(브레드크럼 등)은 P7-7의 몫이다 — 이번엔 사이드바 문서 목록에서만 다룬다.
- 빈 폴더 전용 안내 문구(EmptyState)는 P7-8의 몫이다.
