# P0-1b: 자동 저장 도입

## 배경
[Issue #1](https://github.com/sfood-pioneer-1st/sfood-it-editor/issues/1)에서 결정됨(2026-08-27). 기존 `docs/superpowers/plans/2026-08-21-editor-ui-ux-implementation.md`의 "저장은 수동 유지, 자동저장을 추가하지 않는다"는 결정을 뒤집는다.

**확정된 조건(이슈 답변 원문)**:
1. 변경된 내용이 있을 경우만 저장한다.
2. 1분마다 체크해서 저장한다.
3. localStorage에 임시 저장 후 자동 confluence 저장 실패에 대비한다.

## 수용 기준 (Acceptance Criteria)
- [ ] `mode="edit"`(기존에 저장된 문서, pageId 있음)에서, 1분마다 저장되지 않은 변경사항(`isDirty`)이 있는지 확인해 있을 때만 Confluence에 저장을 시도한다. 변경사항이 없으면 아무 요청도 보내지 않는다.
- [ ] 자동 저장을 시도하기 직전에 현재 제목·본문·태그를 `localStorage`에 먼저 기록한다(문서별로 구분되는 키). Confluence 저장이 성공하면 이 임시 저장본을 지운다 — 성공했는데 계속 남아있으면 다음에 열었을 때 이미 반영된 내용을 "복구할까요?"라고 잘못 묻게 된다.
- [ ] Confluence 저장이 실패하면(네트워크 오류·버전 충돌 등) 임시 저장본을 지우지 않고 그대로 둔다 — 다음 1분 주기에 다시 시도한다. 실패했다는 것을 사용자에게 경고 토스트로 알린다("자동 저장에 실패했습니다. 로컬에는 임시 저장되었습니다." 같은 취지).
- [ ] 문서를 열었을 때(mode="edit") `localStorage`에 그 문서의 임시 저장본이 있고, 그 저장 시각이 서버에서 방금 불러온 문서의 최종 수정 시각보다 **이후**라면(= 서버가 아직 이 편집 내용을 반영하지 못했다는 뜻) 복구 여부를 묻는 `Modal`을 띄운다. 저장 시각이 서버 최종 수정 시각보다 이전이거나 같으면(이미 반영된 오래된 임시본) 조용히 지우고 아무것도 묻지 않는다.
- [ ] 복구를 선택하면 임시 저장본의 제목·본문·태그로 화면 상태를 바꾸고, "저장하지 않은 변경사항 있음"으로 표시한다(이후 수동 저장하거나 다음 자동 저장 주기를 기다리면 된다).
- [ ] 자동 저장은 조용히 진행된다 — 매 분마다 "저장되었습니다" 토스트를 띄우지 않는다(수동 저장 버튼의 토스트와는 구분). 대신 최소한의 상태 표시(예: "자동 저장됨")만 남긴다.
- [ ] 저장 성공 시 버전(`version`) 상태를 갱신해, 다음 저장(수동이든 자동이든)이 최신 버전 기준으로 이루어지게 한다(기존 수동 저장과 동일).
- [ ] `mode="create"`(아직 저장되지 않은 새 문서)에는 이번 자동 저장을 적용하지 않는다 — 아래 "범위 밖" 참고.
- [ ] 자동 저장은 태그는 저장하지 않는다(본문·제목만) — 아래 "범위 밖" 참고.

## 범위 밖
- **새 문서(mode="create")의 자동 저장**: 아직 Confluence에 존재하지 않는 문서라 저장할 대상 pageId가 없다. 첫 자동 저장 시점에 문서를 조용히 새로 만드는 방식도 고려했으나, 사용자가 "저장" 버튼을 누르지 않았는데 문서함에 새 문서가 나타나는 것은 예상치 못한 부작용이 크다고 판단해 이번 범위에서 제외했다. 새 문서는 P0-1a의 이탈 경고(beforeunload·앱 내부 이동 가드)로 여전히 보호된다.
- **자동 저장의 태그 반영**: 확정된 조건에 태그가 명시되지 않았고, 매 분마다 태그까지 저장하면 실패 케이스(태그 저장은 별도 엔드포인트)가 늘어나 자동 저장의 단순함을 해친다고 판단했다. 태그는 지금처럼 "저장" 버튼을 눌러야 반영된다. 단, `localStorage` 임시 저장본에는 태그도 함께 담아 복구 시에는 태그도 되돌아온다.
