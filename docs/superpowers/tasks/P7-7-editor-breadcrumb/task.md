# P7-7: 문서 편집 화면 브레드크럼

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-6까지 끝나 문서를 폴더에 배정·이동하는 기능은 다 갖췄지만, 정작 **편집 화면 자체에는 "지금 이 문서가 어느 폴더에 있는지" 알려주는 곳이 없다** — 사이드바 폴더 트리를 직접 펼쳐봐야만 알 수 있다.
- 원문 수용 기준: "현재 소속 폴더 경로를 헤더에 표시하고 클릭 시 상위 폴더로 이동한다. 사용자가 '지금 이 문서가 어디 있는지' 항상 알 수 있게 해, 리포트가 지적한 '탐색 불가능성'을 직접 보완한다."

## 수용 기준 (Acceptance Criteria)
- [x] 문서가 폴더에 속해 있으면(`document.folderId`) 편집 화면 헤더에 루트부터 그 폴더까지의 경로("업무 / 하위"처럼)를 보여준다.
- [x] 폴더가 없는 문서(대부분)는 이 영역 자체가 보이지 않는다 — 추가 조회도 하지 않는다(폴더 미사용 계정은 기존과 완전히 동일해야 한다는 P7-4/P7-5/P7-6의 반복된 원칙).
- [x] 각 폴더 이름을 누르면 그 폴더로 "이동"한다. 이 프로젝트에는 폴더 전용 상세 화면이 없으므로(P7-4가 사이드바 트리 하나로 탐색을 통일한 기존 설계), "이동"은 `/editor`로 돌아가면서 사이드바가 그 폴더까지 펼치고 스크롤·잠깐 강조하는 것으로 구현한다.
- [x] 공유받은 문서를 볼 때도 브레드크럼이 보인다 — 폴더는 소유자 개인의 조직 체계라(P7-3), 항상 **문서 소유자**의 폴더 트리 기준 경로를 보여준다(내 폴더 트리가 아니다).

## 결정이 필요한 사항
없음 — "폴더 전용 화면이 없으니 클릭 시 사이드바로 돌아가 그 폴더를 펼치고 스크롤한다"는 해석은 P7-4가 이미 확립한 "탐색은 사이드바 트리 하나로 통일한다"는 설계를 따른 것뿐이라 GitHub Issue 없이 직접 정한다(P7-5/P7-6 task.md와 같은 근거). 구분자("/")·강조 지속 시간(1.6초) 등 세부 UX 값도 같은 이유로 직접 정한다.

## 범위 밖
- 브레드크럼에서 곧바로 폴더를 바꾸는 드롭다운(이미 P7-6의 "이동" 모달이 이 역할을 한다).
- 문서 생성(`mode="create"`) 화면의 브레드크럼 — 아직 생성 시점에 폴더를 고르는 UI 자체가 없다(P7-6 task.md "범위 밖" 참고, 생성 후 P7-6의 "이동"으로만 배정 가능).
- 빈 폴더 전용 안내 문구(EmptyState)는 P7-8의 몫이다.
