# P17-21: 문서함 리스트 행 밀도 조정 — task

## 배경
- 사용자가 병합 전 P17-14/P17-20을 실사용하며 함께 리포트한 것 중 하나 — "왼쪽
  문서함 비율이 이상하다"는 초기 리포트를 구체화한 결과: "문서가 많아질 경우
  리스트가 길게 생기고 화면에 많은 문서가 보이지 않게 됨. 화면에 보이는 리스트를
  어느 정도 설정해서 보이는지에 따라 리스트 CSS 조정이 필요함."
- 이어진 확인 질문("행 높이를 줄여 더 보이게 vs 사이드바 자체를 더 높게 vs 스크롤
  자체가 문제")에 사용자가 "행 높이를 줄여 더 많이 보이게"를 선택했다.
- 참고: 문서 목록 행의 상하 패딩은 이미 한 번 조정된 이력이 있다 — P8-2에서
  8px(`py-2`)였다가, P13-1(2026-09-14)에서 "문서가 적어도 목록이 화면을 많이
  차지한다"는 지적으로 6px(`py-1.5`)로 줄였다. 이번은 그 다음 단계로 4px(`py-1`)
  까지 한 번 더 줄인다.

## 수용 기준 (Acceptance Criteria)
- [x] 문서 목록 행(`renderDocumentRow`)의 상하 패딩이 `py-1.5`(6px)에서 `py-1`
      (4px)로 줄어든다.
- [x] 폴더 행(`renderFolderNode`의 토글 버튼)도 문서 행과 같은 높이를 유지하도록
      함께 `py-1`로 줄어든다.
- [x] "공유받은 문서" 행도 같은 이유로 함께 `py-1`로 줄어든다.
- [x] 문서 행의 "⋯"(옵션) 버튼의 상단 정렬 여백(`mt-1.5`)도 `mt-1`로 함께 줄어
      Link의 상단 패딩과 계속 나란히 보인다.
- [x] `docs/product/design.md`의 관련 스펙(사이드바 섹션, "4. 좌측 사이드바" 비교
      표)을 새 값으로 갱신한다.

## 결정이 필요한 사항
없음 — 사용자가 명확히 "행 높이를 줄여 더 많이 보이게"를 선택했고, 구체적인 값
(py-1, 4px)은 Tailwind의 다음 단계 스케일을 그대로 쓰는 구현 디테일 판단이다.

## 범위 밖
- 사이드바 자체의 높이/폭 조정 — 사용자가 "행 높이" 쪽을 선택했으므로 다루지 않는다.
- 문서 옵션(⋯) 팝업 메뉴, 검색 입력 등 목록 행이 아닌 다른 UI 요소의 패딩 — 사용자가
  구체적으로 지적한 "리스트"(문서·폴더 행)에만 적용한다.
