## 재검토 결론
현재 동작(표 전체 삭제만 `Modal` 확인, 행/열 삭제는 클릭 즉시 실행)을 **그대로
유지**하기로 결정했다(사용자 확인, 2026-09-16). 근거:

- 행/열 삭제는 표를 다루는 동안 매우 자주 일어나는 조작이다 — 매번 확인 창을 띄우면
  일반적인 편집 흐름을 크게 방해한다. Notion, Google Docs, Excel 등 대부분의 표
  편집 도구가 행/열 삭제는 확인 없이 즉시 실행하고, 표/시트 전체 삭제처럼 훨씬 더
  큰 단위의 파괴적 동작에만 확인을 요구하는 것과 같은 관례다.
- 에디터에 이미 표준 실행 취소(Ctrl+Z, ProseMirror 히스토리)가 있어, 실수로 지운
  행/열은 즉시 되돌릴 수 있다 — 표 전체 삭제(모든 셀 내용이 한 번에 사라짐)보다
  체감 리스크가 훨씬 작다.
- PRD에 적힌 "비일관성"은 실제로는 버그가 아니라 **파괴성 정도에 따른 의도된
  차등 처리**였다 — "조사 중 추가로 발견"됐을 뿐 실제 사용자 불만으로 제기된 적은
  없었다(원래 목록에 없던 항목이 조사 중 추가된 P17-7/P17-8 중 하나).

## 검토한 대안과 기각 이유
- **행/열 삭제에도 Modal 확인 추가**: 일관성은 얻지만, 행/열 삭제 빈도를 고려하면
  사용성 저하가 더 크다고 판단해 기각.
- **삭제 직후 "실행 취소" 토스트 추가**: 확인창을 막지 않으면서도 되돌릴 방법을
  명시적으로 보여주는 절충안이었지만, 사용자가 "즉시 실행 유지"(현재 상태 그대로)를
  선택해 별도 구현 없이 종결.
