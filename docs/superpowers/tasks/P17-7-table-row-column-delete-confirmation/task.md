# P17-7: 표 행/열 삭제 확인 절차 일관성 — 재검토

## 배경
- PRD(`docs/product/prd.md`) Phase 17, P17-7 항목: "표 행/열 삭제 확인 절차 일관성 —
  표 전체 삭제만 `Modal` 확인을 거치고 행/열 삭제는 즉시 실행되는 파괴성 기준
  비일관성을 재검토한다." — Phase 17 조사 중 추가로 발견한 항목이라, 애초에 "고친다"
  가 아니라 "재검토한다"로 적혀 있었다(원하는 결과가 정해져 있지 않음).
- 코드 확인(`RichTextEditor.tsx`의 `TableToolbar`): "행 삭제"/"열 삭제" 버튼은
  `onClick={() => editor.chain().focus().deleteRow().run()}` 형태로 클릭 즉시
  실행되지만, "표 삭제" 버튼은 `setConfirmDeleteOpen(true)`로 `Modal`을 먼저 띄우고
  "삭제 확인"을 눌러야 실제 `deleteTable()`이 실행된다(1075~1077번 줄 주석: "표
  삭제는 셀/행/열 조작과 되돌릴 수 있는 정도가 다른 파괴적 동작이라... CLAUDE.md
  규칙에 따라... Modal로 확인을 받은 뒤에만 실행한다").

## 결정이 필요한 사항
"행/열 삭제도 표 전체 삭제처럼 Modal 확인을 거쳐야 하는가"는 추측으로 진행하지 않고
사용자에게 직접 물었다(이 세션에서 바로 결정 가능한 사안이라 GitHub Issue 등록
대신 대화로 확인 — CLAUDE.md의 "값·방식이 안 정해진 결정은 추측하지 않는다"는
원칙은 지키되, 실시간 세션이라 더 빠른 경로를 썼다).

- [x] 행/열 삭제도 Modal 확인을 거치게 할까, 지금처럼 즉시 실행을 유지할까? —
      **결정: 즉시 실행 유지**(사용자 선택, 2026-09-16). 표 전체 삭제(내용 전부
      소실)만 Modal로 확인하고, 행/열 삭제는 지금처럼 클릭 즉시 실행한다.
