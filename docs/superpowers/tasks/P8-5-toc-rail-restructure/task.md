# P8-5-toc-rail-restructure: 우측 목차(TOC) 구조를 독립 레일로 변경 + 활성 항목 버그 수정

## 배경
- `docs/product/prd.md`의 **P8-5**(우측 목차 TOC) 항목은 이미 완료 표시돼 있었지만,
  같은 날 두 번의 후속 버그 수정(`P8-5-toc-initial-render-fix`, `P8-5-toc-freeze-hotfix`)이
  더 있었을 만큼 이 기능은 반복적으로 문제가 났다.
- 이번 세션에서 사용자가 실제 화면에서 재보고한 문제: "TOC가 스크롤을 내리면 상단에
  고정된 채 따라오지 않아 화면에서 사라진다." 원인 조사 결과, TOC가 본문과 같은
  `flex justify-center gap-12` 그룹의 아이템이라 `align-items` 기본값(stretch)이 TOC를
  본문과 같은 높이(문서 전체 길이)로 늘려버려 `sticky top-14`가 계산상 무효화되는
  문제였다(1차 수정: `self-start` 추가, PR #112, 이미 main에 머지됨).
- 이 수정을 확인하던 중 사용자가 자신이 벤치마킹한 참고 사이트의 실제 구조를 다시
  설명했다 — 그 사이트의 TOC는 본문과 같은 스크롤 그룹의 아이템이 아니라, **좌측
  사이드바와 동급으로 스크롤 영역 밖에 있는 완전히 독립된 컬럼**(자기 안에서만
  스크롤)이었다. `sticky`로 흉내 내는 지금 구조 자체가 이 버그들이 반복된 근본
  원인이라고 판단해, 구조를 사용자의 관찰대로 바꾸기로 합의했다.
- 같은 대화에서 추가로 제보된 두 버그(모두 "지금 섹션" 활성 표시 로직의 결함):
  1. 문서를 막 열었을 때 TOC에 활성 항목이 표시되지 않는다.
  2. 본문을 끝까지 스크롤해도 마지막 항목까지 활성 표시가 이동하지 않고, 그 때문에
     마지막 항목을 클릭해도 활성 표시가 바뀌지 않는다.
- 관련 문서: `docs/product/design.md` "7. 우측 목차(TOC)" 절(스펙), `docs/product/prd.md`
  445번째 줄(P8-5 항목, 기존 버그 수정 이력 포함).

## 수용 기준 (Acceptance Criteria)
- [x] TOC가 본문 스크롤 영역(`flex-1 overflow-y-auto`) **밖**의 독립된 형제 컬럼으로
      렌더링된다 — 본문을 아무리 스크롤해도 TOC 컬럼 자체의 화면상 위치가 변하지 않는다.
- [x] TOC가 없는 라우트(문서 목록 등)나 헤딩이 없는 문서에서는 이 레일이 렌더링되지
      않아(폭을 차지하지 않아) 기존 레이아웃에 영향을 주지 않는다.
- [x] 문서를 열자마자(스크롤하기 전)도 첫 헤딩이 기본으로 활성 표시된다.
- [x] 본문 스크롤이 바닥에 닿으면(더 내려갈 곳이 없으면) 위치 계산과 무관하게 마지막
      헤딩이 활성 표시된다.
- [x] 마지막 목차 항목을 클릭해 스크롤이 최대치까지 이동하면, 그 항목이 활성 표시된다.
- [x] 기존 동작(문서 순서 목록, h2/h3 들여쓰기, 클릭 시 scrollIntoView, ProseMirror DOM
      비변형, `doc` prop 변경/비동기 마운트 시 재스캔)은 회귀 없이 그대로 유지된다.

## 결정이 필요한 사항
없음 — 구조 변경 방향은 사용자가 대화 중 직접 확정했고(벤치마킹 사이트 재확인 후
"수정하자"고 승인), 나머지는 기존 코드 동작을 그대로 보존하는 리팩터라 새로운 값
결정이 필요하지 않았다.

## 범위 밖
- TOC 활성 표시 색상·타이포 등 시각 스펙 변경(design.md 기존 값 그대로 유지).
- `EditorShell`을 사용하는 다른 라우트(문서 목록 등)의 레이아웃 자체 변경.
