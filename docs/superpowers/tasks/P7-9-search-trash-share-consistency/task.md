# P7-9: 검색·삭제된 문서·공유 문서와의 통합 정합성

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-1~8로 폴더 자체의 CRUD·이동·브레드크럼·빈 폴더 안내까지 끝났지만, 폴더 기능이 이 프로젝트의 다른 기존 기능(Ctrl+K 전역 검색, 삭제된 문서 복구, 공유받은 문서)과 만나는 지점은 아직 하나도 검증되지 않았다.
- 원문 수용 기준: "Ctrl+K 전역 검색 결과에 소속 폴더 경로를 함께 표시하고, 삭제된 문서 복구(P1-2b) 시 폴더 소속을 어떻게 되돌릴지 명시해 회귀 테스트로 고정하며, 공유받은 문서(P6-5)는 폴더 트리와 무관하게 기존처럼 사이드바 별도 영역으로 유지됨(공유받은 사람은 상대방의 폴더 구조를 보지 않음)을 회귀 테스트로 고정한다."

## 수용 기준 (Acceptance Criteria)
- [x] Ctrl+K 전역 검색(`GlobalSearchModal.tsx`) 결과 목록과 미리보기 패널 양쪽에, 문서가 폴더에 속해 있으면 그 경로("업무/하위")를 함께 보여준다. 폴더가 없는 문서(대부분)는 기존과 동일하다.
- [x] 삭제된 문서 복구(`restoreDocument`) 시 폴더 소속 정책을 명시하고 코드로 고정한다: **폴더가 그대로 있으면 원래 폴더로 돌아가고, 휴지통에 있는 동안 그 폴더가 삭제됐으면 미분류로 되돌린다.** (실제로 발견한 갭 — `reassignDocumentsFolder`는 활성 문서만 훑어 휴지통에 있던 문서는 폴더 삭제 시 재배정에서 빠지고, 그대로 두면 `folderId`가 존재하지 않는 폴더를 가리켜 사이드바 어디에도 안 보이는 문서가 될 수 있었다.)
- [x] 공유받은 문서(`SharedDocumentSummary`)는 `folderId`가 있어도 사이드바 폴더 트리에 편입되지 않고 항상 "공유받은 문서" 별도 영역에만 있음을 회귀 테스트로 고정한다(공유받은 사람은 상대방의 폴더 구조를 보지 않는다는 P7-3의 설계를 그대로 반영).

## 결정이 필요한 사항
없음 — 복구 시 폴더 소속 정책("폴더가 있으면 그대로, 없어졌으면 미분류")은 P7-3이 폴더 삭제 시 이미 확립한 "잃지 않고 상위로 승격, 궁극적으로는 미분류"라는 안전한 기본값과 같은 방향이라 GitHub Issue 없이 직접 정한다(P7-5~8 task.md와 같은 근거). 검색 결과의 폴더 경로 표시 위치·구분자는 P7-7 편집 화면 브레드크럼과 같은 관례("/")를 그대로 따른다.

## 범위 밖
- 검색 결과에서 곧바로 문서를 다른 폴더로 옮기는 기능(이미 P7-6의 사이드바 "이동"이 이 역할을 한다).
- 삭제된 문서 목록(`DeletedDocumentsModal.tsx`)에 폴더 경로를 표시하는 것(원문 수용 기준에 없음 — 그 목록은 제목·삭제 시각만 보여주는 게 기존 설계다).
- 키보드 방향키 트리 탐색·WAI-ARIA 패턴은 P7-10의 몫이다.
