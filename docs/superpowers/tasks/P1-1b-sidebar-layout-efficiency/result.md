## 변경 파일
- `src/components/editor/EditorSidebar.tsx`:
  - 문서 검색 입력(`#sidebar-doc-search`)만 담은 블록을 헤더 행(h-14) 바로 아래로
    옮겼다. "본문까지 찾으려면 Ctrl+K" 안내 문장과 정렬 `<Select>`는 이 블록에서 제거했다.
  - "새 문서" `<Link>` 블록을 원래 자리(헤더 바로 아래)에서 제거하고, 태그 필터 섹션과
    `<nav>`(폴더 트리) 사이로 옮겼다 — `border-b`로 "컨트롤 영역 ↔ 문서 목록" 경계를
    표시하는 역할도 검색 블록에서 이 블록으로 함께 넘어왔다.
  - 새 `SortIcon()` 컴포넌트(다른 아이콘들과 같은 20×20 viewBox, stroke 스타일)를 추가하고,
    "폴더" 행에 "새 폴더 만들기" 버튼과 같은 스타일의 아이콘 토글 버튼을 넣었다 — 클릭할
    때마다 `sortBy`를 `updatedAt`↔`title`로 토글한다(옵션이 2개뿐이라 드롭다운 대신 토글로
    충분). `documents.length > 0`일 때만 보인다(기존 정렬 컨트롤과 같은 조건).
  - 이제 안 쓰는 `Select` import를 `@sfood/ui`에서 제거했다.
  - 헤더의 "전체 검색(Ctrl+K)" 버튼(P8-1)에서 "검색" 글자 라벨과 배경 필(`bg-surface-subtle`)
    을 빼고, "새 폴더 만들기"·접기 버튼과 같은 아이콘 전용 스타일(`rounded-btn p-1.5`)로
    맞췄다 — `aria-label`/`title`은 그대로 "전체 검색 (Ctrl+K)"라 접근성 회귀는 없다.
- `src/components/editor/EditorSidebar.test.tsx`:
  - 기존 "제목순으로 바꾸면..."/"문서가 없으면 정렬 드롭다운을 보여주지 않는다" 테스트를
    아이콘 버튼 클릭 기준으로 갱신하고, "다시 누르면 최신순으로 되돌아간다" 테스트를
    새로 추가했다.
  - 신규 회귀 테스트 3개: 검색 입력이 "새 문서" 링크보다 DOM에서 앞에 있음
    (`compareDocumentPosition`), "새 문서" 링크가 "폴더" 라벨보다 앞에 있음, "본문까지
    찾으려면" 문장이 더는 없음.

## 자체 검토
- **긍정**: 검색·정렬·태그 필터의 상태(`query`/`sortBy`/`activeTag`)와 그 소비 로직
  (`filteredDocuments` 계산 등)은 전혀 건드리지 않았다 — 컨트롤의 위치와 형태만 바꿔
  회귀 위험이 낮다. `compareDocumentPosition` 기반 순서 테스트는 앞으로 누군가 실수로
  순서를 되돌려도 바로 잡아낸다.
- **주의사항**: 정렬을 드롭다운에서 토글 버튼으로 바꾸면서, 옵션이 2개보다 늘어나면(예:
  "생성일순" 추가) 이 토글 방식은 더 이상 맞지 않는다 — 그때는 드롭다운이나 메뉴로
  되돌려야 한다(현재는 "최신순"/"제목순" 2개뿐이라는 전제에서만 유효한 설계).
- **우려사항**: AX Auth 로그인 제약으로 이 세션에서는 실제 브라우저로 새 레이아웃을
  스크린샷으로 확인하지 못했다(기존 항목들과 동일한 한계). 컴포넌트 테스트(DOM 순서·클릭
  동작)로만 검증했다. 또한 `npm run build`의 TypeScript 검사 단계가 이 세션과 무관한
  원인(다른 세션이 같은 `.next` 디렉터리에서 동시에 돌리고 있는 dev 서버가 재생성 중이던
  `.next/dev/types/validator.ts`가 쓰기 도중 잘려 문법 오류가 난 것 — gitignore 대상이라
  이 브랜치의 diff에는 전혀 나타나지 않는다)로 실행하지 못했다 — `test.md`에 근거를 남겼다.
