# P1-1b 후속: 사이드바 컨트롤 영역 레이아웃 재배치 (공간 효율화)

## 배경
사용자가 랜딩 화면 검색 중복(P8-4 되돌리기)을 짚은 김에, 사이드바가 항상 열려 있을 때
보이는 나머지 검색/정렬 UI("헤더 검색 버튼" + "사이드바 인라인 문서 검색")를 유지하되,
그 주변 레이아웃을 공간 효율적으로 재정리해 달라고 요청했다(2026-09-11). 구체적으로:
1. 문서 검색(제목·태그 필터) 입력을 사이드바 맨 위로 이동.
2. "새 문서" 버튼을 폴더 생성 섹션 바로 위로 이동.
3. "본문까지 찾으려면 Ctrl+K(Mac: ⌘K)" 안내 문장 삭제.
4. 정렬(최신순/제목순) 드롭다운을 "새 폴더 만들기"와 같은 아이콘 버튼으로 대체.

## 수용 기준 (Acceptance Criteria)
- [x] 사이드바 헤더 행(h-14) 바로 아래에 문서 검색 입력이 온다(그 전에는 "새 문서" 버튼이
      이 자리에 있었다).
- [x] "새 문서" 버튼은 "폴더" 섹션(폴더 트리 + "새 폴더 만들기" 버튼) 바로 위로 옮겨진다.
- [x] "본문까지 찾으려면 Ctrl+K(Mac: ⌘K)" 문장이 화면 어디에도 없다.
- [x] 정렬 `<Select>` 드롭다운이 사라지고, "폴더" 행에 "새 폴더 만들기"와 같은 스타일의
      아이콘 버튼이 추가돼 클릭할 때마다 최신순 ↔ 제목순을 토글한다(옵션이 2개뿐이라
      드롭다운 대신 토글로 충분).
- [x] 기존 검색·정렬·태그 필터·페이지네이션(P1-1a/b/c)의 실제 동작(필터링·정렬 로직 자체)은
      전혀 바뀌지 않는다 — 이번 작업은 배치와 컨트롤의 시각적 형태만 바꾼다.
- [x] 회귀 테스트로 새 레이아웃 순서(검색 → ... → 새 문서 → 폴더 섹션)와 정렬 토글 동작을
      고정한다.

## 결정이 필요한 사항
없음 — 배치 순서·아이콘 대체 여부는 사용자가 직접 지정했다(이 대화의 메시지 참고). 정렬
옵션이 "최신순"/"제목순" 단 2개뿐이라 토글 버튼(드롭다운 메뉴 없이 클릭마다 전환)으로
충분하다는 것은 구현 디테일 판단이라 GitHub Issue 없이 직접 정했다(P1-6a 등과 같은 근거).

## 범위 밖
- 검색·정렬·태그 필터·페이지네이션의 로직 자체 변경(P1-1a/b/c) — 이번 작업은 배치/형태만.
- 공유받은 문서 섹션·태그 필터 칩의 위치 변경 — 사용자가 지정하지 않아 기존 상대 순서를
  그대로 유지했다(검색 다음, 새 문서 앞).
- 헤더 검색 버튼(P8-1) 자체의 변경.
