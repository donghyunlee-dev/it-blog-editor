# P17-9: 이미지 업로드 진행 상태 표시

## 배경
사용자 지적: "이미지를 캡쳐 후 넣거나, 슬러시 이미지로 넣을 때 아무 효과 없이 기다렸다가
들어가기 때문에 작업이 진행 중인지 알 수가 없어. 이미지 들어갈 위치에 로딩이나 텍스트나
프로그레스 등의 효과를 넣어서 알려줬으면 좋겠어. 가장 보편적으로 많이 사용하는 방식으로
작업해줘."

조사 결과: 드래그앤드롭·붙여넣기·슬래시 메뉴 "이미지" 세 경로 모두 `uploadImage(pageId,
file)` 호출이 끝난 뒤(`.then()`)에야 image 노드를 문서에 삽입한다 — 업로드 중에는 그
자리에 아무 표시도 없어, 느린 네트워크에서는 "이미지 기능이 안 되는 것"처럼 보인다(P17-1이
다룬 "슬래시 메뉴 항목 자체가 안 보임"과는 다른 문제 — 이번엔 항목은 정상 동작하지만
업로드 완료까지의 대기 시간에 피드백이 없는 것).

## 수용 기준 (Acceptance Criteria)
- [x] 드래그앤드롭으로 이미지를 넣으면, 업로드가 끝나기 전에 그 위치에 로딩 표시(스피너 +
      안내 문구)가 즉시 보인다.
- [x] 붙여넣기(클립보드)로 이미지를 넣을 때도 동일하게 즉시 로딩 표시가 보인다.
- [x] 슬래시 메뉴 "이미지"로 파일을 선택했을 때도 동일하게 즉시 로딩 표시가 보인다.
- [x] 업로드가 성공하면 로딩 표시가 실제 이미지로 자연스럽게 바뀐다.
- [x] 업로드가 실패하면 로딩 표시가 사라지고(자리표시자를 남기지 않음) 기존과 동일한 에러
      토스트가 뜬다.
- [x] 로딩 표시는 `@sfood/ui`가 제공하는 컴포넌트(`Spinner`)를 쓴다 — 커스텀 CSS 애니메이션을
      새로 만들지 않는다(디자인 시스템 우선순위 규칙).
- [x] 업로드 중 상태(placeholder)는 저장 데이터(Confluence storage format)에는 절대 남지
      않는다 — 업로드가 끝나기 전에 문서를 저장하는 극단적인 경우를 포함해, 최종 저장 결과에
      "업로드 중" 상태가 노출되지 않는다.

## 결정이 필요한 사항
없음 — 사용자가 "가장 보편적으로 많이 사용하는 방식"을 명시적으로 요청했고, 이는 업계
전반의 표준 패턴(업로드 시작과 동시에 자리표시자를 두고, 완료되면 결과로 치환)이라 별도로
정할 값이 없다.

## 범위 밖
- 실제 업로드 진행률(퍼센트) 표시 — 이 프로젝트의 `uploadImage()`는 XHR/fetch 진행률
  이벤트를 노출하지 않는 단순 Promise라, 몇 %까지 왔는지는 알 수 없다. 대신 "진행 중임을
  안다"는 핵심 요구는 스피너+문구로 충분히 만족한다(퍼센트 프로그레스바를 만들려면
  `image-upload.ts`의 업로드 구현 자체를 XHR 기반으로 바꿔야 해 범위가 커진다).
- 업로드 중 로컬 이미지 미리보기(blob URL) — 스피너 자리표시자만으로 "진행 중" 요구를
  충족하므로, 미리보기까지 추가하지 않는다(복잡도 대비 이득이 작다고 판단).
- 문서 저장 버튼을 업로드 진행 중에는 비활성화하는 것 — 이번 범위는 "진행 표시" 자체이고,
  저장 타이밍 가드는 별도 요구가 없어 다루지 않는다.
