## 자동화 테스트
전체 스위트(`npm test`)를 매번 돌리지 않는다 — 변경 파일과 직접 연관된 테스트, 변경 파일
대상 린트만 기본으로 실행한다(CLAUDE.md 참고). 변경 범위가 넓거나 회귀 위험이 높을 때만
전체 `npm test`를 추가하고 이유를 아래에 적는다.

| 커맨드 | 결과 |
|---|---|
| `npx vitest run <바뀐 파일과 짝인 테스트 파일들>` | |
| `npx eslint <바뀐 파일들>` | |
| `npm run build`(코드 변경이 있을 때만) | |

## 수동 검증 (필요 시)
브라우저로 확인한 시나리오와 결과. 스크린샷/로그 등 근거를 남긴다.

## 발견된 문제와 조치
문제가 없었다면 "없음"이라고 쓴다. 있었다면 아래 순서로 기록한다.
- **원인**: ...
- **조치**: ...
- **재검증 결과**: ...

## 검증 중 새로 발견한 결정 사항
없으면 "없음". 있으면 GitHub Issue 링크와 함께 적는다.
