# P17-8: 이미지 노드 삭제/재업로드 버튼

## 배경
- PRD(`docs/product/prd.md`) Phase 17, P17-8 항목: "이미지 노드 삭제/재업로드 버튼 —
  이미지 블록에 alt 텍스트 입력 외에 삭제·다시 업로드 동작이 없는 것을 보완한다."
  (조사 중 추가 발견된 항목.)
- 이미지가 선택돼 있을 때만 뜨는 버블 메뉴(`ImageBubbleMenu`)에는 alt 텍스트 입력
  폼(`ImageAltPopoverForm`)만 있고, 잘못 올린 이미지를 지우거나 다른 파일로 바꿀
  방법이 없었다 — 커서를 옮겨 Backspace를 누르는 것 말고는 대안이 없어 발견하기
  어려웠다.

## 수용 기준 (Acceptance Criteria)
- [ ] 이미지를 클릭해 선택하면(기존 alt 입력 버블 메뉴가 뜨는 바로 그 시점) 삭제
      버튼과 다시 업로드 버튼도 같은 메뉴에 보인다.
- [ ] 삭제 버튼을 누르면 그 이미지 노드가 문서에서 즉시 사라진다(확인 Modal 없이 —
      아래 "결정" 참고).
- [ ] 다시 업로드 버튼을 누르면 파일 선택 창이 뜨고, 새 파일을 고르면 업로드 진행
      중 스피너(P17-9와 같은 자리표시자 패턴)가 같은 자리에 보인 뒤 새 이미지로
      교체된다.
- [ ] 다시 업로드가 실패하면 원래 이미지로 되돌아가고(사라지지 않음) 에러 토스트가
      뜬다.
- [ ] 문서 저장 전(pageId 없음)에 다시 업로드를 시도하면 파일 선택 창을 열지 않고
      안내 토스트만 띄운다(기존 이미지 삽입 경로와 같은 패턴).

## 결정이 필요한 사항
- 이미지 삭제에 확인 Modal이 필요한가? → **결정: 필요 없음, 즉시 삭제.** 근거:
  이미지 삭제는 이미 오늘도 가능한 동작이다(이미지를 선택하고 Backspace) — 새
  버튼은 그 기존 능력을 더 찾기 쉽게 만드는 것뿐이지 새로운 파괴력을 추가하는 게
  아니다. 문단·헤딩·패널 등 다른 어떤 블록 노드도 삭제에 확인을 요구하지 않는
  이 에디터의 일관된 관례이기도 하고, P17-7에서 이미 "파괴성이 크지 않은 블록
  단위 삭제는 즉시 실행"으로 정리한 결정과도 일치한다. GitHub Issue 등록 대상
  아님(추측이 아니라 기존 관례에서 직접 도출되는 결론).
- 재업로드 시 기존 alt 텍스트를 유지할지 비울지 → **결정: 유지.** 새 이미지가
  기존 alt와 안 맞을 수도 있지만, 임의로 지우는 것보다 사용자가 필요하면 alt
  팝오버로 직접 고치게 하는 쪽이 데이터를 덜 파괴한다.

## 범위 밖
- 이미지 크기 조정(리사이즈 핸들) — 별개 기능, 이번 요청에 없음.
- 여러 이미지를 한 번에 선택해 일괄 삭제 — 표의 행/열 다중 선택과 달리 이미지는
  노드 하나씩 선택하는 게 기존 관례라 범위 밖.
