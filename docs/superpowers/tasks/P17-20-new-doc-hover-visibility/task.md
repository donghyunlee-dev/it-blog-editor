# P17-20: 새 문서 버튼 hover가 라이트 모드에서 안 보이던 문제 수정 — task

## 배경
- 사용자가 P17-14(새 문서 버튼 강조도 낮춤) 병합 후 실사용하며 지적: "새문서 마우스
  오버했을 때 변환[반응]이 없다"는 리포트. 이어진 확인 질문에 사용자가 구체화:
  "마우스 오버 했을 때 아무 인터렉션이 없음. 배경 색이 변경이 된다든가[를 기대함]."
- 원인 확인: P17-14에서 `hover:bg-surface-raised`를 썼는데,
  `node_modules/@sfood/ui/tokens/semantic.css` 14~17행에 따르면 **라이트 모드**에서는
  `--color-surface-raised`가 `--color-surface`와 완전히 같은 값(둘 다 `var(--white)`)
  이다 — 즉 hover 시 배경색이 바뀌는 것처럼 클래스는 있지만 실제로는 같은 색이라
  아무 변화가 없다(다크 모드에서는 gray-900→gray-800으로 실제로 달라 정상 작동한다 —
  이 세션이 다크 모드로만 확인해 놓쳤다).
- 이 프로젝트는 이미 같은 버그를 문서·폴더 행에서 한 번 겪고 고친 적이 있다
  (`EditorSidebar.tsx`의 P13-2 주석, `globals.css`의 `.sidebar-row-hover` —
  `color-mix(in srgb, var(--color-brand) 5%, var(--color-surface))`를 써서 라이트/
  다크 어느 쪽이든 항상 실제로 다른 색이 나오게 한다). 그 해결책을 그대로 재사용한다.

## 수용 기준 (Acceptance Criteria)
- [x] "새 문서" 버튼에 마우스를 올리면 라이트 모드에서도 배경색이 실제로 바뀐다.
- [x] 다크 모드에서도 기존과 동일하게(또는 더 낫게) hover가 보인다 — 회귀 없음.
- [x] 새 색상을 하드코딩하지 않고, 이미 이 파일의 다른 행(문서·폴더)이 쓰는
      `.sidebar-row-hover` 클래스를 그대로 재사용한다.

## 결정이 필요한 사항
없음 — 이미 이 코드베이스에 확립된 해결책(`.sidebar-row-hover`)을 재사용하는
명확한 버그 수정이라 새로 정할 값이 없다.

## 범위 밖
- 이 파일의 다른 `hover:bg-surface-raised` 사용처(폴더 "+"·문서 옵션 등 아이콘
  버튼들)는 `hover:text-foreground`를 함께 써서 텍스트 색이 바뀌므로 완전히 무반응은
  아니다 — 사용자가 구체적으로 지적한 것도 아니라 이번 작업에서는 손대지 않는다.
