# P17-6: 슬래시 메뉴 항목 아이콘 추가

## 배경
- PRD(`docs/product/prd.md`) Phase 17, P17-6 항목: "슬래시 메뉴 항목 아이콘 추가 —
  `CommandItem`에 아이콘 필드를 추가하고 렌더러가 텍스트 앞에 아이콘을 함께 그리도록
  한다(버블 메뉴의 "B"/"I"/"</>" 글자 아이콘과는 별개로, 각 블록 타입을 나타내는
  아이콘 사용)."
- 슬래시 메뉴(`/`)는 제목만 나열된 텍스트 목록이라, 항목이 13개(제목1/2/3·글머리
  목록·번호 목록·인용구·구분선·표·코드블록·인라인 코드·패널 3종)+동적 2개(이미지·
  문서 링크)로 늘어난 지금은 원하는 항목을 빠르게 훑어보기 어렵다.
- 렌더러(`SlashCommandExtension.ts`의 `createSlashMenuRenderer`)는 React가 아니라
  `document.createElement`로 직접 DOM을 만드는 순수 TS 모듈이라, 아이콘은 JSX
  컴포넌트가 아니라 문자열(SVG 마크업 또는 이모지)로 전달해야 한다.

## 수용 기준 (Acceptance Criteria)
- [x] `CommandItem`에 아이콘 필드(`icon?: string`)가 추가된다.
- [x] 기본 13개 항목(제목1/2/3·글머리 목록·번호 목록·인용구·구분선·표·코드블록·
      인라인 코드·정보/경고/노트 패널) 전부에 각 블록 타입을 나타내는 아이콘이
      지정된다.
- [x] 동적으로 주입되는 "이미지"·"문서 링크" 항목에도 아이콘이 지정된다.
- [x] 슬래시 메뉴 렌더러가 각 버튼에 아이콘(있으면)을 텍스트 앞에 함께 그린다.
- [x] 아이콘은 장식용(`aria-hidden`)이라 버튼의 접근성 이름(스크린리더가 읽는 텍스트)은
      기존과 동일하게 항목 제목만 유지된다.
- [x] `icon` 필드가 없는 `CommandItem`(기존 테스트 픽스처 등)도 아이콘 없이 정상
      렌더링된다(하위 호환 — 필드를 optional로 둔다).

## 결정이 필요한 사항
없음 — 아이콘의 정확한 모양은 디자인 승인이 필요한 브랜드 자산이 아니라 각 블록
타입을 알아볼 수 있게 하는 장식적 요소이므로, PRD 항목 자체가 요구하는 "블록 타입을
나타내는 아이콘"이라는 기준을 벗어나지 않는 선에서 구현자가 정한다(기존 `TableIcon`/
`CodeCopyIcon`과 같은 시각 스타일 — viewBox 0 0 24 24, stroke=currentColor,
stroke-width=2, h-4 w-4 — 를 그대로 따른다). 패널 3종은 이미 존재하는
`DEFAULT_PANEL_ICONS`(ℹ️/⚠️/📝) 이모지를 그대로 재사용한다.

## 범위 밖
- 새 아이콘 라이브러리(lucide-react 등) 추가 — 기존 프로젝트 관례(직접 그린 인라인
  SVG)를 따른다.
- 슬래시 메뉴 자체의 레이아웃(그리드/컬럼 등) 개편 — 아이콘 추가만 다룬다.
