# P8-4: 소개/랜딩 화면 메인 검색 진입점 추가

## 배경
support.claude.com/ko 벤치마킹(`docs/product/design.md` "벤치마킹" 절 "8. 검색")에서, 레퍼런스
홈 화면 히어로에 420×49px 큰 검색 버튼이 있어 "메인 화면에서 바로 검색되는 것처럼" 보인다는
점을 확인했다. 다만 실측 결과 그 버튼도 실제 `<input>`이 아니라 헤더의 작은 검색 버튼과
**동일한 커맨드 팔레트 모달**을 여는 트리거 버튼이었다 — 이 프로젝트에 이미 있는
`GlobalSearchModal`(Ctrl+K, P8-1에서 헤더 트리거 추가 완료)과 정확히 같은 구조다.

관련 PRD 항목: `docs/product/prd.md`의 **P8-4**(Phase 8, 에디터 UI 레이아웃 벤치마킹).

## 수용 기준 (Acceptance Criteria)
- [x] `/editor` 랜딩 화면(EditorHomePage) 히어로 영역에 큰 검색 버튼을 추가한다.
- [x] 버튼 클릭 시 새 검색 로직 없이 기존 `GlobalSearchModal`을 그대로 연다.
- [x] 버튼에 포커스한 뒤 Enter 키로도 열 수 있다(네이티브 `<button>` + 클릭 핸들러).
- [x] 기존 `Ctrl+K` 단축키·헤더 검색 버튼(P8-1)·`EditorSidebar`의 문서 목록 검색창과 동작이
      중복되거나 충돌하지 않는다 — 모두 같은 하나의 `GlobalSearchModal` 인스턴스를 연다는
      것을 회귀 테스트로 고정한다.
- [x] 랜딩 화면(`src/app/editor/page.tsx`)은 서버 컴포넌트로 유지한다 — 검색 버튼만 별도
      클라이언트 컴포넌트로 분리해 페이지 전체를 클라이언트 컴포넌트로 바꾸지 않는다.

## 결정이 필요한 사항
없음 — design.md에 이미 실측값(420×49px, radius:12px)과 "실제로는 모달 트리거"라는 근거가
있고, 랜딩 화면에 이미 있는 유일한 `primary` 액션("새 문서 작성")과 시각적 우선순위가
겹치지 않도록 이 버튼은 중립 톤으로 두기로 직접 정했다(GitHub Issue 불필요 — 사소한 구현
디테일 판단).

## 범위 밖
- 새 검색 기능·API — 기존 `GlobalSearchModal`을 여는 트리거만 추가한다.
- 랜딩 화면의 다른 레이아웃 변경(스포트라이트 카드, 보조 팁 그리드 등)은 이 항목과 무관.
