# P17-17: 좁은 화면에서 목차를 드로어로 열기 — task

## 배경
- 외부(GPT) UI 개선 제안 리뷰 중 채택한 항목(7번, 저우선). 우측 목차(TOC)는
  `xl`(1280px) 이상에서만 보이고(`EditorShell.tsx`의 `hidden w-60 shrink-0
  xl:block`), 그보다 좁은 화면(노트북처럼 애매하게 좁은 구간 포함)에서는 목차
  자체에 접근할 방법이 전혀 없었다.
- 외부 리뷰 제안: "Desktop: 본문+TOC / 작은 노트북: 본문+접힌 목차 버튼 / Tablet:
  본문만. 상단에 '☰ 이 페이지' 버튼 하나만 보여주고 클릭하면 Drawer로 연다."
- 실제 코드 확인: `@sfood/ui`가 이미 `Drawer`(열림 상태를 props로 받는 controlled
  컴포넌트, 우측/좌측 슬라이드, Escape·바깥 클릭으로 닫힘, `node_modules/@sfood/ui/dist/index.d.ts`
  확인)를 제공해 새 드로어 로직을 직접 구현할 필요가 없었다.
- 관련 코드: `src/components/editor/TableOfContents.tsx`(레일 콘텐츠를 만드는 곳),
  `src/components/editor/EditorShell.tsx`(`xl:block` 레일 슬롯, 손대지 않음).

## 수용 기준 (Acceptance Criteria)
- [x] `xl`(1280px) 이상: 기존 동작 그대로(우측 레일, 변경 없음).
- [x] `md`(768px)~`xl`(1280px) 사이: 우측 레일은 숨겨지고, 대신 화면에 "이 페이지"
      토글 버튼이 보인다.
- [x] `md` 미만(모바일): 토글 버튼도 보이지 않는다(기존과 동일하게 목차 자체에
      접근할 방법이 없음 — 이번 작업의 범위 밖).
- [x] 헤딩이 하나도 없는 문서는 이 구간에서도 토글 버튼을 렌더링하지 않는다(기존
      "헤딩 없으면 렌더링 자체를 안 한다" 원칙과 동일).
- [x] 토글 버튼을 누르면 `@sfood/ui`의 `Drawer`가 우측에서 열리고, 레일과 동일한
      목차 항목 목록(활성 항목 강조 포함)을 보여준다.
- [x] 드로어 안에서 항목을 클릭하면 레일에서와 동일하게 해당 헤딩으로 스크롤
      이동하고, 추가로 드로어를 닫는다(목적을 이미 이뤘으므로).

## 결정이 필요한 사항
없음 — `@sfood/ui`의 `Drawer`를 그대로 재사용하는 반응형 개선이라 새로 정할 값이
없다.

## 범위 밖
- `md` 미만(모바일)에서 목차 접근 방법 제공 — 외부 리뷰도 "Tablet: 본문만"으로
  명시해 이번 범위에서 다루지 않는다.
- TOC 레일 자체의 폭(240px)이나 본문 폭 조정 — 별도 항목(5번, GitHub Issue #161로
  결정 대기 중)에서 다룬다.
