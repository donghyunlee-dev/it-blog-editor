# P17-17: 좁은 화면에서 목차를 드로어로 열기 — 구현 결과 보고서

## 구현 내용
- `TableOfContents.tsx`가 더 이상 항상 `null`을 반환하지 않는다 — 헤딩이 있으면
  `md`(768px)~`xl`(1280px) 구간에서만 보이는 고정 위치 토글 버튼("☰ 이 페이지")과,
  그 버튼으로 여는 `@sfood/ui`의 `Drawer`(우측 슬라이드)를 함께 반환한다. `xl` 이상의
  기존 레일(`TocRailContext`)은 전혀 손대지 않았다.
- 레일과 드로어가 완전히 같은 목록 마크업(`renderHeadingList()`)을 공유한다 — 활성
  헤딩 강조, 클릭 시 스크롤 로직이 두 곳에 복붙되지 않는다. 드로어 안에서는 클릭 시
  추가로 드로어를 닫는다.

## 자체 검토 (Self-Review)
### 긍정 사항
- 새 드로어 로직을 직접 구현하지 않고 `@sfood/ui`의 `Drawer`를 그대로 재사용했다 —
  열림 상태·Escape/바깥 클릭 닫힘을 처음부터 만들 필요가 없었다.
- 레일과 드로어가 같은 함수(`renderHeadingList`)를 공유해, 향후 목차 항목 마크업을
  바꿀 때 한 곳만 고치면 된다.
- 임시 디버그 페이지에서 세 breakpoint(375/1024/1440px)를 모두 실측해 각 구간의
  표시 여부가 정확히 의도대로(모바일: 아무것도 없음, 노트북: 버튼만, 데스크톱: 레일만)
  동작함을 확인했고, 드로어 오픈 → 항목 클릭 → 스크롤+드로어 닫힘까지 실제 클릭
  흐름으로 확인했다.

### 주의사항
- `@sfood/ui`의 `Drawer`는 닫힌 상태에서도 패널이 DOM에 남아있다(전환 애니메이션
  때문 — 컴포넌트 자체의 문서화된 동작). 그 결과 이 컴포넌트가 렌더링하는 동안
  "이 페이지" 목록이 레일(항상 DOM에 있음)과 드로어(항상 DOM에 있지만 닫히면
  `aria-hidden`) 두 군데에 동시에 존재한다 — 실제 브라우저에서는 CSS로 한쪽만
  보이므로 문제가 없지만, 테스트에서 전역 DOM을 스캔하는 방식은 피해야 한다(아래
  "발견된 문제" 참고).

### 우려사항
- 없음 — `xl` 레일 자체의 로직(`useEffect`가 `setTocRail`을 호출하는 부분)은 전혀
  건드리지 않았고, 관련 테스트(TableOfContents 21개, EditorShell/DocumentEditor
  61개) 모두 통과해 회귀 위험이 낮다.
