# P16-1: "삭제된 문서"를 팝업 대신 전용 페이지로 — 검색 + 상세 정보

## 배경
"삭제된 문서"(P1-2b)는 지금 사이드바 하단 버튼 → `Modal` → `DeletedDocumentsModal` 목록으로
구성돼 있다. 사용자 지적: "삭제된 문서는 늘어날 수록 팝업으로 감당이 안돼. 삭제된 문서
클릭 시 오른쪽 페이지 영역에 상단 검색과 하단 삭제된 페이지 리스트가 나오도록 구성을
해야 할 것 같아. 검색해서 복구할 수 있으면 좋을 것 같고, 삭제된 페이지 정보 표시도 좀 더
상세하게 보여 줄 수 있을 것 같아. 페이지 영역을 잘 활용해서 삭제된 문서 리스트 페이지를
잘 구성하는 방향으로 진행해줘."

세 가지 요구를 분해하면:
1. Modal → 전용 페이지(다른 `/editor/*` 라우트처럼 본문 영역 전체를 씀).
2. 검색으로 필터링해서 복구.
3. 삭제된 문서 정보를 더 상세히(현재 `DeletedDocumentEntry`는 `pageId`/`title`/`deletedAt`
   3개뿐이다).

3번을 위해 `DeletedDocumentEntry`에 삭제 시점 스냅샷(태그·게시 상태·소속 폴더)을 추가해야
한다 — 이 정보는 삭제 시점(`deleteDocument()`가 실제로 Confluence 페이지를 지우기 *직전*)
에만 조회 가능하고, 삭제된 뒤에는(정확히는 페이지가 실제로 사라진 뒤에는) 더 이상 그
페이지에서 직접 읽을 수 없다 — 그래서 삭제 시점에 레지스트리에 함께 기록해 둬야 한다.
폴더는 "이름"이 아니라 "id"만 기록한다 — 이름이 나중에 바뀌어도(폴더 이름 변경) 오래된
이름이 박제되지 않게, 조회 시점에 현재 폴더 트리에서 이름을 다시 찾는다(그 폴더가 그 사이
삭제됐으면 "미분류"와 동일하게 표시).

## 수용 기준 (Acceptance Criteria)
- [x] 사이드바의 "삭제된 문서" 버튼이 `Modal`을 여는 대신 새 라우트(`/editor/trash`)로
      이동한다 — 다른 문서 열람/작성처럼 오른쪽 본문 영역 전체를 쓴다.
- [x] 그 페이지 상단에 검색 입력이 있고, 제목·태그로 필터링된다(사이드바 문서 검색과
      같은 방식).
- [x] 하단에 삭제된 문서 리스트가 나온다. 각 행에 제목·삭제일시(기존)뿐 아니라 게시
      상태(아이콘)·태그·원래 있던 폴더 이름(또는 "미분류")을 보여준다.
- [x] 각 행에서 검색 결과 그대로 복구할 수 있다(기존 "복구" 버튼 동작 유지 — 성공하면
      목록에서 제거 + Toast + 사이드바 새로고침).
- [x] `DeletedDocumentEntry`(레지스트리에 저장되는 항목)에 `tags`·`isPublished`·`folderId`가
      추가되고, `deleteDocument()`가 삭제 시점에 이 값을 함께 기록한다. 이 필드가 없는(이번
      변경 이전에 기록된) 옛 항목은 기본값(빈 배열/`false`/`null`)으로 안전하게 표시된다.
- [x] 목록이 비어 있으면(전체 또는 검색 결과) 안내 문구를 보여준다.

## 결정이 필요한 사항
없음 — 사용자가 페이지 레이아웃(상단 검색 + 하단 리스트)과 목적(검색 복구, 상세 정보)을
직접 지정했다. 상세 정보의 구체적 항목(태그·게시 상태·폴더)은 `DocumentSummary`가 이미
사이드바에서 보여주는 정보와 동일한 종류라 임의로 새 개념을 만들지 않고 그대로 따른다.

## 범위 밖
- 삭제된 문서의 미리보기(본문 내용 확인) — 목록/복구만 다룬다.
- 완전 삭제(영구 삭제) 버튼 — 지금처럼 Confluence 자체 휴지통 보관 기간에 맡긴다.
- 폴더 트리 위치 그대로 복구되는 것 확인 UI — 실제 복구 동작(`restoreDocument`)은 이미
  P7-9에서 처리하고 있고, 이번 작업은 그 결과를 미리 보여주는 표시만 추가한다.
