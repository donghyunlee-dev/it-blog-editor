# P11-1: 사이드바 문서 목록 행에서 태그 표시 제거

## 배경
[노션 재현 검토](https://bird-earl-256.notion.site/SFOOD-AI-3d7be4fbb834817f8ed2c4742219ce7b) 문서를 실제로 이 에디터에 만들어 넣어 본 뒤(P10-1 검증 과정, 문서마다 태그 2개씩 부여) 사용자가 실사용 화면을 보고 "태그가 문서 리스트에 너무 공간을 차지한다"고 지적했다(2026-09-11). `EditorSidebar.tsx`가 문서 행마다 제목 아래에 태그 칩을 `flex-wrap`으로 무제한 나열하고 있어, 태그가 2개만 있어도 대부분 2줄짜리 행이 되어 문서가 많을 때 한 화면에 보이는 문서 수가 줄어드는 문제를 직접 확인했다. 몇 가지 개선안(1줄 고정+"+N" 축약, 태그 개수 제한, 보류)을 제시했으나 사용자가 "일단 리스트에서는 제거하자 — 리스트가 너무 흩어진다, 문서가 많으면 한 화면에 몇 개도 안 보일 것"이라고 직접 결정했다.

## 수용 기준 (Acceptance Criteria)
- [ ] 사이드바 문서 목록(미분류 문서, 폴더 안 문서, 공유받은 문서 등 모든 목록)의 각 행에 더 이상 태그 칩이 표시되지 않는다 — 제목(+상태 아이콘)만 한 줄로 보인다.
- [ ] 상단 태그 필터(`ChipGroup`, "전체 태그 보기")는 그대로 유지된다 — 태그로 문서를 찾는 기능 자체는 없애지 않는다.
- [ ] Ctrl+K 전역 검색(`GlobalSearchModal`)의 태그 표시는 이번 범위가 아니다(사이드바 행 한정 요청) — 그대로 둔다.
- [ ] 기존 회귀 테스트가 모두 통과하고, "문서 목록 행에 태그가 없다"는 것을 검증하는 테스트로 갱신된다.

## 결정이 필요한 사항
없음 — 사용자가 대화 중 직접 "제거"로 확정했다(값에 정답이 없는 UI 트레이드오프를 사용자가 이미 선택).

## 범위 밖
- Ctrl+K 검색 결과·미리보기 패널의 태그 표시(`GlobalSearchModal.tsx`) — 사이드바 목록과 별개 화면이라 이번 요청과 무관.
- 태그 자체 기능(추가/제거/필터)은 변경하지 않는다 — 목록 행의 "표시"만 없앤다.
