# P12-2: 태그 입력 영역을 본문 하단으로 이동 + 컴팩트화 + placeholder 조건부 숨김

## 배경
태그 기능 재검토(2026-09-14, P12-1과 같은 대화)에서 태그의 역할을 "폴더에 준하는 1급 분류
축"에서 "검색 시 매칭되는 가벼운 키워드"로 좁히기로 했다. 이에 맞춰 편집 화면에서 태그 입력
영역의 위상도 낮춘다 — 지금은 제목 바로 아래(`DocumentEditor.tsx`)에 "라벨 한 줄 + 입력 박스
한 줄"로 2줄을 차지하며 제목과 같은 "문서 메타" 묶음처럼 상단에 배치되어 있는데, 사용자가
직접 다음을 지적했다: "지금은 타이틀과 입력란 2줄로 구성이 되어 있어서 영역을 많이 차지해",
"컨텐츠에 태그 작성하는 영역은 하단으로 내리고 좀 더 컴팩트하게 구성해줘", "이미 등록된 tag가
있으면 placeholder는 안보여야 하는 게 맞아".

## 수용 기준 (Acceptance Criteria)
- [ ] 태그 입력 영역이 제목 바로 아래(본문 위)가 아니라 본문(TipTap 에디터) 아래, 풋터(최종
      수정일 등) 영역과 같은 자리 또는 그 바로 위로 이동한다. 새 문서 작성(`/editor/new`, 풋터가
      없는 모드)에서도 태그 입력은 그대로 보여야 한다(풋터 렌더링 조건에 종속시키지 않는다).
- [ ] 라벨과 입력 박스가 각각 한 줄씩 차지하던 2줄 레이아웃을, 라벨+칩+입력을 한 행에 배치하는
      1줄(태그가 많아 줄바꿈되는 경우 제외) 레이아웃으로 압축한다.
- [ ] 태그가 하나 이상 있으면 입력 필드의 placeholder("예: React, Backend")가 보이지 않는다 —
      태그가 없을 때만 보인다.
- [ ] 기존 태그 입력 동작(Enter/쉼표로 확정, IME 조합 처리, 자동완성 드롭다운, 칩 삭제)은 전혀
      변경하지 않는다.
- [ ] 기존 회귀 테스트가 모두 통과하고, placeholder 조건부 표시를 검증하는 테스트가 추가된다.
      기존 테스트 중 태그가 있는 상태에서 `getByPlaceholderText`로 입력을 찾던 것은 더 이상 그
      방식으로 찾을 수 없으므로 `getByRole("combobox", { name: "태그" })` 등 placeholder에
      의존하지 않는 쿼리로 교체한다.

## 결정이 필요한 사항
없음 — 위치(하단)·압축 방식(1줄)·placeholder 조건은 사용자가 대화 중 직접 지정했다.

## 범위 밖
- 태그 데이터·검증·API(`tags.ts`, `[pageId]/tags/route.ts`)는 변경하지 않는다.
- 자동완성 후보 계산 로직(`tag-suggestions.ts`)은 변경하지 않는다.
- 사이드바 태그 필터 제거(P12-1) — 별도 작업·별도 PR.
