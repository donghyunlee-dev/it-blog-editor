# P10-1: 문서 링크 카드 블록

## 배경
[노션 페이지 재현 검토](https://bird-earl-256.notion.site/SFOOD-AI-3d7be4fbb834817f8ed2c4742219ce7b)에서 지적된 두 번째 격차 — 노션은 다른 페이지를 아이콘+제목+화살표가 있는 카드형 블록으로 삽입해 클릭 한 번으로 이동할 수 있는데, 이 프로젝트는 일반 텍스트 하이퍼링크만 있고 이런 카드형 블록이 없다(콜아웃 아이콘 자유 지정, Phase 9 완료 후 사용자가 이어서 요청, 2026-09-11). `docs/product/prd.md`의 Phase 10(P10-1) 항목.

## 수용 기준 (Acceptance Criteria)
- [ ] 슬래시 메뉴에 "문서 링크" 항목이 있다(문서가 저장돼 `pageId`가 있을 때만 노출 — 기존 "이미지" 항목과 같은 제약).
- [ ] "문서 링크"를 선택하면 검색 모달이 열리고, 제목·태그·본문으로 문서를 검색할 수 있다(기존 `GET /api/editor/documents/search` 재사용).
- [ ] 검색 결과에서 문서를 클릭하면 슬래시 입력이 지워지고 그 자리에 카드(고정 아이콘 📄 + 문서 제목 + 화살표)가 삽입된다.
- [ ] 카드를 클릭하면 해당 문서 편집 화면(`/editor/{pageId}`)으로 이동한다.
- [ ] 현재 편집 중인 문서 자신은 검색 결과에서 제외된다(자기 자신을 링크할 수 없음).
- [ ] `tiptap-to-storage.ts`가 `documentLink` 노드를 사람이 읽을 수 있는 텍스트로 직렬화한다(제목·문서 ID 포함, XSS 이스케이프 포함) — `panel`과 마찬가지로 역방향 파싱은 만들지 않는다.
- [ ] 기존 회귀 테스트가 모두 통과하고, 새 기능(슬래시 항목 노출 조건, 카드 삽입, 클릭 이동, storage 직렬화)을 검증하는 테스트가 추가된다.

## 결정이 필요한 사항
값 자체에 정답이 없는 순수 구조적 선택이라 GitHub Issue 없이 직접 정했다(P1-6a와 같은 근거) — 근거는 `docs/product/prd.md` Phase 10 "핵심 결정" 참고:
- 제목은 삽입 시점 스냅샷 캐시(실시간 재조회 안 함) — API 호출 비용 때문.
- 링크 대상은 검색 피커로만 고른다(pageId 직접 입력 없음) — 기존 검색 API가 이미 "내 문서만" 범위로 좁혀져 있어 접근 권한 우회 경로가 생기지 않는다.
- 공유받은 문서는 이번 검색 대상에서 제외(범위 밖) — `searchDocuments`가 계정 폴더 기준이라 기본 동작이 이미 그렇다.
- 아이콘은 모든 카드에 고정 이모지(📄) 하나만 쓴다 — 문서 자체에 아이콘 필드가 없어(조사 확인), 문서별 아이콘은 별개의 더 큰 작업이다.

## 범위 밖
- 실시간 제목 갱신(대상 문서 제목이 바뀌어도 카드는 갱신되지 않음 — 알려진 제약, 다시 삽입해야 함).
- pageId 직접 입력, 공유받은 문서 링크, 문서별 커스텀 아이콘.
- 카드 미리보기(본문 스니펫 등 노션의 "미리보기" 모드).
- Confluence storage → TipTap JSON 역방향 파서 신설(`panel`과 동일한 이유로 범위 밖).
