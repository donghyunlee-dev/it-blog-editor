# P0-2: 게시취소 확인 모달

## 배경
2026-08-27 [프로덕션 준비도 감사](https://claude.ai/code/artifact/87302c07-68d6-42ed-8712-9345547cb659)에서 P0로 지적된 항목. 게시 설정 Modal(`PublishForm.tsx`)의 "게시함" `Switch`는 클릭 즉시 `persist()`를 호출해(`handlePublishedChange`, `src/components/editor/PublishForm.tsx:118-121`) Confluence 페이지를 비공개(초안) 폴더로 옮긴다. 문서 삭제에는 `Modal` 확인 절차가 있는데(`DocumentEditor.tsx`), 이미 Space 전체에 공개된 문서를 순간적으로 비공개로 되돌리는 이 동작에는 같은 안전장치가 없다.

관련 PRD 항목: [docs/product/prd.md](../../../docs/product/prd.md) Phase 4, P0-2.

## 수용 기준 (Acceptance Criteria)
- [ ] 이미 게시된 문서에서 "게시함" 스위치를 꺼서 게시를 취소하려 하면, 즉시 저장 요청을 보내지 않고 `Modal`로 먼저 확인받는다.
- [ ] 확인 Modal에서 "취소"(또는 계속 게시 유지)를 누르면 스위치는 켜진 상태 그대로 남고, 어떤 저장 요청도 나가지 않는다.
- [ ] 확인 Modal에서 "게시 취소"를 확정하면 그제서야 기존 로직(`persist`)이 실행되어 실제로 게시가 취소된다.
- [ ] 아직 게시되지 않은 문서에서 "게시함" 스위치를 켤 때(게시 시작)는 이 확인 절차를 거치지 않는다 — 기존처럼 즉시 저장된다(감사에서 지적된 위험은 "이미 공개된 문서가 실수로 순간 비공개 전환"되는 쪽이지, 게시 자체가 아니다).
- [ ] 뷰어별 노출 스위치(`enabledViewers` 토글)나 slug/메타 설명 입력은 이 확인 절차의 대상이 아니다(기존 동작 유지) — 문서 전체의 게시 여부를 끄는 마스터 스위치만 대상이다.
- [ ] 기존 `PublishForm.test.tsx` 테스트가 깨지지 않는다(필요하면 게시 취소를 다루는 기존 테스트를 이 새 확인 절차에 맞게 갱신한다).
