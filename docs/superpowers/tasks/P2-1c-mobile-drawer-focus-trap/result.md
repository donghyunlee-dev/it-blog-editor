# P2-1c: 모바일 오프캔버스 드로어 포커스 트랩 — 구현 결과 보고서

## 구현 내용
- `EditorShell.tsx`에 `GlobalSearchModal.tsx`의 포커스 트랩(첫 포커스 이동 → Tab 순환 →
  닫힐 때 포커스 복원)과 같은 패턴을 재현했다.
  - 사이드바 드로어 래퍼(`fixed inset-y-0 left-0 z-40 ...` div)에 `drawerRef`를 달고,
    `isMobile && open`일 때만 동작하는 `useEffect`를 추가했다.
  - 드로어가 열리면 안의 첫 포커스 가능 요소로 포커스를 옮기고, Tab/Shift+Tab이 드로어의
    첫/마지막 요소 경계에서 반대쪽으로 순환하게 했다.
  - Escape를 누르면 드로어를 닫는다 — 모바일 사이드바에는 원래 키보드로 닫을 수 있는 버튼이
    하나도 없었다(데스크톱 전용 "문서함 접기" 버튼은 `md:block`으로 모바일에서 숨겨져 있음).
    포커스 트랩만 추가하고 Escape를 빠뜨리면 키보드 사용자가 드로어에 갇히는 문제가 생겨,
    이번 항목에 함께 포함했다(`task.md`의 "추가로 발견한 문제" 참고).
  - 드로어가 닫히면(Escape든 배경 클릭이든) 열기 직전 포커스가 있던 요소로 되돌아간다.
  - 데스크톱(`!isMobile`)에서는 이 effect가 조건에서 즉시 반환돼 전혀 개입하지 않는다.
- **구현 중 발견한 버그를 미리 막음**: 데스크톱 전용 컨트롤(사이드바의 "문서함 접기" 버튼,
  폭 조절 핸들)은 모바일에서 Tailwind `hidden` 클래스로 화면에서만 안 보일 뿐 DOM에는
  그대로 남아있다. 포커스 가능 요소를 단순히 `querySelectorAll(FOCUSABLE_SELECTOR)`로만
  계산하면 이 안 보이는 요소를 "첫/마지막 포커스 대상"으로 잘못 계산해 Tab 순환 경계가
  실제 화면과 어긋나는 버그가 생긴다(실제 브라우저는 `display:none` 요소를 Tab 순서에서
  건너뛰므로, 코드의 계산과 실제 브라우저 동작이 어긋난다). `getFocusables()` 헬퍼에서
  `classList.contains("hidden")`인 요소를 제외해 해결했고, 폭 조절 핸들에는 추가로
  모바일에서 `tabIndex={-1}`을 줘 애초에 후보에서 빠지게 했다(이중 방어).

## 자체 검토 (Self-Review)
### 긍정 사항
- 하드코딩된 "이 요소가 첫/마지막"이라는 가정 대신, 테스트도 구현과 같은 선택자·필터로
  "지금 실제 포커스 가능한 요소"를 계산해 검증하게 했다 — 사이드바 내부 구조가 나중에
  바뀌어도(문서 검색 입력 위치 변경 등) 테스트가 헛되이 깨지지 않는다.
- CSS로만 숨겨진 데스크톱 전용 컨트롤이 경계 계산을 오염시키는 버그를 실제로 짜기 전에
  코드 리딩으로 먼저 찾아내 필터링했다 — "실제 브라우저의 Tab 스킵 동작"과 "코드가 계산한
  경계"가 어긋나는 미묘한 종류의 버그라 자동화 테스트만으로는 잡기 어려웠을 수 있다.
- 데스크톱에서는 토글 버튼이 CSS로만 숨겨져 있어 테스트 환경(jsdom/happy-dom, 실제 CSS
  미적용)에서는 여전히 클릭 가능하다는 것까지 확인하고, 그 상태에서도 `isMobile` 게이트로
  트랩이 개입하지 않음을 직접 검증했다.

### 주의사항
- 실제 모바일 기기·스크린 리더로 직접 확인하는 수동 검증은 AX Auth 로그인 제약으로 하지
  못했다(P1-7 시리즈·P2-1a/b와 동일한 제약) — jsdom 기반 자동화 테스트로 포커스 이동·순환·
  복원을 검증했다.
- 배경 스크롤 잠금(`body.style.overflow`)은 추가하지 않았다 — `task.md`의 "범위 밖"에 근거를
  남겼다(이 드로어는 이미 `position: fixed` + 내부 스크롤 컨테이너 구조라 문서 body 자체가
  스크롤되는 경로가 없음을 코드로 확인).
