## 수동 검증 (필요 시)
- `preview_start`로 로컬 dev 서버(`editor-dev`, localhost:3100)를 띄워 확인을 시도했으나
  `/editor`가 MS 계정 로그인(AX Auth) 화면으로 이어져, 이 세션에서는 그 이상 진행할 수
  없었다(P1-7 시리즈·P2-1a/b와 동일한 환경 제약). 실제 모바일 뷰포트에서 드로어를 열고
  Tab/Shift+Tab으로 순환이 실제로 체감되는지, 실제 스크린 리더 음성 안내는 사용자가 실제
  계정으로 직접 확인해야 한다.

## 발견된 문제와 조치
- **원인**: 사이드바의 데스크톱 전용 컨트롤(문서함 접기 버튼, 폭 조절 핸들)이 모바일에서
  Tailwind `hidden` 클래스로 화면에서만 숨겨질 뿐 DOM에는 남아있어, `querySelectorAll`로만
  포커스 가능 요소를 계산하면 이 안 보이는 요소가 "첫/마지막"으로 잘못 잡혀 Tab 순환 경계가
  실제 화면과 어긋난다(실제 브라우저는 `display:none` 요소를 Tab 순서에서 건너뛰므로 계산과
  실제 동작이 어긋남).
- **조치**: `getFocusables()` 헬퍼에서 `classList.contains("hidden")`인 요소를 제외하고,
  폭 조절 핸들에는 모바일에서 `tabIndex={-1}`을 추가로 줬다.
- **재검증 결과**: 이 프로젝트의 유일한 문서(`문서A`)만 있는 최소 구성에서도 "첫 요소 ↔
  마지막 요소" 순환 테스트가 정확히 통과함을 확인했다(위 자동화 테스트 표 참고). 실제
  사이드바에 문서함 접기 버튼·검색 입력·여러 문서 링크가 모두 있는 실사용 화면에서
  Tab 순환 경계가 어디로 잡히는지는 실제 브라우저 수동 검증이 별도로 필요하다(위 "수동 검증"
  참고).
