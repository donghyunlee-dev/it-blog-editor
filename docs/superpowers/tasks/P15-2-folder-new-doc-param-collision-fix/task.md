# P15-2: 폴더 "+" 클릭 시 메인 화면으로 튕기는 버그 수정

## 배경
P15-1(폴더 행의 "+" → `/editor/new?folder={id}`)을 머지한 뒤 사용자 제보: "폴더에서 + 버튼을
눌렀을 때 메인화면으로 가는 버그가 있어."

원인 분석: `EditorSidebar.tsx`는 P7-7("편집 화면 브레드크럼에서 폴더를 누르면
`/editor?folder={id}`로 이동 → 사이드바가 그 폴더까지 펼치고 스크롤·강조")을 위해
`useSearchParams().get("folder")`를 읽는 `useEffect`를 갖고 있다. 이 컴포넌트는
`/editor/*` 전체 레이아웃에 걸쳐 항상 마운트돼 있고, 이 effect는 **pathname을 전혀
가리지 않은 채** "folder" 쿼리가 있으면 무조건 반응한다 — 대상 폴더를 펼치고 강조한 뒤
`router.replace("/editor")`로 쿼리를 지운다(원래 의도: `/editor?folder=` 도착 후 쿼리
정리).

P15-1이 같은 이름("folder")의 쿼리를 `/editor/new`에도 쓰기 시작하면서, 폴더 "+"를 눌러
`/editor/new?folder={id}`로 들어가면 이 P7-7 effect가 그대로 반응해 버렸다 — 폴더를
펼치고 강조하는 것까지는 부수효과일 뿐이지만, 마지막의 `router.replace("/editor")`가
방금 이동한 `/editor/new?folder={id}`를 곧바로 `/editor`(메인 화면)로 덮어써 사용자가
"메인 화면으로 튕겨나간다"고 느낀 것이다. 두 기능이 서로 무관하게 개발되면서 같은 쿼리
이름을 우연히 공유하게 된 것이 근본 원인이다.

## 수용 기준 (Acceptance Criteria)
- [x] 폴더 행의 "+"를 눌러 `/editor/new?folder={id}`로 이동하면, 메인 화면(`/editor`)으로
      되돌아가지 않고 그 화면에 그대로 머문다.
- [x] 기존 P7-7 기능(`/editor?folder={id}`로 들어왔을 때 사이드바가 그 폴더를 펼치고
      스크롤·강조 후 쿼리를 지움)은 그대로 동작한다 — 회귀 없음.
- [x] 근본 원인(쿼리 이름 우연한 재사용)이 앞으로도 반복되지 않도록, P7-7 effect는 정확히
      `/editor` 경로일 때만 그 쿼리를 읽도록 pathname으로 범위를 좁힌다(다른 화면의 쿼리
      이름 재사용과 원천적으로 격리).

## 결정이 필요한 사항
없음 — 사용자가 버그를 제보했고, 원인·수정 방향(effect를 pathname으로 좁힘) 모두 코드
분석만으로 확정할 수 있었다.

## 범위 밖
- P15-1의 `?folder=` 쿼리 이름 자체를 바꾸는 것 — pathname으로 격리하는 쪽이 더 근본적인
  해결책이라 이름 변경은 하지 않는다(다른 화면이 우연히 같은 이름을 또 써도 안전해진다).
