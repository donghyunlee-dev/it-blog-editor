## 실제 Confluence 인스턴스 end-to-end 검증
실제 계정(`donghyun.lee@s-food.com`)의 계정 폴더로 검증했다. 검증 전 `folderIndex`가
비어 있음을 먼저 확인한 뒤에만 진행했고, 끝나고 정확히 빈 배열로 복구했다.
1. 최상위 폴더 생성 → 성공, `id`가 UUID 형식.
2. 그 아래 하위 폴더 생성(깊이 2) → 성공.
3. 조회 → 방금 만든 두 폴더가 그대로 보임.
4. 존재하지 않는 `parentId`로 생성 시도 → `ValidationError`("상위 폴더를 찾을 수
   없습니다.")로 정상 거부.
5. 3~5단계까지 이어서 생성(정확히 5단계까지) → 모두 성공.
6. 5단계 아래 6단계 생성 시도 → `ValidationError`("폴더는 최대 5단계까지만 만들 수
   있습니다.")로 정상 거부.
7. 생성한 폴더 전부 삭제 → 정리 후 목록이 빈 배열로 원상 복구됨을 확인.

## 발견된 문제와 조치
- **원인**: 단위 테스트로 "정확히 5단계(경계값)는 허용해야 한다"를 작성하는 과정에서
  `computeDepth` 헬퍼가 실제로는 깊이를 1만큼 더 크게 계산하고 있음을 발견했다 — 최상위
  폴더(`parentId: null`) 아래 만드는 폴더도 깊이 2로 계산돼, 정확히 5단계째 생성이
  거부되는 버그였다.
- **조치**: `computeDepth`의 시작값과 순회 방식을 고쳐, `parentId`로 지정한 폴더 자신의
  깊이(최상위=1)를 정확히 반환하도록 했다.
- **재검증 결과**: 경계값 테스트를 포함한 10건 전부 통과, 위 실제 인스턴스 5단계
  검증도 성공.
