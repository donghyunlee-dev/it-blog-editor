# P18-1: 하이퍼링크 텍스트 클릭 시 열기

## 배경
- PRD(`docs/product/prd.md`) Phase 18 항목 — 사용자 지적: "링크를 넣어서 주소를
  입력했는데, 언더바와 색상은 변경되는데 글자를 눌러도 링크의 url이 열리거나
  이동이 되지 않아."
- 원인: `RichTextEditor.tsx`의 `StarterKit.configure({ link: { openOnClick: false } })`
  가 편집 중 실수로 링크를 눌러 페이지가 이동되는 사고를 막으려고 의도적으로
  클릭 열기를 꺼둔 것이었다. 그런데 대신 열 수 있는 다른 방법(버튼 등)이 전혀
  없어 "링크를 아예 열 수 없다"는 결과가 됐다 — `@tiptap/extension-link`의 기본
  클릭 핸들러는 `openOnClick`이 꺼져 있으면 아무 조건에서도 안 열어 준다
  (node_modules 확인).

## 수용 기준 (Acceptance Criteria)
- [ ] 링크가 적용된 텍스트를 일반 클릭하면(기존과 동일) 페이지가 이동되지 않고
      커서만 그 위치로 옮겨진다.
- [ ] 링크가 적용된 텍스트를 Ctrl(Windows)/Cmd(Mac)+클릭하면 새 탭에서 그 URL이
      열린다.
- [ ] 링크가 선택돼 있을 때 뜨는 버블 메뉴(기존 URL 입력 팝오버)에 "열기" 버튼이
      추가로 보이고, 누르면 새 탭에서 열린다.
- [ ] 아직 URL을 입력하지 않은(새로 링크를 만드는 중인) 팝오버에는 "열기" 버튼이
      보이지 않는다(열 대상이 없으므로).
- [ ] `javascript:` 등 안전하지 않은 스킴이 저장돼 있어도(예: 다른 경로로 유입된
      문서) Ctrl+클릭으로 열리지 않는다 — 기존 `isSafeLinkHref` 검사를 그대로
      재사용한다.

## 결정이 필요한 사항
사용자에게 직접 확인했다(AskUserQuestion, 2026-09-17) — "Ctrl/Cmd+클릭으로 열기 +
버블 메뉴에 '열기' 버튼" 안과 "일반 클릭만으로 바로 열기" 안 중 선택을 물었고,
사용자가 "둘다 다 가능했으면 좋겠어"라고 답해 **Ctrl/Cmd+클릭과 "열기" 버튼 둘 다
지원**하기로 확정했다. 일반 클릭은 편집 중 커서 배치용으로 그대로 남긴다(Notion/
Google Docs와 같은 관례).

## 범위 밖
- 링크 텍스트에 마우스를 올렸을 때 URL을 미리보기로 보여주는 툴팁 — 이번 요청에
  없음, 별도 요청 시 진행.
- 문서 링크 카드(📄 아이콘+제목)의 클릭 동작 — 이미 정상적으로 이동한다(별개 버그
  아님).
