# P17-24: 사이드바 들여쓰기·아이콘 정렬 + TOC 폭 흔들림 수정 — 구현 결과 보고서

## 구현 내용
1. **폴더 트리 들여쓰기 고정값 전환**: `INDENT_BASE_PX + depth * INDENT_STEP_PX`(깊이당
   +20px)로 늘어나던 왼쪽 들여쓰기를 깊이와 무관한 고정 `INDENT_BASE_PX`(8px)로
   바꿨다. `INDENT_STEP_PX` 상수와 그 사용처(문서 행, 폴더 행, 빈 폴더 안내) 3곳을
   모두 정리했다. 폴더/문서는 앞의 아이콘(화살표·폴더·게시 상태)만으로 이미
   구분되므로 깊이별 들여쓰기가 없어도 계층이 드러난다.
2. **폴더/문서 아이콘 왼쪽 위치 정렬**: 폴더 행의 안쪽 왼쪽 여백을 `pl-1`(4px)에서
   문서 행과 같은 `pl-2`(8px)로 맞췄다. 두 행 모두 "고정 들여쓰기(8px) + 안쪽 여백
   (8px) = 16px" 지점에서 아이콘이 시작해, 폴더의 접힘/펼침 화살표와 문서의 게시
   상태 아이콘이 같은 x좌표에서 나란히 보인다.
3. **TOC 레일 폭 고정**: `TableOfContents`가 우측 레일에 밀어 넣는 노드를 바꿨다 —
   이전엔 헤딩이 0개면 레일 슬롯 전체를 비워(`setTocRail(null)`) `EditorShell`의
   `{tocRail && ...}` 조건에 따라 240px 레일 컬럼 자체가 사라졌다. 이제는 헤딩 유무와
   무관하게 헤더 높이 맞춤용 spacer(`div`)는 항상 레일에 밀어 넣어 컬럼 폭 자체를
   고정해 두고, 실제 목차 콘텐츠(`nav aria-label="이 페이지"`)만 헤딩이 있을 때 그
   안에 조건부로 렌더링한다. 문서를 열 때 본문 DOM이 한 커밋 늦게 붙는 타이밍과
   헤딩 스캔이 겹쳐 레일이 뒤늦게 나타나며 본문 폭이 좌우로 흔들리던 문제가
   구조적으로 사라진다.

## 자체 검토 (Self-Review)
### 긍정 사항
- 세 요청 모두 사용자가 원인(패딩이 공간을 차지, 아이콘 위치 불일치, 레일 유무에
  따른 폭 변화)을 정확히 짚어줘서 추측 없이 원인 코드를 바로 찾아 고칠 수 있었다.
- TOC 폭 고정은 헤딩 존재 여부에 따른 접근성 계약(랜드마크 유무)을 건드리지 않고
  순수하게 레이아웃 컬럼의 폭만 고정하는 방식으로 구현해, 기존 접근성 테스트를
  그대로 통과시켰다.
- 폴더/문서 들여쓰기·안쪽 여백을 같은 상수·클래스로 통일해, 이후 값이 다시 바뀌어도
  두 곳이 따로 어긋날 가능성을 줄였다.

### 주의사항
- 문서 편집 화면(`/editor/[pageId]`)이 AX Auth(MS SSO) 로그인 뒤에 있어, 이 세션의
  브라우저 도구로는 실제 화면에서 좌우 흔들림이 사라졌는지 시각적으로 확인하지
  못했다 — 자동화 테스트(단위 테스트로 레일 구조·클래스 검증)와 코드 리뷰로만
  검증했다.
- 헤딩이 전혀 없는 문서에서도 TOC 레일 컬럼(빈 상태)이 계속 자리를 차지한다 —
  사용자가 명시적으로 요청한 트레이드오프("toc가 없더라도 우측 공간을 차지하고
  있으면...")이지만, 정말 헤딩이 없는 문서가 많다면 오른쪽에 항상 빈 여백이 남는다는
  점은 후속 피드백이 필요할 수 있다.
