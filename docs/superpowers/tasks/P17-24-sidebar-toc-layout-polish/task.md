# P17-24: 사이드바 들여쓰기·아이콘 정렬 + TOC 폭 흔들림 수정 — task

## 배경
같은 대화 안에서 사용자가 이어서 요청한, 서로 연관된 세 가지 사이드바/TOC 레이아웃
미세조정이다 — 각각 별도 요청이었지만 같은 세션에서 연속으로 진행돼 하나의 PR로
묶는다.

1. **폴더 트리 왼쪽 들여쓰기 제거**: "왼쪽 lnb 문서함에 정렬을 좀 수정해줘. 폴더와
   파일로 구성되어 있는데 하위 구조를 표현하다 보니 폴더 안에 파일 왼쪽에 패딩이
   적용되어 있어. 공간이 비어서 페이지 제목이 많이 보이지 않고 있어. 패딩을 없애고
   좌우 조정을 해서 왼쪽 라인에 너무 붙지 않게만 수정해줘. 앞에 아이콘이 있어서
   폴더와 파일이 구분이 잘 되기 때문에 패딩이 필요 없을 것 같아."
2. **폴더/문서 아이콘 왼쪽 위치 정렬**: "폴더의 접는 아이콘과 페이지의 게시 아이콘
   왼쪽 위치를 맞춰 줄 수 있어?" — 1번 변경 직후 발견된 후속 지적.
3. **TOC 폭 흔들림 수정**: "페이지를 호출하면서 화면에 렌딩할 때 좌,우로 흔들리는
   모습이 보여. toc가 있을 때와 없을 때, 컨텐츠 사이즈가 맞춰지는 과정에서 그렇게
   보이는 거 같애. 이 문제를 해결할 수 있을까? toc가 없더라도 우측 공간을 차지하고
   있으면 위치 조정하는 느낌의 화면이 안보일까?"

## 수용 기준 (Acceptance Criteria)
- [x] 폴더 트리 왼쪽 들여쓰기가 깊이(depth)와 무관하게 고정값을 쓴다 — 깊이가 깊어질
      수록 늘어나던 `INDENT_STEP_PX` 배수 들여쓰기를 없앤다.
- [x] 들여쓰기가 완전히 0은 아니다 — 행 배경이 사이드바 왼쪽 라인에 완전히 붙지 않을
      최소한의 여백은 남는다.
- [x] 폴더 행의 접힘/펼침 화살표(`ChevronIcon`)와 문서 행의 게시 상태 아이콘
      (`StatusIcon`)이 항상 같은 왼쪽 x좌표에서 시작한다(깊이가 같을 때).
- [x] 문서를 열 때(또는 헤딩 스캔 결과가 바뀔 때) 우측 TOC 레일의 유무에 따라 본문
      영역의 가로 폭이 변하지 않는다 — 레일 컬럼(240px)은 헤딩이 있든 없든 항상
      같은 폭으로 자리를 차지하고, 안쪽 목차 콘텐츠만 있으면 보이고 없으면 빈
      상태로 둔다.
- [x] 헤딩이 하나도 없는 문서에서 "이 페이지" 목차 랜드마크(`role="navigation"`,
      `aria-label="이 페이지"`)는 여전히 렌더링되지 않는다(접근성 계약 유지).
- [x] `docs/product/design.md`의 관련 스펙(사이드바 섹션, TOC 섹션)을 새 동작으로
      갱신한다.

## 결정이 필요한 사항
없음 — 세 요청 모두 사용자가 원인과 원하는 방향("패딩 없애고 좌우 조정", "아이콘
위치 맞추기", "toc 없어도 우측 공간을 차지")을 구체적으로 제시했고, 구체적인 px
값(고정 들여쓰기 8px, 폴더 행 `pl-1`→`pl-2`)은 기존 `INDENT_BASE_PX`/문서 행
`pl-2`를 그대로 재사용하는 구현 디테일 판단이다.

## 범위 밖
- 폴더 트리 깊이 자체의 최대 제한(Phase 7에서 이미 5단계로 결정됨) — 이번엔 들여쓰기
  "표현 방식"만 다룬다.
- TOC가 완전히 없는 라우트(문서 목록 등)에 레일 공간을 새로 만드는 것 — `TableOfContents`가
  아예 마운트되지 않는 라우트는 이번 범위에 포함하지 않는다(문서 편집 화면 안에서의
  폭 안정성만 다룬다).
