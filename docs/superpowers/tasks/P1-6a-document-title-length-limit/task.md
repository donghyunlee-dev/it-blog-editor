# P1-6a: 문서 제목 길이 상한을 서버에서 검증한다

## 배경
2026-08-27 [프로덕션 준비도 감사](https://claude.ai/code/artifact/87302c07-68d6-42ed-8712-9345547cb659)에서 지적된 항목. `createDocument`/`updateDocument`(`documents.ts`)는 제목이 비어있는지만 검사(`!input.title.trim()`)할 뿐 길이 상한이 없다.

P0-7 이전이었다면 Confluence page title 자체의 길이 제약(관례적으로 255자 안팎)을 걱정해야 했겠지만, 지금은 Confluence page의 실제 title이 `randomUUID()`(고정 36자)이고 사용자가 입력한 제목은 `sourceDocument` content property(문자열 크기 제약이 훨씬 넉넉함)에 저장된다(P0-7). 즉 이 항목은 더 이상 "Confluence의 하드 리밋을 피하기 위한 방어"가 아니라, 순수하게 "화면 레이아웃·데이터 남용 방지를 위한 상식적인 상한"이라는 성격의 항목이 됐다.

## 수용 기준 (Acceptance Criteria)
- [ ] `createDocument`/`updateDocument`가 제목 길이가 상한(200자)을 초과하면 `ValidationError`(400)를 던진다.
- [ ] 상한 이하(경계값 200자 정확히 포함)는 기존과 동일하게 정상 처리된다.
- [ ] 기존 "제목 또는 본문 누락" 검증과 동일한 에러 타입·응답 코드(400)를 쓴다 — 새 에러 코드를 만들지 않는다.

## 결정이 필요한 사항
없음 — P0-7 이후로는 이 상한이 Confluence의 하드 리밋을 피하기 위한 값이 아니라 순수 UX 가드레일이 됐다(제목 입력창은 자동으로 줄바꿈되는 `<textarea>`라 아주 긴 제목도 기술적으로는 렌더링되지만, 문서함 목록·검색 결과에서 한 줄 요약으로 쓰기엔 부적절해진다). P0-4b(이미지 개수 30장 상한)와 같은 근거로 GitHub Issue 없이 보수적이지 않은 넉넉한 기본값(200자 — 일반적인 문서 제목보다 훨씬 길다)을 직접 정했다.

## 범위 밖
- 클라이언트 쪽 실시간 글자 수 안내(예: "180/200") — 이번엔 서버 검증만 다룬다. 필요해지면 후속으로 추가한다.
- 태그·slug 길이 검증(P1-6b/P1-6c) — 별도 PRD 항목.
