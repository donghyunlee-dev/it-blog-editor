# P8-1: 헤더 레이아웃 정비 — 검색 트리거 버튼 추가

## 배경
사용자가 [support.claude.com/ko](https://support.claude.com/ko) 문서 뷰어를 지목해 이 프로젝트
에디터 UI와 벤치마킹해 달라고 요청했다(`docs/product/design.md` "벤치마킹 —
support.claude.com/ko 문서 뷰어 레이아웃 실측 비교" 절, "3. 헤더" 표). 실측 결과 레퍼런스
헤더에는 140×30px 크기의 검색 트리거 버튼이 있는데, 이 프로젝트는 `Ctrl+K` 단축키만 있고
헤더 어디에도 그 진입점을 시각적으로 알려주는 버튼이 없었다.

관련 PRD 항목: `docs/product/prd.md`의 **P8-1**(Phase 8, 에디터 UI 레이아웃 벤치마킹).

## 수용 기준 (Acceptance Criteria)
- [x] 헤더(사이드바 상단 브랜딩 행, `EditorSidebar.tsx`)에 검색 트리거 버튼을 추가하고, 클릭
      시 기존 `GlobalSearchModal`(Ctrl+K)을 연다 — 새로운 검색 로직·API를 만들지 않는다.
- [x] 모바일 오프캔버스 드로어가 닫혀 있을 때 보이는 상단 바(`EditorShell.tsx`)에도 같은
      트리거를 추가해, 드로어를 열지 않고도 검색에 접근할 수 있게 한다.
- [x] 헤더 높이(`h-14`, 56px)는 바꾸지 않는다 — 변경 시 회귀로 간주(design.md "헤더(공통)"
      절의 기존 고정 결정).
- [x] 기존 `Ctrl+K` 단축키 동작에 회귀가 없다(`GlobalSearchModal.test.tsx` 기존 테스트 전부
      통과 + 새 동작 추가 검증).
- [x] 자동화 테스트로 클릭 시 모달이 열림을 확인한다(브라우저 스크린샷은 AX Auth 로그인
      제약으로 이 세션에서 불가능 — P7-7 등 기존 항목과 같은 한계, `test.md` 참고).

## 결정이 필요한 사항
없음 — 버튼 크기(140×30px)·radius·배경색 등은 design.md에 이미 실측값이 있고, 이 프로젝트는
사이드바 폭이 가변(220~440px)이라 고정 픽셀을 그대로 옮기지 않고 내용물 기준으로 자연스럽게
줄어들게 하는 것으로 직접 정했다(사소한 구현 디테일 판단, P1-6a와 같은 근거 — GitHub Issue
불필요).

## 범위 밖
- 헤더 배경색을 레퍼런스의 톤온톤(테두리 없음) 스타일로 바꾸는 것 — design.md는 "참고만 하고
  채택 여부는 P8-1에서 판단"이라고 했으나, 대비 저하 우려로 기존 `border-b border-border`를
  유지하기로 했다(변경하지 않음).
- 로고~우측 액션 그룹 사이 "간격 비율"을 레퍼런스와 픽셀 단위로 맞추는 것 — 기존 `gap-2` 레이아웃에
  검색 버튼을 자연스럽게 끼워 넣는 선에서 처리했고, 추가 미세조정은 이번 항목의 필수 수용
  기준이 아니다.
- 새 검색 기능·API 변경(P8-1은 기존 `GlobalSearchModal`을 여는 트리거만 추가한다).
