# P2-5: 표 안 텍스트 서식(색상·폰트) 격차 조사 — 구현 결과 보고서

## 구현 내용
- 코드 조사: `RichTextEditor.tsx`의 `EditorBubbleMenu`는 `shouldShow`를 오버라이드하지 않는다. `@tiptap/extension-bubble-menu` 3.30.2의 기본 `shouldShow`(`node_modules/@tiptap/extension-bubble-menu/dist/index.cjs`)를 직접 읽어, 표 셀 여부를 구분하는 로직이 전혀 없음을 확인했다(포커스 여부, 선택이 비어있지 않은지, 빈 텍스트 블록이 아닌지, `editor.isEditable`만 검사). 표 셀 안 텍스트를 선택하는 것도 여러 셀에 걸치지 않는 한 일반 `TextSelection`이라 이 조건을 그대로 통과한다.
- 실측: `selectText` 헬퍼(P1-9e가 확립한 방식)로 표 셀 안 텍스트를 실제로 선택해 렌더링한 결과, 서식 버블 메뉴(굵게/글자 색상 등)가 정상적으로 뜸을 확인했다 — 사용자가 보고한 문제 중 "색상/서식 버튼 자체가 안 뜬다"는 부분은 재현되지 않았다.
- 조사: `package.json`을 확인한 결과 `FontFamily`/`FontSize` 관련 `@tiptap` 확장이 설치돼 있지 않다 — 글꼴 종류·글자 크기를 바꾸는 기능은 표 셀 안팎을 가리지 않고 문서 전체 어디에도 없다.
- 결정 필요 사항 등록: 폰트(글꼴·크기) 서식 추가 여부·방식은 문서 전체에 걸친 새 기능이고 값이 정해지지 않아 [Issue #69](https://github.com/sfood-pioneer-1st/sfood-it-editor/issues/69)로 등록했다. 이 항목에서는 구현하지 않는다.
- 확인된 동작(색상/하이라이트가 표 셀 안에서도 정상 동작함)을 회귀 테스트로 고정했다.

## 자체 검토 (Self-Review)
### 긍정 사항
- "버그가 있을 것"이라는 사용자 보고를 그대로 믿고 새 UI를 만드는 대신, 먼저 실제 코드·자동화 테스트로 재현을 시도해 "실제로는 이미 동작한다"는 사실을 확인한 뒤 회귀 테스트로 고정했다 — 불필요한 중복 기능을 만들지 않았다.
- 진짜 격차(폰트 종류·크기 미구현)는 값이 정해지지 않은 문서 전체 기능이라는 것을 명확히 하고, 표 항목(P2-4)과 섞지 않은 채 별도 이슈로 분리했다.

### 주의사항
- 사용자가 실제로 무엇을 시도했다가 "안 된다"고 느꼈는지는 이 세션에서 직접 관찰하지 못했다 — 재현 시도 결과 코드상으로는 정상 동작해, 실제 원인이 "폰트(글꼴·크기)가 없어서"였을 가능성이 높다고 추정한다(사용자가 "색상이나 폰트"를 한 문장으로 보고했고, 그중 폰트 쪽만 실제로 없기 때문). 다만 이는 추정이며, 표 셀 안에서만 재현되는 다른 조건(예: 특정 브라우저·특정 셀 병합 상태)이 있었을 가능성은 완전히 배제하지 못했다.

### 우려사항
- 폰트 서식 자체는 Issue #69 답변 전까지 미구현 상태로 남는다 — 사용자가 실제로 원했던 것이 색상 버그 수정이 아니라 폰트 기능 추가였다면, 이번 항목만으로는 체감되는 변화가 없을 수 있다.
