# P1-10: 삭제된 문서 복구 시 Space 최상위로 이동하던 사례 후속 조치

## 배경
- 2026-08-28, P0-5b/P0-7 작업 중 실제 계정 폴더를 조회하다가 우연히 발견된 사례. `docs/product/prd.md`의 Phase 4 P1 체크리스트 항목이다.
- 문서(pageId `212959235`, "CODEX 명령어 요약1")가 계정 폴더가 아니라 Space 홈페이지 바로 아래(최상위)에 초안과 동일한 제한(작성자 1인 전용)으로 남아있는 상태로 발견됐다 — 앱 자신이 쓰는 property(`authorMeta`/`sourceDocument`/`publishMetadata`)를 모두 갖고 있어 이 앱이 만든 진짜 문서임은 확실하지만, `listDocuments()`가 계정 폴더 하위만 조회하므로 앱 화면에서는 더 이상 보이지 않는 사실상의 데이터 유실 상태다.
- P0-8(2026-08-28)에서 "초안"/"게시" 서브폴더 구분 자체를 없애고 복구를 계정 폴더 하나로만 이동시키도록 리팩터했다 — 이 때문에 재현 경로가 사라진 것으로 "보인다"는 정도로만 PRD에 남아 있었고, 원래 버그의 정확한 코드상 원인은 소급 확인되지 않은 채였다.

## 수용 기준 (Acceptance Criteria)
- [x] 현재(P0-8 이후) `restoreDocument`(`src/lib/editor/deleted-documents.ts`) 구현이 구조적으로 Space 홈페이지 등 계정 폴더 이외의 위치로 이동시킬 수 있는 경로가 있는지 코드로 확인한다.
- [x] P0-8 이전 커밋(`469c3bb^1`)의 `restoreDocument`/`folder.ts` 구현도 함께 확인해, 원래 버그(계정 폴더 대신 Space 홈페이지로 이동)를 설명할 수 있는 구체적인 코드 경로가 있는지 조사한다.
- [x] 조사 결과를 있는 그대로 문서화한다 — 확인됐으면 확인된 대로, 특정하지 못했으면 추측으로 메우지 않고 "특정하지 못했다"고 정직하게 남긴다.
- [x] 현재 `restoreDocument`가 항상 계정 폴더로만 이동함을 검증하는 회귀 테스트가 이미 있는지 확인하고, 없으면 추가한다.
- [ ] pageId `212959235`(Space 최상위에 남아있는 실제 문서) 자체를 계정 폴더로 옮기는 실제 정리 작업 — 실제 Confluence 인스턴스에 쓰기 작업이 필요해 사용자 승인 없이는 진행하지 않는다. **(사용자 확인 대기 중)**
