# P12-1: 사이드바 태그 필터(ChipGroup) 제거 — 태그를 검색 전용으로 재정의

## 배경
사용자와 태그 기능 전반을 다시 검토하는 대화(2026-09-14)에서, 태그가 실제로 감당할 수 있는
역할은 "폴더에 준하는 1급 분류 축"이 아니라 "검색 시 매칭되는 가벼운 키워드"라는 결론에
도달했다 — 태그 이름 변경/병합 기능이 없고, 자동완성이 본인 문서로만 한정되며, 필터도
다중 선택(AND/OR)이 아닌 단일 선택 토글뿐이라 정교한 분류 체계로 쓰기엔 관리 기능이 부실하기
때문이다. 반면 사이드바 검색(`EditorSidebar.tsx`)은 이미 제목+태그를 함께 매칭하고 있어,
"태그로 찾기"라는 목적은 검색만으로 이미 달성된다.

확인 결과 Ctrl+K 전역 검색(`searchDocuments`, `src/lib/editor/documents.ts:274`)도 이미
제목·태그·본문을 모두 매칭하고 있었다(`GlobalSearchModal.tsx`의 `titleOnly`는 이미 받아온
결과를 제목 기준으로 다시 좁히는 클라이언트 사이드 토글일 뿐, 기본 검색 범위가 아니다) —
따라서 "Ctrl+K에 태그 매칭을 추가"하는 작업은 불필요하며 이번 범위에 포함하지 않는다.

관리 기능 없이 상시 노출된 필터 UI(`ChipGroup`)는 태그가 늘어날수록(이름변경 불가로 오타가
누적되는 채로) 사이드바에 계속 나열되는 문제가 있고, 사이드바 검색과 기능이 중복된다. 이번
작업은 그 중복된 노출 표면(필터 칩)만 제거하고, 태그 데이터·입력·검색 매칭 기능 자체는 그대로
둔다.

## 수용 기준 (Acceptance Criteria)
- [ ] 사이드바 상단의 태그 필터 칩(`ChipGroup`, `role="tab"`)이 더 이상 렌더링되지 않는다.
- [ ] 태그 데이터 자체(등록·조회·사이드바 검색·Ctrl+K 검색의 태그 매칭)는 전혀 변경하지 않는다
      — 이번 작업은 "필터 칩 노출"만 제거한다.
- [ ] 필터 칩 제거에 따라 더 이상 쓰이지 않는 `activeTag` 상태·`allTags` 계산·`ChipGroup` import를
      정리한다(죽은 코드를 남기지 않는다).
- [ ] 기존 회귀 테스트가 모두 통과하고, 제거된 필터 칩에 의존하던 테스트(태그 클릭 필터링, 필터
      토글, 필터+검색어 AND 조합)는 제거하거나 갱신한다.
- [ ] `docs/product/prd.md`의 "내 문서함 조회"·"문서 태그 지정" 기능 설명과 화면 정의 표에서
      "태그 필터"를 더 이상 사이드바 기능으로 언급하지 않도록 갱신한다.

## 결정이 필요한 사항
없음 — 사용자가 대화 중 태그를 "검색 전용"으로 좁히는 방향에 직접 동의했다(값에 정답이 없는
UI 트레이드오프를 사용자가 이미 선택).

## 범위 밖
- 태그 입력 UI(`TagInput.tsx`)의 위치·레이아웃 변경 — 별도 작업(P12-2)에서 다룬다.
- Ctrl+K 검색에 태그 매칭 추가 — 이미 구현되어 있어 불필요(위 "배경" 참고).
- 태그 이름 변경/병합 등 관리 기능 신설 — 이번 방향(검색 전용, 가벼운 키워드) 하에서는 필요성이
  낮다고 판단해 범위에서 제외한다.
