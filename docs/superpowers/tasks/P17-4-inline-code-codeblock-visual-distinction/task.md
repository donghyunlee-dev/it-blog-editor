# P17-4: 인라인 코드 vs 코드 블록 시각적 구분 강화

## 배경
사용자 지적: "인라인 코드, 코드 블록 차이점 모르겠음."

조사 결과: `globals.css`의 `.prose` 규칙에서 `--tw-prose-code`(인라인 코드 글자색)와
`--tw-prose-pre-code`(코드 블록 글자색) 둘 다 `--color-foreground`(본문 글자색과 동일)로
지정돼 있었다. 코드 블록은 `--tw-prose-pre-bg`로 전체 폭 배경 박스가 있어 그나마
구분됐지만, 인라인 코드는 모노스페이스 폰트 외에는 본문과 구별할 신호가 없었다(배경도
없고 글자색도 같음) — `@tailwindcss/typography` 기본값이 넣는 백틱(`) 정도가 유일한
단서였다.

## 수용 기준 (Acceptance Criteria)
- [x] 인라인 코드(문장 중간의 `code`)가 배경 칩(배경+테두리+둥근 모서리)으로 표시돼
      본문 글자와 한눈에 구분된다.
- [x] 코드 블록(전체 폭 박스, 문법 강조)과 인라인 코드(짧은 칩)가 형태 자체로 서로
      다르게 보여, 사용자가 "이게 인라인이고 이게 블록이다"를 직관적으로 알 수 있다.
- [x] 라이트/다크 테마 모두에서 정상적으로 보인다(하드코딩 hex 색상 없이 기존
      CSS 변수 토큰만 사용).
- [x] 코드 블록 쪽 렌더링(문법 강조, 배경)은 기존과 동일하게 유지된다(회귀 없음).
- [x] 새 아이콘 라이브러리나 새 컴포넌트를 추가하지 않는다 — 순수 CSS 조정으로 해결한다.

## 결정이 필요한 사항
없음 — GitHub/Notion류 에디터에서 흔히 쓰는 "인라인 코드 배경 칩" 표현을 그대로
적용하면 되고, 기존 CSS 변수 토큰(`--color-surface-subtle`, `--color-border`)을
그대로 재사용하면 되므로 별도로 정할 값이 없다.

## 범위 밖
- 슬래시 메뉴의 "코드블록"/"인라인 코드" 항목에 아이콘을 붙이는 것(P17-6에서 별도로
  다룬다 — 이번 범위는 렌더링된 코드 자체의 시각적 구분만).
- 코드 블록 편집 편의 기능(Tab 들여쓰기·언어 선택·복사 버튼, P17-5a/b/c에서 별도 진행).
