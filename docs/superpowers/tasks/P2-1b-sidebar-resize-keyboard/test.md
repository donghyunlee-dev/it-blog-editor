## 수동 검증 (필요 시)
- `preview_start`로 dev 서버(`editor-dev`, localhost:3100)를 띄워 `/editor`로 접근을 시도했으나
  MS 계정 로그인(AX Auth) 화면으로 이어져, 이 세션에서는 그 이상 진행할 수 없었다(P1-7
  시리즈·P2-1a와 동일한 환경 제약 — 로그인 자격 증명에 접근할 수 없음). 실제 브라우저에서
  Tab으로 핸들에 포커스를 옮기고 방향키/Home/End를 눌러 사이드바가 실제로 넓어지고 좁아지는
  것을 육안으로 확인하는 것과 실제 스크린 리더 음성 안내 확인은 사용자가 실제 계정으로 직접
  확인해야 한다.

## 발견된 문제와 조치
- **원인(2026-09-07, 머지 후 사용자의 실제 Edge 브라우저 QA 중 발견)**: 핸들이 키보드 포커스를
  받으면 브랜드색 포커스 테두리가 생기는데, 이 테두리가 `DocumentEditor.tsx`의 `sticky` 상단
  헤더(h-14, `z-10`)와 정확히 같은 `z-10`을 쓰고 있었다. 핸들과 헤더가 같은 스태킹 컨텍스트에서
  동률이면 DOM 순서가 늦은 쪽(헤더 — `children`으로 핸들보다 뒤에 렌더링됨)이 그 높이 구간에서
  위에 그려져, 포커스 테두리가 헤더 높이(상단 56px)만큼 가려 보였다. 실사용 보고: "라인이
  2개 생기고, 사이드바 자체의 `border-r`(왼쪽)은 헤더까지 끊김 없이 이어지는데 포커스 테두리
  (오른쪽)는 헤더 구간만 빠져 보인다."
- **조치**: 핸들의 `z-10`을 `z-20`으로 올려 항상 헤더 위에 그려지게 했다. 핸들이 보이는
  데스크톱(`md:block`)에서는 모바일 전용 오버레이(`z-30`)·접힘 펼치기 버튼(`z-40`)이 함께
  나타나지 않아 겹칠 일이 없음을 확인했다.
- **재검증 결과**: `npx vitest run`(전체 스위트, 54 파일/499건)·`npm run lint`·`npx tsc --noEmit`·
  `npm run build` 모두 통과. 시각적 재확인은 사용자가 Edge에서 직접 확인했다(별도 PR로 반영).
