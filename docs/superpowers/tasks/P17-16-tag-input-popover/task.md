# P17-16: 태그 UI를 칩+팝오버 방식으로 전환 — task

## 배경
- 외부(GPT) UI 개선 제안 리뷰 중 채택한 항목(6번). 태그 위치(문서 하단, P12-2 결정)는
  적절하다고 판단해 그대로 두고, 인터랙션만 개선한다.
- 문제: 현재 `TagInput`은 상시 열린 테두리+배경 입력 행(`border border-border
  bg-surface`)이라 "문서 마지막에 거대한 Form 필드가 하나 붙어 있다"는 인상을 준다.
- 실제 코드 확인: `@sfood/ui`가 이미 `Popover`(트리거 클릭으로 열고, 바깥 클릭/Escape로
  닫는 것까지 구현된 컴포넌트, `node_modules/@sfood/ui/dist/index.d.ts` 확인)를 제공해
  새 라이브러리 없이 그대로 쓸 수 있다.
- 관련 코드: `src/components/editor/TagInput.tsx`, 사용부 `DocumentEditor.tsx`(위치는
  변경 없음).

## 수용 기준 (Acceptance Criteria)
- [x] 평소(팝오버가 닫혀 있을 때)에는 칩(선택된 태그) + "태그 추가" 트리거 버튼만
      보이고, 상시 입력 박스(테두리+배경)는 없다.
- [x] "태그 추가"를 누르면 `@sfood/ui`의 `Popover` 안에 검색/입력 필드가 뜬다.
- [x] 팝오버를 열면(아직 아무 것도 입력하지 않아도) 이미 선택되지 않은 추천 태그
      전체를 곧바로 보여준다 — "검색"뿐 아니라 "둘러보기"도 가능해야 한다는
      제안 취지를 반영한다.
- [x] 입력한 글자로 추천 태그 목록이 좁혀진다(기존 동작 유지).
- [x] Enter/쉼표로 직접 입력한 태그를 추가할 수 있다(기존 동작 유지).
- [x] 추천 태그를 클릭하면 칩으로 추가되고, 팝오버는 닫히지 않는다(연속으로 여러
      태그를 추가할 수 있어야 한다).
- [x] 칩의 삭제 버튼은 팝오버를 열지 않아도 항상 동작한다(기존 동작 유지).
- [x] 한글 등 조합형 입력(IME) 중 Enter는 태그를 추가하지 않는다(기존 동작 유지).
- [x] 이미 선택된 태그는 중복 추가되지 않는다(기존 동작 유지).

## 결정이 필요한 사항
없음 — `@sfood/ui`의 `Popover`를 그대로 재사용하는 인터랙션 개선이라 새로 정할 값이
없다.

## 범위 밖
- 태그의 화면 내 위치(상단 vs 하단) 변경 — P12-2에서 이미 하단으로 확정했고, 이번
  외부 리뷰도 "위치는 그대로가 맞다"고 결론 내려 다루지 않는다.
- 태그 자동완성 후보를 만드는 로직(`listTagSuggestions` 등) 변경 — UI 인터랙션만
  바꾼다.
