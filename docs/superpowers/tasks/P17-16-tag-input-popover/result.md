# P17-16: 태그 UI를 칩+팝오버 방식으로 전환 — 구현 결과 보고서

## 구현 내용
- `TagInput.tsx`의 상시 노출 테두리+배경 입력 행을 제거하고, 칩 뒤에 `@sfood/ui`의
  `Popover`(trigger: "태그 추가" 버튼)를 추가했다. 실제 입력·검색·추천 목록은 이
  팝오버 안으로 옮겼다.
- 팝오버가 열림/닫힘 상태를 직접 관리해줘서 기존 `suggestionsOpen`/`onFocus`/`onBlur`
  로직을 제거할 수 있었다. `candidates` 필터에서 `draft.length > 0` 조건도 없애,
  팝오버를 막 열었을 때(아직 아무 것도 안 쳤을 때)도 추천 태그 전체를 보여준다.
- 태그 커밋(`commitTag`)·IME 처리(`handleKeyDown`)·삭제(`removeTag`) 로직은 그대로
  재사용했다 — 바뀐 것은 "언제 입력창이 보이는가"뿐이다.

## 자체 검토 (Self-Review)
### 긍정 사항
- 새 팝오버 로직을 직접 구현하지 않고 `@sfood/ui`가 이미 제공하는 `Popover`를
  그대로 재사용했다 — 열림 상태 관리·바깥 클릭/Escape 닫힘을 처음부터 만들 필요가
  없었고, 오히려 기존의 `onFocus`/`onBlur`+setTimeout 기반 임시방편 코드를 걷어냈다.
- 팝오버를 열면 입력 없이도 추천 태그 전체를 보여주도록 바꿔, "검색만 되고 둘러보기는
  안 된다"는 아쉬움까지 함께 해소했다(GPT 제안의 취지).
- 임시 디버그 페이지에서 실제 클릭 흐름(트리거 → 전체 추천 노출 → 검색어로 좁힘 →
  클릭 시 칩 추가 + 팝오버 유지)을 직접 확인했다.

### 주의사항
- 팝오버 안 `draft`(입력 중이던 텍스트)는 팝오버가 Escape/바깥 클릭으로 그냥 닫힐
  때 초기화되지 않는다 — `Popover`가 열림 상태를 완전히 자체 관리해 "닫힐 때" 콜백을
  받을 방법이 없다. 다시 열면 이전에 입력하다 만 텍스트가 남아있을 수 있다(태그를
  커밋하면 정상적으로 비워진다). 기능적 결함은 아니라 이번 범위에서 손보지 않았다.

### 우려사항
- 없음 — 태그 커밋/삭제/IME 처리 로직 자체는 손대지 않았고, 관련 테스트(TagInput
  9개 + DocumentEditor 43개) 모두 통과해 회귀 위험이 낮다.
