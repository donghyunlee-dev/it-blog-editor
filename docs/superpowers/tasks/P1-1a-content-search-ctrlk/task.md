# P1-1a 후속: 문서 본문 검색(Ctrl+K 전체 검색)을 추가한다

## 배경
- P1-1a(사이드바 검색을 태그까지 확장)는 이미 완료됐지만, 본문 검색은 `listDocuments()`의 N+1 조회 비용을 배로 늘리는 아키텍처 트레이드오프라 별도 결정이 필요해 [Issue #7](https://github.com/sfood-pioneer-1st/sfood-it-editor/issues/7)로 분리됐다.
- 2026-08-30 "본문 검색은 Notion과 같이 Ctrl+K 기능으로, 팝업 창을 띄워 전체 검색해서 찾는 방식으로 개별 진행. 사이드 패널의 검색은 페이지 타이틀로만 검색 유지"로 결정됐다 — 원래 이슈가 제시한 3가지 후보 중 "2. 검색 시점에만 서버에 물어보기"에 해당한다.

## 수용 기준 (Acceptance Criteria)
- [x] 계정 폴더의 문서를 제목·태그·본문(TipTap JSON에서 추출한 순수 텍스트) 기준으로 검색하는 서버 함수를 추가한다.
- [x] 이 검색은 사용자가 명시적으로 호출할 때만 실행되는 별도 API(`GET /api/editor/documents/search?q=...`)로 제공한다 — `listDocuments()`(사이드바가 매 렌더링마다 쓰는 함수) 자체는 건드리지 않는다.
- [x] `Ctrl+K`(Mac: `Cmd+K`)로 `/editor/*` 어느 화면에서든 열리는 전역 검색 팝업을 추가한다.
- [x] 팝업에서 검색어를 입력하면(디바운스 적용) 결과를 보여주고, 결과를 클릭하거나 방향키+Enter로 선택하면 그 문서 편집 화면으로 이동한다.
- [x] 사이드바의 기존 검색(제목·태그)은 이번 작업으로 바꾸지 않는다 — 결정에 명시된 대로 그대로 둔다.
- [x] 새 검색 API·전역 검색 팝업 모두 자동화 테스트로 검증한다.

## 결정이 필요한 사항
없음 — Issue #7로 이미 확정됐다.

## 범위 밖
- 검색 결과에 일치 부분을 강조 표시(하이라이트)하거나 본문 스니펫을 보여주는 것은 이번 범위에 포함하지 않는다 — 최소 기능(제목/태그/게시 상태만 보여주는 목록)으로 시작한다.
- 이 새 검색 API에 레이트리밋(P1-5)을 적용하지 않는다 — P1-5는 "문서 생성·이미지 업로드·게시" 세 곳으로 명시적으로 범위가 정해져 있었다. 대신 클라이언트에서 300ms 디바운스로 호출 빈도를 억제한다.
- 사이드바 검색창에서 이 전역 검색 팝업을 직접 여는 버튼은 두지 않는다(모달이 자체적으로 열림 상태를 관리해 외부에서 제어할 접점이 없다) — 힌트 문구로만 존재를 알린다.
