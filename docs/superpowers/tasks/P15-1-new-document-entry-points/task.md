# P15-1: 새 문서 생성 진입점 개편 — 폴더별 "+"와 "미분류" 대응

## 배경
P7-4/P7-5(폴더 트리)가 들어오면서 사이드바 상단의 큰 "새 문서" 버튼과 폴더 행의 "+"
버튼(하위 폴더 추가)이 같은 모양의 아이콘으로 겹쳐 보이는데 의미가 다르다는 지적이다.
사용자 진단: "폴더에서 새문서를 시작할 방법이 없어. 폴더 버튼에 + 버튼이 하위 폴더로
되어 있기 때문에 폴더 내 문서 기능이 겹치고 있어."

검토 결과, 백엔드는 이미 이 시나리오를 지원한다 — `POST /api/editor/documents`가
`folderId`를 받아 생성 시점에 바로 그 폴더로 배정한다(`src/app/api/editor/documents/route.ts`
38-50행, P7-3에서 이미 만들어졌지만 지금까지 프론트에서 쓴 적이 없다). 즉 이번 작업은
새 API가 필요 없는, 순수 프론트 배선 + 사이드바 UI 재구성이다.

사용자가 제시한 최종 구조(대화 중 수정됨 — 처음엔 사이드바의 "새 문서" 버튼을 완전히
없애고 `/editor` 홈 화면의 CTA만 남기려 했으나, 그러면 **폴더가 하나도 없는 계정**(대부분의
현재 사용자)은 사이드바 안에서 문서를 만들 방법이 없어져 홈 화면으로 나가야 하는 퇴보가
생긴다는 지적으로 아래처럼 정정됨):
1. **"미분류" 새 문서 — 사이드바 안, 항상 보임** — 독립 버튼을 없애는 대신 문서/폴더
   목록의 **맨 아래**(폴더 트리 + 미분류 문서 리스트 다음)로 옮긴다. 미분류는 항상 목록의
   마지막에 위치하므로, 이 위치 자체가 "이 버튼은 미분류에 문서를 만든다"는 것을 자연스럽게
   전달한다. 폴더가 하나도 없는 계정은 기존과 동작이 완전히 같다(그냥 새 문서, 위치만
   맨 위 → 맨 아래로 이동).
2. **"메인"에서 새 문서 시작** — 이미 존재하는 `/editor`(문서를 안 연 상태의 홈 화면)의
   "새 문서 작성" 버튼(`src/app/editor/page.tsx`)도 그대로 둔다 — 같은 동작(미분류 생성)의
   또 다른 진입점이라 두 개가 공존해도 모순이 아니다.
3. **폴더(개별)에서 "+"로 생성** — 폴더 행의 "+"가 지금은 "하위 폴더 추가"인데, 이를
   "이 폴더에 새 문서"로 바꾼다. 대신 "하위 폴더 추가"는 폴더 행에 새로 추가하는 "..."
   컨텍스트 메뉴(이름 변경·삭제와 함께)로 옮긴다. "미분류"는 위 1번이 이미 그 역할을
   하므로 별도의 폴더-스타일 미니 헤더로 승격하지 않는다(불필요한 중복 UI를 피한다).

폴더 "..." 메뉴는 문서 행의 옵션(⋯) 메뉴(P14-1~P14-3)와 정확히 같은 문제(사이드바
`<nav overflow-y-auto>` 안에서 팝업이 잘리는 문제, P14-3에서 이미 겪음)를 그대로 안고
시작하므로, 처음부터 그 해결책(팝업을 `<nav>` 바깥에 `position: fixed`로 그리는 방식)을
재사용한다 — 문서/폴더 두 메뉴가 거의 동일한 open/닫기 로직을 가지므로 공통 상태
(`openMenu`)로 합쳐 코드 중복을 줄인다.

## 수용 기준 (Acceptance Criteria)
- [x] 사이드바 상단의 "새 문서" 버튼이 문서/폴더 목록(`<nav>`) 맨 아래(폴더 트리 + 미분류
      문서 리스트 + "더 보기" 다음)로 옮겨진다 — 제거되지 않는다. 폴더 유무와 무관하게
      항상 보이고, 클릭하면 폴더 파라미터 없이 `/editor/new`로 이동한다(미분류 생성).
- [x] 폴더 행에 "+"(새 문서, `/editor/new?folder={folderId}`로 이동)와 "..."(옵션 메뉴)
      두 개의 트리거만 남는다. "..." 메뉴에는 "하위 폴더 추가"·"이름 변경"·"삭제"(danger,
      구분선)가 들어가고, 클릭 동작(모달 열기 등)은 기존과 동일하다.
- [x] "미분류"는 기존과 동일한 레이블(`<p>`)로 남는다 — 별도의 "+"를 붙이지 않는다(맨
      아래로 옮긴 "새 문서" 버튼이 그 역할을 겸한다).
- [x] 폴더가 하나도 없는 계정은 기존과 동일하게 동작한다(평평한 목록 + 맨 아래 "새 문서"
      버튼, `/editor` 홈 화면의 "새 문서 작성" 버튼도 그대로 유지).
- [x] `/editor/new?folder={id}`로 들어가 저장하면 그 폴더로 배정된 문서가 생성된다
      (`POST /api/editor/documents` body에 `folderId` 포함).
- [x] `/editor/new?folder={id}`로 들어가면 헤더에 그 폴더의 경로(브레드크럼)가 보인다 —
      이미 있는 `folderPath`/`DocumentEditor` 메커니즘(P7-7)을 create 모드에도 그대로
      연결한다(새 UI를 만들지 않는다).
- [x] 폴더 옵션 메뉴 팝업이 사이드바 스크롤 영역 바깥까지 온전히 보인다(P14-3와 동일한
      `position: fixed` 방식).
- [x] 기존 회귀 테스트(폴더 생성·이름변경·삭제, 문서 옵션 메뉴)가 새 트리거 경로에 맞게
      갱신되어 통과한다.

## 결정이 필요한 사항
없음 — 사용자가 대화 중 두 진입점(메인/폴더별)의 구조를 직접 확정했고, 백엔드
`folderId` 파라미터는 이미 구현되어 있어 새로 정할 값(주기·용량 같은 임의값)이 없다.

## 범위 밖
- 폴더 트리 자체의 드래그앤드롭 재배치 — 기존과 마찬가지로 범위 밖(P7-6 결정 유지).
- `/editor/new` 화면에 폴더를 직접 고르는 선택 UI(드롭다운 등) — 폴더 파라미터는 사이드바
  "+"에서만 전달되고, 화면 자체에 폴더 변경 UI를 새로 만들지 않는다(필요해지면 별도 작업).
- 문서 작성 중 폴더를 바꾸는 것 — 기존처럼 저장 후 사이드바 "다른 폴더로 이동" 메뉴를 쓴다.
