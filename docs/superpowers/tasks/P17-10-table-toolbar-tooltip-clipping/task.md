# P17-10: 표 툴바 툴팁이 화면 상단에서 잘려 보이던 문제 수정

## 배경
P17-3(표 삭제 아이콘 구분) PR을 검토하던 사용자 지적: "표 툴바에 마우스 올리면 설명이
나왔으면 좋겠어. 마우스 오버 했을 때 Top 라인의 크기가 이상해. 버튼에 맞지 않고 크게
나와. 이동하는 버튼 4개가 그렇네."

디버그용 임시 페이지(`/dev-preview-table-toolbar`, 커밋하지 않고 검증 후 삭제)로
`EditorShell.tsx`의 실제 구조(`<div className="scrollbar-hidden flex-1
overflow-y-auto">{children}</div>` 스크롤 컨테이너 + 상단 고정 헤더)를 그대로 재현해
실제 브라우저(Browser pane)로 재현했다. 원인 확인:
- 표 툴바는 `sticky top-14`라 표를 스크롤하면 이 스크롤 컨테이너 맨 위(헤더 바로
  아래)에 들러붙는다.
- 툴바 버튼의 `Tooltip`은 `side` prop을 지정하지 않아 기본값 `"top"`을 쓴다 — 버튼
  "위"에 그려지려 하는데, 그 자리가 스크롤 컨테이너의 경계(맨 위) 밖이다.
- `overflow-y-auto`는 CSS 스펙상 `overflow-x`도 `auto`로 강제 계산되어(P14-3에서
  이미 확인된 것과 같은 원인) 컨테이너 경계 밖으로 나가는 절대위치 자손을 전부
  잘라낸다 — 그래서 툴팁의 대부분(둥근 모서리·텍스트가 있는 윗부분)이 잘리고,
  경계에 걸친 아주 얇은 흰 띠(하단 padding 일부)만 남아 보인다. 사용자가 본
  "버튼에 맞지 않고 크게 나와" 있는 그 모양이 정확히 이것이었다.
- 실제로 개발자 도구로 확인한 결과: 툴팁 rect top=38, 스크롤 컨테이너 top=56 —
  툴팁의 위쪽 18px가 컨테이너 경계 밖에서 잘려 하단 6px(38~56 사이는 안 보이고
  56~62만 보임)만 남았다.

"이동하는 버튼 4개"(행 추가(위)/행 추가(아래)/열 추가(왼쪽)/열 추가(오른쪽))만 지적됐지만,
같은 행에 있는 모든 버튼(행 삭제·열 삭제·병합·분할·표 삭제)이 구조적으로 동일하게
영향받는다는 것도 재현으로 확인했다 — 사용자가 먼저 눈에 띈 버튼들만 언급한 것으로
보인다.

## 수용 기준 (Acceptance Criteria)
- [x] 표 툴바의 아무 버튼에 마우스를 올리면 설명(Tooltip)이 잘리지 않고 완전한 모양
      (둥근 모서리 + 텍스트)으로 보인다.
- [x] 표가 스크롤되어 툴바가 `EditorShell` 스크롤 컨테이너 맨 위에 붙어 있는 상태에서도
      동일하게 잘리지 않는다(재현 시나리오의 핵심 조건).
- [x] "이동하는 버튼 4개"뿐 아니라 툴바의 모든 버튼(행/열 삭제, 병합, 분할, 표 삭제
      포함)에 동일하게 적용된다.
- [x] 조건부 위치 계산(스크롤 위치를 감지해 동적으로 방향을 바꾸는 방식) 대신, 구조적으로
      클리핑이 생기지 않는 방향(버튼 아래 — 항상 표 본문이 있어 공간이 보장됨)을 기본값으로
      쓴다(P14-3·P15-4 선례와 같은 "조건부 CSS 대신 구조로 해결" 원칙).

## 결정이 필요한 사항
없음 — 사용자가 "툴팁과 top 라인 사이즈 확인해서"라고 구체적으로 원인 파악을 요청했고,
재현으로 확인한 근본 원인(스크롤 컨테이너 클리핑)에 대한 표준적인 해결책(툴팁 방향을
클리핑이 없는 쪽으로 고정)을 적용하면 되므로 별도로 정할 값이 없다.

## 범위 밖
- 사이드바 문서 옵션 메뉴(P14-3)처럼 완전히 별도 `position: fixed` 포털로 재구현하는
  것 — Tooltip은 `@sfood/ui`가 제공하는 기존 컴포넌트고 `side` prop만으로 이 문제가
  구조적으로 해결되므로, 새 커스텀 구현을 만들지 않는다.
- 표 툴바 외 다른 곳(슬래시 메뉴, 버블 메뉴 등)의 Tooltip/플로팅 UI 재검토 — 이번
  지적은 표 툴바에 한정된다.
