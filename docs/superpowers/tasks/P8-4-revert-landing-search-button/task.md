# P8-4 되돌리기: 랜딩 화면 검색 버튼 제거

## 배경
P8-4에서 `/editor` 랜딩 화면 히어로에 검색 버튼(`LandingSearchButton.tsx`)을 추가했다.
이후 사용자가 실제 화면을 보고 "메인 화면에 검색이 3군데(헤더 버튼·랜딩 버튼·사이드바
제목/태그 필터)나 있는데 이게 좋은 UI인가?"라고 직접 지적했다. 헤더 버튼(P8-1)과 랜딩
버튼(P8-4) 둘은 완전히 같은 `GlobalSearchModal`을 여는 동작이라 실질적으로 중복이었다.

레퍼런스(support.claude.com/ko)가 이 중복을 갖는 이유는 불특정 다수가 처음 방문하는
공개 헬프센터라 "Ctrl+K를 모르는 신규 방문자에게 큰 CTA로 한 번 더 알려주는" 맥락이
있어서다. 이 프로젝트는 같은 팀원이 반복해서 쓰는 사내 도구라 그 맥락이 약하고, 중복의
실익보다 화면 혼잡도가 더 크다고 판단해 랜딩 버튼을 제거하기로 사용자와 합의했다
(AskUserQuestion으로 "제거" vs "유지" 중 제거를 선택받음).

관련 PRD 항목: `docs/product/prd.md`의 **P8-4**(재검토·되돌림).

## 수용 기준 (Acceptance Criteria)
- [x] `/editor` 랜딩 화면에서 히어로 검색 버튼이 사라진다 — "새 문서 작성" 링크만 남는다.
- [x] 헤더 검색 버튼(P8-1, 사이드바 상단·모바일 상단 바)은 전혀 영향받지 않고 그대로
      동작한다.
- [x] 랜딩 버튼만을 위해 만들었던 `LandingSearchButton.tsx`·`GlobalSearchContext.tsx`와
      그 테스트를 모두 제거한다(더는 쓰이지 않는 죽은 코드를 남기지 않는다).
- [x] `EditorShell.tsx`의 기존 `triggerSearch`/`openSignal`(P8-1) 배선은 그대로 유지한다.
- [x] 관련 테스트가 회귀 없이 통과하고, 제거된 기능을 검증하던 테스트도 함께 정리된다.

## 결정이 필요한 사항
없음 — 제거 여부 자체가 이번 작업에서 사용자에게 직접 확인받은 결정이다(AskUserQuestion,
"랜딩 히어로 검색 버튼 제거" 선택).
