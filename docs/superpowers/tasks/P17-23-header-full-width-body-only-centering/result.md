# P17-23: 헤더는 항상 꽉 채우고 본문만 가운데 정렬 — 구현 결과 보고서

## 구현 내용
- P17-22가 도입한 "본문+TOC를 하나로 묶어 최대폭(1300px)으로 가운데 정렬"하는
  EditorShell의 wrapper를 제거했다. TOC는 다시(P17-18 이전과 같이) 화면 진짜
  오른쪽 끝에 고정된 독립 컬럼으로 돌아갔고, 본문 스크롤 영역은 그 옆에서
  자연스럽게 남은 flex-1 공간 전체를 차지한다.
- 이 결과 문서 헤더(`DocumentEditor.tsx`의 `<header sticky>`)는 자기 칼럼(본문
  스크롤 영역)의 전체 폭을 그대로 차지하게 되어, 사이드바~TOC 사이 어디에도
  빈틈 없이 항상 꽉 찬다. 본문 텍스트만 `DocumentEditor.tsx`가 이미 자체적으로
  하고 있던 가운데 정렬(920px/Wide mode 1200px)로 좁아진다 — 이 부분은 이번
  작업에서 전혀 건드리지 않았다.

## 자체 검토 (Self-Review)
### 긍정 사항
- P17-18/22 두 차례의 실사용 피드백을 종합해, 이번엔 사용자가 명시적으로 고른
  "헤더는 항상 꽉 채움" 방향으로 EditorShell을 가장 단순한(P17-18 이전과 동일한)
  구조로 되돌렸다 — 또 다른 절충안을 새로 발명하지 않고, 이미 검증됐던 구조를
  재사용했다.
- 임시 디버그 페이지에서 1920px 뷰포트를 실측해, 헤더가 사이드바~TOC 사이
  전체(빈틈 없이)를 채우고, TOC가 화면 진짜 오른쪽 끝에 있으며, 본문 텍스트만
  그 칼럼 안에서 자체 중앙 정렬됨을 확인했다.

### 주의사항
- "넓은 모니터에서 본문 좌우로 커지는 빈 공간"이라는 P17-18의 원래 동기는 이제
  다시 존재한다(트레이드오프로 받아들이기로 함 — task.md "범위 밖" 참고). 이
  여백 자체가 다시 문제로 지적되면, 이번엔 EditorShell 레벨이 아니라
  `DocumentEditor.tsx`의 본문 자체 최대폭 값을 조정하는 방향으로 접근해야
  한다(헤더에 영향을 주지 않는 유일한 안전한 지점이기 때문).
