# P17-23: 헤더는 항상 꽉 채우고 본문만 가운데 정렬 — task

## 배경
- 사용자가 병합된 P17-22("본문+TOC 묶음만 최대폭으로 가운데 정렬")를 실제
  화면에서 보고 스크린샷과 함께 리포트: "이번에는 헤더가 문제네. 헤더가 같이
  좁혀 졌어. 라인이 이상하지? 뒤로 가는 버튼도 공간이 띄워져 있어. 오른쪽 끝에도
  라인이 끝까지 되어 있지 않아."
- 실측 결과(1920px 뷰포트): 이전 결과대로 대칭(좌우 각 182px)이었고 헤더~TOC
  사이도 붙어 있어 "버그"는 아니었다 — 다만 P17-22가 문서 헤더(`DocumentEditor.tsx`
  의 `<header sticky>`, 뒤로가기·공유·저장 버튼)까지 "본문+TOC" 묶음 안에 포함시켜
  헤더까지 함께 좁아지고 가운데로 밀린 것이었다.
- 확인 질문("헤더를 항상 꽉 채우고 본문만 좁힐지 / 헤더도 함께 좁힐지 / 정렬
  기능 자체를 없앨지")에 사용자가 "헤더는 항상 꽉 채우고(추천), 본문만 가운데
  좁혀"를 선택했다 — Notion/Confluence 등 대부분의 문서 도구 관례과 같다.

## 수용 기준 (Acceptance Criteria)
- [x] 문서 헤더(뒤로가기·게시 설정·공유·저장 버튼이 있는 툴바)는 항상 자기
      칼럼(사이드바 오른쪽 끝 ~ TOC 왼쪽 끝) 전체를 채운다 — 좌우 어디에도
      의도치 않은 여백이 생기지 않는다.
- [x] TOC는 다시(P17-18 이전과 같이) 화면 진짜 오른쪽 끝에 고정된 독립 컬럼으로
      돌아간다 — 헤더와 TOC 사이에 빈틈이 없다.
- [x] 본문 텍스트(제목·내용)는 그대로 `DocumentEditor.tsx`가 이미 갖고 있는 자체
      가운데 정렬(920px/Wide mode 1200px)을 유지한다 — 이 작업으로 새로 건드리지
      않는다.
- [x] EditorShell 레벨에서 "본문+TOC를 하나로 묶어 가운데 정렬"하던 P17-22의
      wrapper(`max-w-[1300px]`)를 제거한다.

## 결정이 필요한 사항
없음 — 사용자가 명확히 "헤더는 항상 꽉 채우고, 본문만 가운데 좁혀"를 선택했다.

## 범위 밖
- "넓은 모니터에서 본문 좌우로 커지는 빈 공간"(P17-18의 원래 동기) 자체를 다시
  EditorShell 구조로 해결하려는 시도 — 이번 결정으로 그 트레이드오프(툴바는
  꽉 채우고 본문만 좁아짐)를 받아들이기로 했으므로, 더 이상 EditorShell 레벨의
  정렬 기능을 만들지 않는다.
