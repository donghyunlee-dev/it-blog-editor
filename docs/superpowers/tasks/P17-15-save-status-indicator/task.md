# P17-15: 저장 버튼 상태 표현 강화 — task

## 배경
- 외부(GPT) UI 개선 제안 리뷰 중 채택한 항목(3번). 저장 버튼 자체는 유지하되(Confluence
  실제 저장·문서 이력 생성과 연결되어 있어 단순 Editor UI 이상의 의미가 있다는 진단에
  동의), "지금 수정 중인지/저장이 필요한지/방금 저장됐는지"를 알려주는 상태 표시가
  약하다는 지적을 검토해 채택했다.
- 실제 코드 확인 결과: 저장 상태 텍스트가 이미 존재하긴 했지만 **풋터**에 있고
  (`mode === "edit" && initialUpdatedAt`일 때만, 자동 저장 진행/성공에만 반응), 헤더의
  저장 버튼 자체는 아이콘만 있어 방금 열었을 때/처음 저장하기 전에는 아무 상태도 보여
  주지 않았다. GPT 제안(`공유  변경사항 있음  [저장]` / `공유  ✓ 저장됨 13:27`)대로
  헤더로 끌어올린다.
- 관련 코드: `src/components/editor/DocumentEditor.tsx`(헤더, `status`/`isDirty`/
  `autosaveStatus` 상태, `handleSave`/`performAutosave`).

## 수용 기준 (Acceptance Criteria)
- [x] 저장 버튼 옆(같은 헤더)에 다음 세 상태 중 하나를 보여준다: "저장 중...", "변경사항
      있음", "저장됨 HH:MM". 우선순위는 저장 중 > 변경사항 있음 > 저장됨.
- [x] 아직 한 번도 저장한 적 없고 변경도 없는 새 문서(mode="create", 방금 연 상태)는
      셋 다 해당 없어 아무것도 표시하지 않는다(억지로 상태를 지어내지 않는다).
- [x] 이미 저장된 적 있는 문서를 열면(`initialUpdatedAt` 있음) 그 최종 수정 시각을
      "저장됨 HH:MM"의 초깃값으로 보여준다.
- [x] 제목/본문/태그를 수정하면 즉시 "변경사항 있음"으로 바뀐다.
- [x] 저장(수동 클릭 또는 1분 자동저장)이 성공하면 "저장됨 HH:MM"으로 바뀐다(HH:MM은
      저장이 완료된 실제 시각).
- [x] 상태 표시는 `role="status" aria-live="polite"`로 스크린 리더에도 전달된다(기존
      풋터 표시가 쓰던 패턴을 그대로 옮긴다).
- [x] 저장 버튼의 클릭 동작·비활성화 조건(`status !== "idle"`)·아이콘은 그대로 둔다 —
      이번 작업은 상태 "표시"만 추가한다.
- [x] 중복이 된 풋터의 자동저장 상태 문구("자동 저장 중.../자동 저장됨")는 제거하고,
      풋터에는 세션을 넘나드는 이력 정보(최종 수정 날짜·수정자)만 남긴다 — 두 군데서
      서로 다른 시점의 상태를 보여주며 혼란을 주지 않도록 한 곳으로 통합한다.

## 결정이 필요한 사항
없음 — 표시 문구·우선순위·초깃값 규칙은 GPT 제안과 기존 코드의 상태 변수
(`status`/`isDirty`/`initialUpdatedAt`)만으로 결정 가능해 새로 정할 값이 없다.

## 범위 밖
- 저장 버튼 자체의 모양(아이콘/텍스트) 변경 — 이번 작업은 상태 표시 추가만 다룬다.
- 자동저장 주기(60초 고정 interval) 변경 — 별도 항목(4번, 이번 라운드에서 제외)에서
  다룬다.
