# P2-7: 인라인 코드 서식 추가(슬래시 메뉴 + 서식 버블 메뉴)

## 배경
- 사용자가 "코드를 넣을 수 있는 컴포넌트가 있는지 확인해줘"라고 물어 조사했다. 결과:
  - **코드블록**(여러 줄, 문법 강조 지원)은 이미 있다 — 슬래시 메뉴 "/코드블록"(P1-7c).
  - **인라인 코드**(문장 중 짧은 코드 표기, 예: `` `useState` ``)는 스키마에는 이미 있었다 — `StarterKit`이 기본 제공하는 `code` 마크가 비활성화되지 않았고, `tiptap-to-storage.ts`의 `MARK_TAGS.code`가 이미 `<code>`로 직렬화하도록 돼 있었다. **하지만 이를 적용할 UI(슬래시 메뉴 항목·버블 메뉴 버튼)가 전혀 없어**, 기본 키보드 단축키(TipTap 기본값 `Cmd/Ctrl+E`) 없이는 아무도 쓸 수 없는 상태였다.
- 사용자가 이어서 "슬래시 기능과 툴바 버튼으로 인라인 코드 컴포넌트를 넣어줘. notion의 기능을 참고해줘"라고 요청해 이 항목을 착수한다.
- 관련 PRD 체크리스트: `docs/product/prd.md`의 "P2 — 다듬기", P2-7.

## Notion 참고 사항
- Notion의 플로팅 포맷 툴바(텍스트 선택 시 뜸)에는 굵게/기울임/밑줄/취소선/코드/링크 등이 나란히 있고, "코드"는 `</>` 모양 아이콘으로 표시된다 — 이 프로젝트의 굵게(B)/기울임(I)/취소선(S) 텍스트 글자 라벨 관례를 그대로 따라 `</>` 텍스트를 라벨로 썼다(새 SVG 아이콘 추가 안 함, `@sfood/ui`의 `Icon`이 `search`/`comment`만 제공하는 기존 제약과 동일한 이유).
- Notion은 슬래시 메뉴로 마크(인라인 서식)를 적용하는 기능은 없지만(슬래시는 보통 블록 삽입용), 이 프로젝트는 이미 "코드블록"을 슬래시 메뉴 항목으로 제공하는 선례가 있어(커서 위치에서 토글, 다음 입력부터 적용) 같은 패턴을 인라인 코드에도 적용한다 — 사용자가 명시적으로 슬래시 메뉴도 요청했으므로 범위에 포함한다.

## 수용 기준 (Acceptance Criteria)
- [ ] 슬래시 메뉴에 "인라인 코드" 항목을 추가한다(기존 "코드블록" 바로 아래) — 선택하면 커서 위치에서 인라인 코드 토글이 켜진다(다음 입력부터 코드 마크가 적용됨, "코드블록" 항목과 동일한 패턴).
- [ ] 서식 버블 메뉴(텍스트 선택 시 뜨는 메뉴)에 코드 토글 버튼을 추가한다 — 선택한 텍스트에 인라인 코드 마크를 적용/해제한다.
- [ ] 표 셀 안에서도 두 진입점 모두 동일하게 동작한다(P2-5/P2-6과 같은 패턴 — `EditorBubbleMenu`가 표 셀을 구분하지 않으므로 자연히 성립할 것으로 예상, 테스트로 확인).
- [ ] 발행(Confluence storage format 변환)에도 인라인 코드가 반영된다 — 이미 `tiptap-to-storage.ts`의 `MARK_TAGS.code`가 처리하고 있어 추가 작업이 필요 없음을 확인만 한다.
- [ ] `SlashCommandExtension.test.ts`와 `RichTextEditor.test.tsx`에 각각 회귀 테스트를 추가한다.

## 결정이 필요한 사항
없음 — 이미 스키마·직렬화가 있는 기능에 UI만 노출하는 작업이고, 사용자가 진입점(슬래시+툴바 버튼)과 참고 대상(Notion)을 직접 지정했다.

## 범위 밖
- 코드블록(여러 줄) 관련 기능은 P1-7c에서 이미 완료됐고 이 항목과 무관하다.
- 인라인 코드의 언어별 문법 강조는 다루지 않는다(코드블록과 달리 인라인 코드는 Notion도 강조를 하지 않는다 — 짧은 표기용 기능이라는 성격상 범위 밖).
