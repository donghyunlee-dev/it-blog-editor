# P1-1a 후속: Ctrl+K 전역 검색 팝업을 Notion 스타일로 재구성한다

## 배경
- `docs/superpowers/tasks/P1-1a-content-search-ctrlk/`에서 만든 첫 버전은 결과를 제목·태그만 보여주는
  단일 목록이었다. 실제 병합(PR #38) 후 사용자가 Notion의 실제 Ctrl+K 검색 화면 캡처를 공유하며
  "지금 개발된 것과 너무 차이난다"고 지적, 캡처와 가깝게 재구현을 요청했다.
- 캡처에서 확인한 요소: ① 상단의 큰 검색 입력창, ② "제목만" 필터 필(pill), ③ 결과를 오늘/어제/지난주
  등 최근 순으로 그룹핑, ④ 각 결과 행에 아이콘 + 굵은 제목 + " — " + 보조 텍스트, ⑤ 오른쪽에 선택한
  문서의 제목·본문 미리보기를 보여주는 2단(две-pane) 레이아웃.
- 캡처에 있지만 이번 범위에서 제외한 것(사용자에게 사전 고지, 이견 없음):
  - "생성자"/"검색 범위" 필터 — 이 앱은 계정별 개인 폴더 구조라 여러 사용자의 문서를 넘나들며 찾을
    일이 없다(Notion의 워크스페이스 공유 문서 모델과 다름).
  - 즐겨찾기/북마크 — 이 앱에는 해당 기능 자체가 없다.

## 수용 기준 (Acceptance Criteria)
- [x] 검색 팝업 상단에 검색 입력창을 크게 배치한다.
- [x] "제목만" 토글 필을 추가한다 — 켜면 제목에 쿼리가 포함된 문서만 남기고(본문·태그로만 일치한
      문서는 숨김), 끄면 기존처럼 제목·태그·본문 전체 결과를 보여준다.
- [x] 결과 목록을 문서의 최종 수정일(`updatedAt`) 기준 오늘/어제/최근 7일/이전 4개 구간으로 묶어
      구간 헤더와 함께 보여준다.
- [x] 각 결과 행은 기존 `StatusIcon`(게시/초안) + 제목 + (태그가 있으면) " — 태그, 태그" 형태로
      표시한다.
- [x] 오른쪽 패널에 현재 강조된(하이라이트된) 결과의 태그·제목·본문 미리보기(스니펫)를 보여준다 —
      키보드 방향키로 강조를 옮기면 미리보기도 함께 바뀐다.
- [x] 본문 미리보기용 스니펫은 서버에서 계산해 내려준다 — 검색어가 본문에 있으면 그 앞뒤 문맥을,
      없으면(제목·태그만 일치) 본문 맨 앞부분을 잘라 보여준다.
- [x] 기존 키보드 동작(Ctrl+K/Cmd+K 토글, Escape 닫기, ArrowUp/Down+Enter 이동, 클릭 이동)은
      회귀 없이 유지한다.
- [x] `@sfood/ui`의 `Modal`은 `size`가 `sm/md/lg`(최대 `max-w-2xl`)까지만 지원해 요구되는 2단
      와이드 레이아웃을 담을 수 없다 — design.md의 "① 대응 요소 없으면 대체 구성" 원칙에 따라
      커스텀 오버레이를 만들고 그 이유를 design.md에 기록한다.

## 결정이 필요한 사항
없음 — 사용자가 캡처로 직접 목표 UI를 지정했고, 위 "제외 범위"도 대화 중 사전 고지에 이견이 없었다.

## 범위 밖
- "생성자"/"검색 범위" 필터, 즐겨찾기/북마크(위 배경 참고 — 이 앱 데이터 모델에 대응 개념이 없음).
- 하이라이트(일치 부분 강조 표시)는 이번에도 범위 밖이다 — 스니펫(주변 문맥 잘라 보여주기)까지만
  구현한다.
