# P2-4: 표 삭제 버튼 추가

## 배경
- 사용자가 실사용 중 발견한 공백 두 가지 중 하나(2026-09-09 보고): "표 자체를 삭제하는 기능이 없다."
- P1-7a(`docs/product/prd.md`, Phase 4 P1 체크리스트)에서 행/열 추가·삭제, 셀 병합·분할까지는 구현했지만 "표 삭제, 헤더 토글은 범위 밖"이라고 명시적으로 미뤄둔 항목이다 — 처음부터 알려진 채 남겨둔 공백이지, 이번에 새로 생긴 결함이 아니다.
- 관련 PRD 체크리스트: `docs/product/prd.md`의 "P2 — 다듬기", P2-4.
- 관련 코드: `src/components/editor/RichTextEditor.tsx`의 `TableToolbar`(표 자체 상단에 고정되는 sticky 아이콘 툴바, P1-7a 3차 재설계 참고) — 행 추가/삭제, 열 추가/삭제, 셀 병합/분할 버튼이 이미 이 컴포넌트에 있다.

## 수용 기준 (Acceptance Criteria)
- [ ] 커서가 표 안에 있을 때 `TableToolbar`에 "표 삭제" 버튼이 보인다(다른 버튼과 마찬가지로 `Tooltip`+`aria-label`).
- [ ] "표 삭제" 버튼을 클릭하면 즉시 삭제되지 않고, CLAUDE.md 규칙("확인이 필요한 삭제 등의 동작은 `window.confirm()` 대신 `Modal`을")에 따라 `@sfood/ui`의 `Modal`로 확인을 받는다. 기존 `DocumentEditor.tsx`의 "문서 삭제" Modal과 동일한 패턴(제목, 취소=`variant="secondary"`, 확인=`variant="danger"`)을 따른다.
- [ ] Modal에서 취소하면 표가 그대로 유지된다.
- [ ] Modal에서 확인하면 표 전체(행/열/내용 전부)가 문서에서 제거되고 `onChange`에 반영된다.
- [ ] 문서에 표가 여러 개일 때, 삭제 버튼을 눌러도 커서가 있던 표만 삭제되고 다른 표는 그대로 유지된다(기존 P1-7a의 "다중 표" 회귀 테스트와 같은 종류의 검증).
- [ ] `RichTextEditor.test.tsx`에 위 시나리오를 검증하는 테스트를 추가한다.

## 결정이 필요한 사항
없음 — TipTap `@tiptap/extension-table`이 이미 제공하는 표준 커맨드(`deleteTable`)를 노출하는 단순 UI 추가이고, 확인 절차(Modal)는 CLAUDE.md 규칙과 기존 "문서 삭제" Modal 선례를 그대로 따르면 돼 새로 정할 값이 없다.

## 범위 밖
- 헤더 토글(표의 첫 행/열을 헤더로 지정·해제)은 P1-7a에서와 마찬가지로 이번에도 범위 밖이다 — 사용자가 이번에 보고한 두 가지 공백(표 삭제, 표 안 서식)에 포함되지 않는다.
- 표 안 텍스트 서식(색상·폰트) 관련 조사·작업은 별도 항목(P2-5)에서 다룬다.
