## 수동/시각 검증(Browser pane으로 실제 확인)
- `.selectedCell` 배경색 표시는 실제로 확인했다 — 임시 디버그 페이지(검증 후 삭제)
  에서 A1/B1 두 셀을 드래그로 선택하니 `--color-brand-subtle` 톤의 배경이 스크린샷
  으로 확인됐고, 이어서 "셀 병합"을 클릭해 정상적으로 병합됨(A1B1 하나의 셀)도
  재확인했다 — 이번 수정이 기존 동작을 깨지 않았음을 보여준다.
- **원래 버그(mousedown 선택 되돌림) 자체는 이 세션에서 재현·재확인하지 못했다** —
  이 세션의 Browser pane(헤드리스 Chromium)과 실제 Playwright(다운로드해 로컬
  dev 서버에 대해 실행, 여러 스텝의 진짜 마우스 이벤트로 재시도)로 8행 표의 7행에
  커서를 두고 툴바 버튼을 클릭하는 시나리오를 여러 방식으로 반복 검증했지만 매번
  올바른 위치에 삽입됐다 — 이 특정 브라우저 동작(비편집 버튼을 mousedown할 때
  에디터 선택을 되돌리는 것)이 합성 마우스 이벤트로는 트리거되지 않는 것으로
  보인다. 사용자가 실제 브라우저에서 직접 원인을 확정했고("테이블 위에 툴바를
  클릭하면 마우스 포인트가 테이블 첫번째로 이동"), 적용한 수정은 이 정확한 증상에
  대한 업계 표준 해법(리치 텍스트 에디터 툴바의 `onMouseDown` preventDefault
  패턴)이라 근본 수정으로 판단했다.

## 문제 → 조치 → 재검증
- **문제**: `.selectedCell` 배경색 수정이 병합 기능 자체를 깨뜨리지 않는지 걱정됐다.
- **조치**: 없음(우려만 있었고 실제 문제는 없었다).
- **재검증**: Browser pane에서 드래그 선택 → 배경색 확인 → 병합 클릭 → 실제 병합
  됨을 확인해 안전함을 검증했다.

없음.

## 사용자 재확인 요청
이 수정(`onMouseDown` preventDefault)이 실제로 "행 추가가 항상 1행 기준" /
"병합 버튼은 활성화되는데 눌러도 아무 일도 안 일어난다" 문제를 없애는지, 실제
브라우저에서 다시 확인 부탁드립니다 — 이 세션의 자동화 도구로는 원래 버그 자체를
재현하지 못해 수정 전후 비교를 시각적으로 보여드릴 수 없었습니다.
