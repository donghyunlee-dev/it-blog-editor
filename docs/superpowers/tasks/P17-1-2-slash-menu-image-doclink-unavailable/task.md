# P17-1/P17-2: 슬래시 메뉴 "이미지"·"문서 링크" 삽입 무반응 수정

## 배경
사용자가 편집 화면에서 "이미지 기능 안됨. 아무 반응 없음", "문서 링크 기능 안됨"을
지적했다. 조사 결과 두 항목은 같은 원인이다 — `RichTextEditor.tsx`가 신규 문서(저장 전,
`pageId` 미확정) 상태에서는 슬래시 메뉴의 "이미지"·"문서 링크" 항목 자체를 목록에서
빼버린다. `/`를 입력해도 해당 항목이 안 보이거나 "일치하는 항목이 없습니다"만 떠서
"아무 반응 없음"으로 느껴진다. 같은 상황에서 드래그앤드롭/붙여넣기 업로드 경로는 이미
"문서를 먼저 저장한 뒤에 이미지를 추가할 수 있습니다." 토스트로 안내하는데, 슬래시
메뉴만 조용히 항목을 숨기는 비대칭이 원인이다.

두 항목은 원인·코드 위치(`RichTextEditor.tsx`의 슬래시 확장 설정 블록)·수정 방식이
완전히 같아 하나의 작업으로 묶는다(P6-2/P6-3 병합 구현과 같은 선례).

## 수용 기준 (Acceptance Criteria)
- [x] 신규 문서(저장 전)에서도 `/이미지`, `/문서 링크`를 입력하면 슬래시 메뉴에 두
      항목이 항상 보인다(더 이상 조건부로 숨겨지지 않음).
- [x] 저장 전 문서에서 "이미지" 항목을 클릭하면 파일 선택 창이 열리지 않고, 드래그
      앤드롭/붙여넣기와 동일한 안내 토스트("문서를 먼저 저장한 뒤에 이미지를 추가할
      수 있습니다.")가 뜬다.
- [x] 저장 전 문서에서 "문서 링크" 항목을 클릭하면 검색 피커 모달이 열리지 않고, 같은
      패턴의 안내 토스트("문서를 먼저 저장한 뒤에 문서 링크를 추가할 수 있습니다.")가
      뜬다.
- [x] 저장된 문서(`pageId` 있음)에서는 기존과 동일하게 정상 동작한다(회귀 없음) — 이미지는
      파일 선택 후 업로드·삽입, 문서 링크는 검색 피커가 열리고 문서를 고르면 카드가
      삽입된다.

## 결정이 필요한 사항
없음 — "저장 전 안내 방식"은 이미 드래그앤드롭/붙여넣기 경로에서 토스트로 확립된
패턴이라 그대로 재사용하면 되고, 별도로 정할 값이 없다.

## 범위 밖
- 신규 문서를 자동으로 임시 저장해 pageId를 미리 만들어주는 방식(더 큰 설계 변경이라
  이번 범위 밖) — 안내로 이유를 알려주는 것까지만 다룬다.
- 표 삭제 아이콘 구분, 코드 블록 편집 개선 등 Phase 17의 다른 항목(P17-3~P17-8)은
  각각 별도 작업으로 진행한다.
