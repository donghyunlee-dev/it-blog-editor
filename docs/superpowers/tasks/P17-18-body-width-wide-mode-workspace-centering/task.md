# P17-18: 본문 폭 확대 + Wide mode + 워크스페이스 중앙 정렬 — task

## 배경
- 외부(GPT) UI 개선 제안 리뷰 중 채택한 항목(5번). 값·범위가 정해지지 않아 GitHub
  Issue #161로 등록했고, 사용자가 직접 답한 결정 사항을 그대로 반영한다
  (https://github.com/sfood-pioneer-1st/sfood-it-editor/issues/161, 닫힘).
- 결정 사항:
  1. 본문 최대 폭: 830px(P8-6 벤치마킹 값) → **920px**.
  2. Wide mode: **문서 전체 토글**(블록 단위는 스키마 변경이 필요한 별도 후속 작업으로
     미룸) — 켜면 1200px.
  3. 워크스페이스(사이드바+본문+TOC) 전체를 최대폭으로 묶어 페이지 가운데 정렬 —
     이번에 함께 처리(1번 항목 조사에서, 넓은 모니터에서 본문 좌우로 점점 커지는
     빈 공간을 확인했다: 1920px에서 각 297px, 1440px에서 각 57px).
- 관련 코드: `src/components/editor/DocumentEditor.tsx`(본문 폭·Wide mode 토글),
  `src/components/editor/EditorShell.tsx`(워크스페이스 최대폭+중앙 정렬),
  `src/components/editor/VersionHistoryPage.tsx`/`DeletedDocumentsPage.tsx`(같은
  830px 값을 이미 맞춰 뒀던 화면들 — 일관성을 위해 함께 920px로).

## 수용 기준 (Acceptance Criteria)
- [x] 본문 기본(좁게) 최대 폭이 830px에서 920px로 바뀐다.
- [x] 헤더에 "넓게 보기" 토글 버튼이 있고, 누르면 본문 최대 폭이 1200px로 바뀐다
      (`aria-pressed`로 상태 전달). 다시 누르면 920px로 돌아온다.
- [x] Wide mode 선택은 localStorage에 저장되어 다음에 문서를 열어도 유지된다(문서
      내용이 아니라 이 브라우저를 쓰는 사람의 보기 취향이므로 서버에 저장하지 않는다).
- [x] 사이드바+본문+TOC로 이뤄진 워크스페이스 전체가 최대폭(1800px)으로 묶여 페이지
      가운데 정렬된다 — 그보다 넓은 화면에서는 초과분이 좌우 여백으로만 남는다.
- [x] 이 구조 변경으로 깨질 수 있는 두 곳을 함께 고친다: (1) 사이드바 폭 조절 드래그
      (기존에는 "커서 x좌표 = 폭"을 가정했는데, 워크스페이스가 화면 왼쪽 끝에 붙어
      있지 않을 수 있어 실제 워크스페이스 왼쪽 끝을 기준으로 다시 계산해야 한다),
      (2) 접힌 사이드바를 다시 펴는 버튼(`fixed`로 뷰포트 기준이었던 것을 워크스페이스
      기준으로 바꿔야 한다).
- [x] `VersionHistoryPage.tsx`/`DeletedDocumentsPage.tsx`도 같은 830px 값을 맞춰
      두고 있었으므로, 편집 화면과의 폭 불일치가 생기지 않도록 920px로 함께 맞춘다.

## 결정이 필요한 사항
없음 — 모두 Issue #161에서 사용자가 직접 확인했다. 워크스페이스 전체 최대폭의 구체적
값(1800px)만 구현 디테일로 직접 정했다(WIDTH_STEP과 같은 선례 — 사이드바 최대폭
440px + Wide mode 본문 1200px + TOC 240px + 거터를 모두 넉넉히 담는 값).

## 범위 밖
- 블록(표/코드블록 등) 단위 Wide mode — 스키마 변경이 필요한 별도 후속 작업.
- 자동저장 방식 변경(4번 항목) — 사용자 요청으로 이번 라운드에서 제외.
