# P19-4: 문서 이력에 작성자 표시

## 배경
사용자 지적 — "히스토리에 버전 숫자만 나오는데 더 이상 보여줄 정보나 기능이 없어? 작성자
외에는 작업이 크다는 거야?"라는 질문에 답하며 3가지(작성자 표시/변경 내용 diff/특정 버전
복원)를 계획해 순차 진행하기로 확인함(대화, 2026-09-18). 이 항목은 그중 첫 번째 작업이다.

**중요한 정정**: 처음에는 Confluence 버전 API의 `authorId`(Confluence accountId)를 계정
이름으로 매핑하기만 하면 될 거라 판단했으나, 조사 결과 이 앱의 모든 Confluence API 호출이
서비스 계정 하나로만 이루어져(`src/lib/editor/access.ts`) `authorId`는 실제 편집자와 무관하게
항상 같은 값이라는 것이 확인됐다 — 이 값으로는 "작성자"를 보여줄 수 없다.

대신 Confluence 버전 API가 원래 지원하는 `version.message`(버전 코멘트, 지금은 항상
빈 문자열로만 저장되고 있음 — `ConfluencePageVersion.message`)에 저장 시점의 실제 편집자
정보(이메일)를 실어 보내는 방식으로 해결한다(사용자 확인, 2026-09-18 — "내 컨플루언스
계정 말고, 작성한 사람의 정보가 없나?"). 이 방식은 **적용 이후 새로 저장되는 버전부터만**
작성자가 남고, 이미 쌓인 과거 버전은 소급 적용되지 않아 "정보 없음"으로 표시된다 — 이
한계는 사용자에게 안내하고 진행하기로 확인됨.

관련 문서: `docs/superpowers/tasks/P19-1-history-page/task.md`(이력 전용 페이지),
`docs/product/prd.md` Phase 19.

## 수용 기준 (Acceptance Criteria)
- [ ] `updateDocument`(수동 저장·자동 저장 공통 경로)가 Confluence 페이지를 갱신할 때
      `version.message`에 저장을 요청한 사람(`input.editor`)의 표시 정보를 담아 보낸다.
- [ ] `/editor/history/{pageId}` 화면의 각 버전 행에 그 버전의 작성자가 표시된다 —
      `message`가 있으면 그 값을 사용하고, 없으면(이 작업 적용 이전에 저장된 버전) "정보
      없음"으로 표시한다.
- [ ] P19-2(저장 dedup)로 실제 저장이 건너뛰어진 경우에는 새 버전 자체가 생기지 않으므로
      해당 없음(자연히 만족).
- [ ] 기존 읽기 전용 범위(P1-2a)는 그대로 유지한다 — 이 작업은 표시 추가만 한다.

## 결정이 필요한 사항
없음 — 위 "배경"에서 사용자와 함께 확정함.

## 범위 밖
- 과거(이 작업 이전에 저장된) 버전에 소급해서 작성자 정보를 채워 넣는 것 — 애초에
  기록된 적 없는 정보라 불가능하다.
- 변경 내용(diff) 표시 — P19-5에서 다룬다.
- 특정 버전으로 복원 — P19-6에서 다룬다.
