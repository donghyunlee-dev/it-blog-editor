# P14-2: 사이드바 문서 옵션 메뉴에 "이력"·"삭제" 추가 + 에디터 헤더 버튼 제거

## 배경
P14-1(같은 PR)에서 사이드바 문서 행의 "다른 폴더로 이동" 단일 버튼을 옵션(⋯) 메뉴로
바꿨는데, 사용자가 원래 의도를 다시 정정했다 — "헤더에 ⋯을 추가하는 건 안 해도 돼"라는
말은 에디터 헤더에 **별도의** 옵션 메뉴를 새로 만들지 말라는 뜻이었지, 헤더의 "이력"·"삭제"
버튼을 그대로 두라는 뜻이 아니었다. 실제로는: (1) 이력·삭제 버튼은 에디터 헤더에서
**제거**하고, (2) 그 기능을 이미 만든 사이드바 문서 옵션(⋯) 메뉴에 **항목으로 추가**해
"이동·이력·삭제 3개를 하나의 메뉴로" 모으는 것이 목표였다.

추가로 사용자가 실제 화면에서 두 가지 결함을 지적했다:
1. "컨텍스트 메뉴 나오는 위치가 왼쪽으로 나오는데 오른쪽 페이지 방향으로 나와야 해" —
   `@sfood/ui`의 `DropdownMenu`는 메뉴를 트리거 기준 `right-0`(왼쪽으로 펼쳐짐)으로 고정
   배치하는데, 트리거가 좁은 사이드바의 오른쪽 끝에 있어 왼쪽으로 펼치면 문서 제목과
   겹친다. 컴포넌트에 위치를 바꾸는 prop이 없어, CSS로 `[role="menu"]`의 위치를 덮어썼다.
2. "폴더 이동 말고, 이력과 삭제 기능은 넣어 달라고 했는데 안했어" — 위 배경 참고.

## 수용 기준 (Acceptance Criteria)
- [ ] 사이드바 문서 행의 옵션(⋯) 메뉴에 "이력"(항상 노출)과 "삭제"(항상 노출, danger 스타일,
      구분선으로 "이동" 항목과 분리)가 추가된다. "이동"은 이전처럼 폴더가 있을 때만 보인다.
- [ ] "이력" 클릭 시 그 문서의 `VersionHistory`(pageId 기준)를 보여주는 모달이 열린다.
- [ ] "삭제" 클릭 시 확인 모달이 뜨고, 확인해야 `DELETE /api/editor/documents/{pageId}`를
      호출한다. 지금 보고 있는 문서(activePageId와 일치)를 삭제하면 `/editor`로 이동하고,
      아닌 경우 목록만 새로고침한다.
- [ ] 에디터 헤더(`DocumentEditor.tsx`)의 "이력"·"삭제" 버튼과 그 버튼이 열던 모달·핸들러가
      모두 제거된다(죽은 코드를 남기지 않는다).
- [ ] 옵션 메뉴가 사이드바 바깥(본문/페이지 방향)으로 펼쳐진다 — 문서 제목과 겹치지 않는다.
- [ ] 기존 회귀 테스트가 모두 통과하고, DocumentEditor의 이력/삭제 테스트는
      EditorSidebar.test.tsx로 이전된다.

## 결정이 필요한 사항
없음 — 범위(이동·이력·삭제 3개를 사이드바 메뉴로, 헤더 버튼은 제거)와 메뉴 방향을 사용자가
대화 중 직접 정정·확정했다.

## 범위 밖
- 폴더 행의 액션 아이콘 통합 — 여전히 보류.
- `DropdownMenu` 메뉴 항목 자체의 호버 스타일(P13-2와 같은 원인의 라이트 모드 문제) — 이건
  `@sfood/ui` 패키지 내부 구현이라 이 프로젝트에서 고칠 수 없다.
