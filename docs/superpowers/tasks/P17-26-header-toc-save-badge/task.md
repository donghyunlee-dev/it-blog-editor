# P17-26: 헤더 버튼·TOC 경계 여백 정렬 + 저장 상태 뱃지화 — task

## 배경
사용자 리포트(스크린샷 첨부): "페이지의 헤더 버튼과 toc의 위치와 구성이 조잡스러워.
저장됨이라는 텍스트도 위치가 적당해 보이지 않아. 버튼의 순서도 검토가 필요해. 내가
말한 기준으로 검토해서 개선할 계획을 제시해줘."

구현 전 대화로 여러 차례 확인하며 범위를 좁혔다:
1. 먼저 코드 진단 결과와 개선 방향(안)을 제시 → 사용자가 "그 전에 버튼 위치와 toc와
   헤더 라인에 대해 먼저 평가를 해봐"로 되돌려, 실측(`getBoundingClientRect`)부터
   진행했다.
2. 실측 결과 헤더 하단 경계선과 TOC 상단 spacer 경계선은 x=1160px에서 끊기지 않고
   정확히 이어져 있어 "선 자체"는 문제가 아니었다. 실제 문제는 그 경계선을 기준으로
   한 좌우 여백 비율 — 헤더 버튼은 24px(`px-6`), TOC 콘텐츠는 48px(`pl-12`)로 정확히
   2배 차이가 나 "버튼이 한쪽으로 쏠려 붙어 있는 느낌"을 만들고 있었다.
3. 사용자에게 확인한 결과: **TOC 쪽 여백을 헤더 버튼과 같은 24px로 줄임**(96px의
   상단 공백 자체는 본문 제목과의 정렬을 위해 그대로 유지).
4. 이어서 "저장됨" 텍스트를 사용자가 먼저 "단순 텍스트보다 뱃지 형식으로" 바꾸는
   것부터 진행해달라고 요청 — `@sfood/ui`의 `Badge`(배경·테두리가 있는 알약 모양,
   CLAUDE.md 우선순위 ① 원칙에 따라 이 프로젝트가 이미 쓰는 컴포넌트를 재사용)로
   교체.
5. 마지막으로 남은 헤더 버튼 순서/그룹핑(구분선 도입) 제안 — 배지로 바뀐 것만으로도
   충분히 정돈되어 보인다는 사용자 판단으로 **추가 변경 없이 이번 범위를 마무리**.

## 수용 기준 (Acceptance Criteria)
- [x] TOC 콘텐츠(`<nav aria-label="이 페이지">`)의 왼쪽 안쪽 여백이 헤더 버튼
      클러스터의 오른쪽 여백과 같은 24px가 된다(본문↔TOC 경계선 기준 좌우 대칭).
- [x] TOC 상단 공백(헤더 높이 56px + 40px = 96px, 본문 제목 시작 위치와의 정렬)은
      그대로 유지된다.
- [x] "저장됨"/"변경사항 있음"/"저장 중..." 상태 표시가 순수 텍스트가 아니라
      `@sfood/ui`의 `Badge`(배경·테두리가 있는 알약 모양)로 렌더링된다.
- [x] 상태별 색 의미가 명확하다 — 저장 중=진행 중(`info`), 변경사항 있음=주의
      (`warning`), 저장됨=완료(`success`).
- [x] 접근성(`role="status"`, `aria-live="polite"`)과 기존 반응형 숨김(모바일에서는
      숨김)은 그대로 유지된다.
- [x] 헤더 버튼 순서/그룹핑(구분선 도입 등)은 사용자 확인 결과 **이번 범위에서
      제외** — 배지 변경만으로 충분하다고 판단됨.

## 결정이 필요한 사항 (해결됨)
- TOC 좌측 여백 목표 값: 헤더 버튼과 같은 24px로 확정(대화 중 확인).
- TOC 상단 96px 공백 축소 여부: 그대로 유지로 확정(본문 제목 정렬 우선).
- 저장 상태 표현 방식: `Badge`(알약 모양)로 확정 — `StatusBadge`(점+텍스트)는
  검토했으나 사용자가 요청한 "뱃지 형식"과 맞지 않아 채택하지 않음.
- 헤더 버튼 그룹핑/구분선 도입 여부: 배지 변경만으로 충분하다는 판단으로 보류(추가
  요청 시 재개).

## 범위 밖
- 헤더 버튼 순서 재배치·구분선 도입(위 "결정이 필요한 사항" 참고, 이번엔 진행하지
  않음).
- 라이트 모드 배경/입력 모드 색감(P17-25에서 이미 별도 보류로 확정된 사항, 이 task와
  무관).
