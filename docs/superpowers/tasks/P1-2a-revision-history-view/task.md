# P1-2a: Confluence 페이지 버전 이력 읽기 전용 조회 화면

## 배경
2026-08-27 [프로덕션 준비도 감사](https://claude.ai/code/artifact/87302c07-68d6-42ed-8712-9345547cb659)에서 P1로 지적된 항목. Confluence는 페이지 버전 이력을 자체적으로 남기지만(`getPage`가 돌려주는 `version.number`가 이미 그 증거다), 이 애플리케이션은 이를 화면에 전혀 노출하지 않는다.

## 이 작업을 PR로 진행하는 이유
이 항목은 **실제 Confluence 인스턴스로 스파이크 검증을 하지 못한 채** 구현했다 — `GET /api/v2/pages/{id}/versions`의 정확한 응답 형태(필드명·정렬 기본값)를 Atlassian 공식 문서 기준으로만 구현했고, 당시엔 이 환경에서 실제 Confluence 인스턴스로 검증할 방법을 몰랐다(사실 `.env`에 실제 인스턴스 자격증명이 있었다 — 아래 "2026-08-28 갱신" 참고). 이 프로젝트가 이전 단계(Phase 1)에서 중요한 Confluence API 가정마다 실제 인스턴스로 스파이크 검증을 거친 전례(`architecture.md`의 "착수 전 스파이크로 다음 4가지를 검증했다")를 따라, 이번 것도 머지 전에 실제 인스턴스로 한 번 확인하는 것이 안전하다고 판단해 main에 직접 반영하지 않고 PR로 올렸다.

### 2026-08-28 갱신 — 실제 인스턴스로 검증 완료
사용자가 "아무도 사용하지 않는 사내 Confluence 스페이스라 써도 된다"고 승인해, 실제 인스턴스에 임시 페이지를 만들어 `GET /api/v2/pages/{id}/versions`를 직접 호출해봤다. `result.md`/`test.md`에 상세 기록. 결론: `listPageVersions`가 기대한 필드명(`number`/`createdAt`)이 실제 응답과 정확히 일치했다 — 이 PR을 막던 핵심 불확실성이 해소됐다.

## 수용 기준 (Acceptance Criteria)
- [ ] 문서 편집 화면 헤더에 "이력" 버튼을 추가한다(게시 설정과 저장 사이).
- [ ] 클릭하면 이 문서의 버전 목록을 보여주는 Modal이 뜬다 — 버전 번호와 저장 시각을 최신순으로 나열하고, 가장 최근 버전에 "현재 버전" 표시를 한다.
- [ ] 이 화면은 읽기 전용이다 — 특정 버전으로 되돌리기(restore) 등 쓰기 동작은 이번 범위에 없다.
- [ ] 목록 조회가 실패하면 오류 메시지를 안내한다(빈 화면으로 방치하지 않는다).
- [ ] 남의 문서의 버전 이력은 조회할 수 없다(`requireDocumentOwner` 재사용).

## 결정이 필요한 사항
없음 — 다만 위 "PR로 진행하는 이유"에서 밝힌 대로, `GET /api/v2/pages/{id}/versions` 응답 형태에 대한 가정을 실제 인스턴스로 검증하지 못했다. PR 리뷰/머지 전에 실제 환경에서 한 번 확인하는 것을 권장한다.

## 범위 밖
- 특정 과거 버전의 본문 내용을 읽기 전용으로 렌더링하는 것 — 이번엔 "언제 몇 번째 버전이 있었는지" 목록만 다룬다. 과거 버전 내용까지 보여주려면 각 버전의 storage format을 추가로 조회해야 해서 별도 항목으로 다루는 것이 낫다고 판단했다.
- 특정 버전으로 되돌리기(restore).
