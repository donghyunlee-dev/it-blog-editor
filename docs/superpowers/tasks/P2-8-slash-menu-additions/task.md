# P2-8: 인용구·구분선·밑줄 서식과 "제목 3" 진입점 추가

## 배경
- `docs/product/prd.md` Phase 2 체크리스트 항목. [Confluence·Notion 비교 리포트](https://claude.ai/code/artifact/5b088947-cb55-4370-8b61-176510385f84) 2차 개정에서 "QW"(Quick Win)로 분류돼 발견됐다.
- `RichTextEditor.tsx`가 실제로 활성화하는 TipTap 확장을 코드로 직접 확인한 결과, `StarterKit`이 기본으로 켜는 `blockquote`·`horizontalRule`·`underline`과, 명시적으로 `heading: { levels: [1, 2, 3] }`로 설정한 `heading`의 `level: 3`이 **스키마상으로는 이미 활성화돼 있는데도** 버블 툴바·슬래시 메뉴 어디에도 진입점이 없어 발견 자체가 불가능했다(마크다운 입력 규칙이나 `Ctrl+U` 단축키를 우연히 아는 경우에만 접근 가능).
- 새 기능 구현이 아니라 기존 커맨드(`toggleBlockquote`/`setHorizontalRule`/`toggleUnderline`/`setNode("heading", { level: 3 })`)에 UI만 연결하는 작업이다.

## 수용 기준 (Acceptance Criteria)
- [x] "제목 3"을 슬래시 메뉴에 추가한다 — 기존 "제목 1"/"제목 2"와 완전히 같은 방식(`setNode("heading", { level: 3 })`).
- [x] "인용구"(blockquote)를 슬래시 메뉴에 추가한다 — `toggleBlockquote()`.
- [x] "구분선"(horizontal rule)을 슬래시 메뉴에 추가한다 — `setHorizontalRule()`.
- [x] "밑줄"(underline)을 버블 툴바에 토글 버튼으로 추가한다 — `toggleUnderline()`, 기존 굵게/기울임/취소선과 같은 패턴.

## 결정이 필요한 사항
없음 — 각 항목을 슬래시 메뉴와 버블 툴바 중 어디에 넣을지는, 이 코드베이스가 이미 확립한 두 그룹을 그대로 따랐다(추측이 아니라 기존 코드를 근거로 판단):
- **버블 툴바 = 선택한 텍스트에 씌우는 인라인 마크만** — 지금 있는 굵게·기울임·취소선·인라인 코드가 전부 이 종류다. `underline`도 완전히 같은 성격의 마크라 여기 추가한다.
- **슬래시 메뉴 = 블록 구조를 바꾸거나 새 블록을 끼워 넣는 명령** — 지금 있는 "제목 1/2"·"글머리 목록"·"번호 목록"·"표"·"코드블록"이 전부 이 종류이고, 헤딩(제목1/2)은 버블 툴바에 아예 없다. `blockquote`(선택 문단을 인용구로 바꾸는 블록 토글)와 `horizontalRule`(새 블록을 삽입, 선택 텍스트에 씌울 수 있는 성격이 아님)도 이 그룹에 속하므로 슬래시 메뉴에만 추가하고, "제목 3"도 "제목 1/2"와 동일하게 슬래시 메뉴에만 넣는다.

원문 문구("인용구·구분선·밑줄 서식 버튼과 '제목 3' 슬래시 항목")를 문자 그대로 읽으면 인용구·구분선도 "버튼"(버블 툴바)으로 읽힐 수 있으나, 실제 코드의 기존 관례(위 두 그룹)와 각 명령의 성격(구분선은 애초에 "선택 텍스트에 씌우는" 개념 자체가 성립하지 않는 삽입형 명령)을 근거로 슬래시 메뉴로 판단했다 — P1-6a/b, P7-5 등에서 반복된 "순수 UX 구현 디테일은 기존 관례를 근거로 직접 정한다"는 원칙과 같다.

## 범위 밖
- 새 TipTap 확장 설치나 스키마 변경 — 네 커맨드 모두 이미 활성화돼 있었다.
- 버블 툴바의 다른 정렬/재배치(기존 버튼 순서는 그대로 두고 밑줄만 취소선 바로 뒤에 끼워 넣는다).
