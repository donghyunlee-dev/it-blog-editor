# P5-4: 계정 정보 수정 팝업

## 배경
- Phase 5(사용자 계정 관리)의 네 번째 항목. 온보딩(P5-2)은 최초 1회·강제 흐름(전용 페이지)이라 이름·팀을 잘못 입력했거나 나중에 바뀌었을 때 고칠 방법이 없다. 로그인한 사용자가 원할 때 스스로 여는 계정 정보 수정 팝업이 필요하다.
- P5-2 진행 중 "메인에서 팝업으로 받는 방식은 아니다"라는 피드백이 있었지만, 이는 강제 온보딩에 한정된 지적이었다 — 사용자가 스스로 열고 닫을 수 있는 이 팝업까지 페이지로 바꿀 필요는 없다고 판단했다(`docs/superpowers/tasks/P5-2-onboarding-modal/task.md`의 "범위 밖" 참고).
- 관련 문서: [prd.md의 Phase 5](../../../product/prd.md#-단계별-개발-계획)(P5-4), [api-spec.md의 GET·PUT /api/editor/account](../../../product/api-spec.md)

## 수용 기준 (Acceptance Criteria)
- [ ] 사이드바 하단 계정 표시(이메일)를 누르면 계정 정보 Modal이 열린다.
- [ ] Modal은 열릴 때 `GET /api/editor/account`로 현재 이름·팀을 불러와 입력창에 채워 보여준다. 이메일은 읽기 전용으로 함께 보여준다.
- [ ] 이름·팀을 수정하고 저장하면 `PUT /api/editor/account`를 호출하고, 성공 시 Toast로 안내한다(Modal은 열어 둔 채로 — 강제 흐름이 아니므로 자동으로 닫지 않는다).
- [ ] 저장에 실패하면 Toast(danger)로 안내한다(CLAUDE.md 규칙 — 인라인 텍스트 대신 Toast).
- [ ] 위 동작을 검증하는 자동화 테스트가 있다.

## 결정이 필요한 사항
없음 — Phase 5 착수 전 사용자와의 대화로 이미 확정.

## 범위 밖
- 계정 표시 형식을 "이름(이메일)"로 통일하는 것은 P5-5에서 다룬다 — 이 항목은 팝업 자체만 다룬다.
- `accessEnabled`는 이 팝업에서 다루지 않는다(관리자 전용, P5-6).
