# P13-2: 사이드바 행 왼쪽 여백 + 호버 하이라이트 복구

## 배경
P13-1(같은 PR) 적용 후 사용자가 새 캡처로 확인하며 두 가지를 추가로 지적했다(2026-09-14):

1. "선택한 페이지 영역의 왼쪽은 여백이 없어. 게시 아이콘하고 붙어 있어." — 문서 행의 배경
   (선택 시 핑크, `.sidebar-row-active`)이 상태 아이콘과 맞닿아 있다. 원인은 `<Link>`가
   `pr-2`만 있고 `pl-*`가 없어서다. 왼쪽 들여쓰기는 부모 `<li>`의 inline
   `paddingLeft`(`INDENT_BASE_PX + depth * INDENT_STEP_PX`)가 행 전체(배경 포함)를 오른쪽으로
   밀어줄 뿐, 배경 박스 **안쪽** 여백은 아니라서 아이콘이 박스 왼쪽 끝에 바로 붙어 보인다.
2. "마우스 오버 했을 때 폴더, 파일의 선택 영역이 표시되어야 하는데 없어. 선택한 색상보다
   엷은 색상으로 CSS가 적용되어야 하는데 없어." — 코드 확인 결과 `hover:bg-surface-raised`가
   폴더 행·문서 행에 이미 적용돼 있었지만, `node_modules/@sfood/ui/tokens/semantic.css`를
   보면 **라이트 모드에서 `--color-surface-raised`가 `--color-surface`와 같은 값**(둘 다
   `var(--white)`)이라 호버 시 배경색이 전혀 바뀌지 않는다. 같은 원인으로 이미
   `.sidebar-row-active`(2026-08-26)가 `color-mix()`로 직접 배경을 만드는 방식을 쓰고
   있었는데, 호버에는 그 처리가 안 돼 있었다.

## 수용 기준 (Acceptance Criteria)
- [ ] 문서 행(`Link`)에 왼쪽 안쪽 여백(`pl-2`, 오른쪽 `pr-2`와 대칭)이 생겨, 상태 아이콘이
      선택/호버 배경 박스 왼쪽 끝에 바로 붙지 않는다.
- [ ] 폴더 행에도 같은 이유로 왼쪽 안쪽 여백(`pl-1`, 오른쪽 `pr-1`과 대칭)이 생긴다.
- [ ] 폴더 행·문서 행(내 문서·공유받은 문서 모두)에 마우스를 올리면, 선택 상태(핑크, 10%
      브랜드 믹스)보다 옅은 배경(5% 브랜드 믹스)이 라이트/다크 모드 모두에서 보인다.
- [ ] 선택된(활성) 행에는 호버 배경이 덧씌워지지 않는다(기존 동작 유지 — 활성 상태가 우선).
- [ ] 기존 회귀 테스트가 모두 통과한다.

## 결정이 필요한 사항
없음 — 왼쪽 여백 추가와 호버 배경 표시는 사용자가 명시적으로 지적한 결함이라 값에 대한 별도
합의가 필요 없었다(오른쪽 padding·선택 상태 배경 비율과 대칭/비례를 맞추는 것으로 판단).

## 범위 밖
- 사이드바의 다른 `hover:bg-surface-raised` 사용처(정렬/새 폴더/이름변경/삭제 등 아이콘
  버튼, 계정 정보 버튼, 로그아웃 버튼)는 이번 범위에서 다루지 않는다 — 같은 라이트 모드 토큰
  문제가 있을 수 있지만, 사용자가 지적한 건 "폴더, 파일의 선택 영역"에 한정된다. 넓은 범위의
  문제일 수 있어 별도로 조사가 필요하다고 보고, 이번엔 행 배경만 고친다.
- 행 padding을 `py-1.5`보다 더 줄이는 추가 밀도 조정 — 사용자가 "간격이 큰 변화가 없는
  듯하다"고 언급했지만 "더 줄여달라"는 명시적 요청은 아직 없어, 별도 확인 후 진행한다.
