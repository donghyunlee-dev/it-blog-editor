# P14-3: 문서 옵션 메뉴가 사이드바 스크롤 영역에 잘려 안 보이는 문제 수정

## 배경
P14-2까지 사이드바 문서 옵션(⋯) 메뉴는 `@sfood/ui`의 `DropdownMenu`를 그대로 쓰고, 메뉴가
트리거 기준 왼쪽으로 펼쳐지는 문제만 CSS(`[role="menu"] { left: 0; right: auto; }`)로
고쳤다. 그런데 실제로 보니 메뉴가 아예 "문서함 패널 안으로 들어가서 보이지 않는" 현상이
있었다(2026-09-14, 사용자 지적 — "z-index를 완전히 밖으로 빼야 할 거 같아").

원인을 코드로 확인했다: `EditorSidebar.tsx`의 문서 목록을 감싸는 `<nav className="flex-1
overflow-y-auto p-2.5">`가 스크롤 컨테이너다. CSS 스펙상 `overflow-y`가 `visible`이 아니면
`overflow-x`도 `visible`이 아니라 `auto`로 강제 계산되므로(브라우저가 실제로 이렇게
동작한다), 이 `<nav>`는 세로뿐 아니라 가로로 넘치는 자손도 클리핑한다. `DropdownMenu`는
팝업을 트리거를 감싸는 자기 자신의 `position: relative` 래퍼 안에 `position: absolute`로
그리는데, 그 래퍼가 `<nav>` 안(사이드바의 좁은 폭 안)에 있어 메뉴가 사이드바 폭을 넘어
펼쳐지려는 순간 `<nav>`의 overflow에 잘려 안 보인다. **z-index는 스태킹(그리는 순서)만
바꿀 뿐 overflow 클리핑 자체를 뚫지 못하므로, 사용자가 제안한 "z-index를 밖으로 빼는" 접근은
이 문제의 원인과 맞지 않는다** — 실제로는 팝업이 클리핑 조상(`<nav>`) 자체를 벗어나야 한다.

## 수용 기준 (Acceptance Criteria)
- [ ] 문서 옵션 메뉴를 열면, 사이드바 폭을 넘어 본문(페이지) 영역까지 잘리지 않고 온전히
      보인다(뷰포트 좌표 기준으로 그려야 한다 — `<nav>`의 overflow에 영향받지 않아야 한다).
- [ ] 메뉴는 여전히 트리거 바로 아래·왼쪽 정렬(페이지 방향으로 펼쳐짐)에서 열린다.
- [ ] 바깥 클릭·Escape로 닫히는 기존 동작(`@sfood/ui`의 `DropdownMenu`가 제공하던 것)을
      동일하게 유지한다.
- [ ] 사이드바를 스크롤하거나 창 크기를 바꾸면(앵커 좌표가 낡아지므로) 메뉴가 닫힌다.
- [ ] 기존 회귀 테스트(`role="button"`으로 트리거 찾기, `role="menuitem"`으로 항목 찾기)가
      그대로 통과한다 — 접근성 역할·라벨은 바꾸지 않는다.

## 결정이 필요한 사항
없음 — 원인·해법(포탈 방식이 아니라 `<nav>` 바깥 형제 위치에 `position: fixed`로 직접
그리는 방식) 모두 코드 분석으로 확정했다.

## 범위 밖
- `@sfood/ui`의 `DropdownMenu` 자체를 고치는 것 — 패키지 내부라 이 프로젝트에서 손댈 수 없다.
- 이 프로젝트의 다른 곳에서 `DropdownMenu`를 쓰는 사례 — 없음(문서 옵션 메뉴가 유일한
  사용처였고, 이제 커스텀 구현으로 교체됐다).
