# P7-5: 새 폴더 만들기·이름 변경·삭제 UI

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조) 체크리스트 항목. P7-1~4가 끝나 도메인 함수·API(`folders.ts`, `/api/editor/folders*`)와 사이드바 폴더 트리 UI(P7-4, 조회 전용)까지 갖췄다 — 하지만 **폴더를 만들 UI 자체가 아직 없다.** 지금까지는 API를 직접 호출해야만 폴더가 생겼다(P7-4 테스트가 `folders` prop을 직접 주입해 검증한 것도 이 때문).
- 원문 수용 기준: "Modal+FormField로 생성/이름변경, 삭제는 문서 삭제와 동일하게 Modal 확인 절차를 거친다. 저장 성공/실패는 Toast로 안내(CLAUDE.md UI 규칙 준수)."

## 수용 기준 (Acceptance Criteria)
- [ ] 사이드바 폴더 트리 위에 "새 폴더" 진입점(+ 버튼)이 있다 — **폴더가 하나도 없는 계정에서도 보인다**(그렇지 않으면 첫 폴더를 만들 방법이 없다).
- [ ] 각 폴더 행에 "하위 폴더 추가"·"이름 변경"·"삭제" 액션이 있다(평소엔 숨겨져 있다가 행에 마우스를 올리거나 키보드 포커스가 들어오면 나타난다).
- [ ] 생성·이름변경은 `Modal`+`FormField`(이름 입력 하나)로 이뤄진다. 저장 성공/실패는 `Toast`로 안내한다.
- [ ] 삭제는 `window.confirm()` 대신 `Modal`로 확인받는다(CLAUDE.md 규칙, `DocumentEditor.tsx`의 "문서 삭제" Modal과 동일한 패턴) — 안내 문구는 삭제 시 그 안의 하위 폴더·문서가 사라지는 게 아니라 상위 위치로 승격된다는 사실을 정확히 전달한다(실제 `deleteFolder`/`promoteDocumentsFromDeletedFolder` 동작과 일치).
- [ ] 저장/삭제 성공 시 `router.refresh()`로 서버 컴포넌트(`layout.tsx`)가 최신 `folders`/`documents`를 다시 내려주도록 한다(`DeletedDocumentsModal.tsx`의 `onRestored` 선례와 동일한 패턴 — 별도 클라이언트 캐시 무효화 인프라를 새로 만들지 않는다).

## 결정이 필요한 사항
없음 — 새 폴더 진입점 위치(트리 상단), 액션 노출 방식(hover/focus-within), 삭제 확인 문구는 순수 UX 구현 디테일이라 GitHub Issue 없이 직접 정한다(P1-6a와 같은 근거). 폴더 중첩 깊이 제한(5단계)은 이미 서버가 검증하므로 클라이언트에서 미리 막지 않고 실패 시 Toast로 안내한다(서버 검증 하나만 신뢰 — 이중 검증 로직을 만들지 않는다).

## 범위 밖
- 문서를 폴더로 옮기는 UI는 P7-6, 편집 화면 브레드크럼은 P7-7이 각각 다룬다.
- 폴더 자체를 다른 폴더 밑으로 옮기는 기능은 PRD 어디에도 명시돼 있지 않다(P7-2 task.md에서 이미 확인된 사실) — 이번에도 다루지 않는다.
- 빈 폴더 전용 안내 문구(EmptyState)는 P7-8의 몫이다.
