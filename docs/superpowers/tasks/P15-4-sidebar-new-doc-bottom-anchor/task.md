# P15-4: "새 문서" 버튼이 목록이 짧아도 항상 패널 하단에 보이도록 재구성

## 배경
P15-3에서 "새 문서" 버튼에 `sticky bottom-0`을 줬는데, 사용자 확인(머지 후) 결과 여전히
"다시 화면 그렸을 때 그대로 미분류에 붙어 있어"라는 문제가 남아 있었다.

원인: `position: sticky`는 **스크롤이 실제로 발생할 때만** 효과가 있다 — 스크롤 컨테이너
(`<nav overflow-y-auto>`) 안의 콘텐츠가 컨테이너보다 짧으면(문서가 몇 개 없는 대부분의
계정) 애초에 스크롤이 생기지 않고, sticky 요소는 그냥 자기 자리(문서 목록 바로 다음)에
얌전히 남는다 — "빈 공간을 채워서 바닥까지 밀어주는" 효과가 없다. 즉 P15-3은 "목록이
길 때" 케이스만 고쳤고, "목록이 짧을 때"(더 흔한 케이스) 는 그대로였다.

추가로 사용자가 지적: 버튼 wrapper에 넣었던 `border-t`(구분선)도 "왼쪽 패널에 라인이
너무 많다"는 이유로 빼야 한다.

## 수용 기준 (Acceptance Criteria)
- [x] 문서가 적어(목록이 `<nav>`보다 짧아) 스크롤이 없어도 "새 문서" 버튼이 사이드바
      패널의 맨 아래에 보인다(더 이상 미분류 바로 아래에 붙어 있지 않음).
- [x] 문서가 많아 목록이 길어도(P15-3이 다루던 케이스) 버튼은 계속 하단에 보인다 — 회귀
      없음.
- [x] "새 문서" 버튼 영역에 구분선(`border-t`)을 넣지 않는다.
- [x] href·클릭 동작(미분류 문서 생성)은 그대로다.

## 결정이 필요한 사항
없음 — 사용자가 문제(짧은 목록에서도 재현됨)와 구분선 제거 방향을 직접 확인·지시했다.

## 범위 밖
- 이번에도 위치 이동 + 새 문서 기능 범위로만 검증한다(전체 스위트 실행 안 함).
