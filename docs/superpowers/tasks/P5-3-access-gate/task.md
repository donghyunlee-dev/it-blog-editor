# P5-3: 접속 권한 게이트

## 배경
- Phase 5(사용자 계정 관리)의 세 번째 항목. P5-1에서 만든 `accountMeta.accessEnabled`를 실제로 강제하는 항목이다 — 관리자가 계정을 차단(N)해도 지금은 아무 효과가 없다(코드가 값을 읽는 곳이 없음).
- 관련 문서: [prd.md의 Phase 5](../../../product/prd.md#-단계별-개발-계획)(P5-3), [prd.md 기능별 정의의 "접속 권한 게이트"](../../../product/prd.md#-기능별-정의), [api-spec.md의 `ACCESS_DISABLED`](../../../product/api-spec.md)

## 수용 기준 (Acceptance Criteria)
- [ ] `accountMeta.accessEnabled === false`인 계정으로 `/editor`(하위 라우트 포함)에 접근하면, 리다이렉트 없이 그 자리에서 접속 차단 안내 화면이 렌더링된다(사이드바·문서 목록 등 메인 콘텐츠는 전혀 렌더링되지 않음).
- [ ] `accessEnabled === true`(기본값 포함)인 계정은 지금까지와 동일하게 정상 진입한다.
- [ ] 접속이 차단된 계정은 온보딩 여부와 무관하게 차단 화면을 먼저 본다 — `needsOnboarding`이 true여도 `/welcome`로 리다이렉트되지 않는다.
- [ ] `/api/editor/**` 엔드포인트도 접속 차단된 계정의 요청에 403(`ACCESS_DISABLED`)을 반환한다. 계정 폴더가 아직 없는 세션(이론상 `/editor`를 한 번도 렌더링하지 않은 경우)은 검사 대상에서 제외한다 — 확인할 `accountMeta` 자체가 없기 때문.
- [ ] 차단 화면에는 로그아웃 진입점이 있다(막힌 화면에서 빠져나갈 방법이 없으면 안 됨).
- [ ] 위 동작을 검증하는 자동화 테스트가 있다.

## 결정이 필요한 사항
없음 — Phase 5 착수 전 사용자와의 대화로 이미 확정([prd.md](../../../product/prd.md#phase-5--사용자-계정-관리-신규-2026-09-03-계획) 참고).

## 범위 밖
- `accessEnabled` 값을 실제로 바꾸는 관리자 스크립트는 P5-6에서 다룬다 — 이 항목은 이미 `false`로 저장되어 있는 값을 "강제하는" 쪽만 다룬다.
- 계정 관리 페이지(목록·검색)는 P5-7에서 다룬다.
