# P7-10: 모바일 대응 + 접근성

## 배경
- `docs/product/prd.md` Phase 7(문서 폴더 구조)의 마지막 항목. P7-4가 사이드바 폴더 트리를 처음 만들 때 "키보드 방향키 트리 탐색·WAI-ARIA `tree`/`treeitem` 패턴은 의도적으로 범위 밖에 남겼다(P2-1a~c 선례와 같은 순서 — 기능 먼저, 접근성 보강은 나중에)"고 명시했다 — 이 항목이 그 유예를 갚는다.
- 원문 수용 기준: "오프캔버스 드로어에서 폴더 트리가 정상 동작함을 확인하고(P2-1c 패턴 재사용), 키보드 트리 탐색(방향키로 펼침/접힘, WAI-ARIA `tree`/`treeitem` 패턴)까지 구현해야 완료로 표시한다(P2-1a·P2-1b 선례와 동일 기준 — 접근성 보강을 별도 후속 Phase로 미루지 않는다)."

## 수용 기준 (Acceptance Criteria)
- [x] 사이드바 폴더 트리에 WAI-ARIA 트리 뷰 구조를 붙인다: 트리 루트 `role="tree"`, 각 폴더·문서 행 `role="treeitem"`(`aria-level`, 폴더는 `aria-expanded`, 둘 다 `aria-selected`), 하위 목록 `role="group"`.
- [x] 방향키로 트리를 탐색할 수 있다 — ArrowDown/ArrowUp은 지금 화면에 보이는 다음/이전 항목으로, ArrowRight는 접힌 폴더를 펼치거나(이미 펼쳐져 있으면) 첫 자식으로, ArrowLeft는 펼쳐진 폴더를 접거나(이미 접혀 있거나 리프 노드면) 상위 폴더로, Home/End는 트리에서 보이는 첫/마지막 항목으로 이동한다.
- [x] 기존 Tab 순서·마우스 클릭 동작은 그대로 유지한다 — 방향키 탐색은 얹는 추가 수단이지, 대체가 아니다(로빙 tabindex 등 전면 재작성은 하지 않는다).
- [x] 모바일 오프캔버스 드로어(P2-1c) 안에서도 폴더 트리가 정상 동작함을 회귀 테스트로 고정한다 — 포커스 트랩(Tab 순환)이 폴더 트리가 추가한 요소(토글·액션 버튼·이동 버튼)까지 포함하고, 트랩의 키보드 처리(Tab/Escape)가 트리 방향키 탐색과 충돌하지 않는다.

## 결정이 필요한 사항
없음 — "로빙 tabindex를 포함한 완전한 APG 트리 위젯 재작성"과 "기존 Tab 순서를 그대로 두고 방향키 탐색만 얹는 절충안" 중 후자를 택했다. 현재 포커스 가능 요소(폴더 토글 버튼, 하위 폴더 추가·이름변경·삭제·문서 이동 버튼, 문서 링크)가 전부 실제 상호작용을 가진 개별 컨트롤이라, 이들을 하나의 로빙 tabindex 그룹으로 묶으면 Tab 키로 각 액션 버튼에 개별 접근하던 기존 동작(P7-5/P7-6)이 깨진다 — 이미 있는 정상 동작을 접근성 보강 때문에 퇴보시키지 않는 것이 우선이라는 판단이다(P1-6a/b, P7-5 등에서 반복된 "순수 UX/구현 디테일은 직접 정한다" 원칙과 같은 근거).

## 범위 밖
- 로빙 tabindex(트리 안에서 Tab 키 자체의 의미를 바꾸는 것)를 포함한 전면적인 APG 트리 위젯 재작성.
- 폴더 트리 바깥의 "미분류" 평문 목록·"공유받은 문서" 목록에 대한 트리 탐색(그 목록들은애초에 트리 구조가 아니다).
- 사이드바 전체의 반응형 레이아웃 자체를 다시 다듬는 것(이미 P2-1c에서 끝났다 — 이번엔 그 위에 폴더 트리가 얹혀도 깨지지 않는지만 확인한다).
