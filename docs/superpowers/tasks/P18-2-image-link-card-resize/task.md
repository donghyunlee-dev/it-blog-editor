# P18-2: 이미지/문서 링크 카드 크기 조절

## 배경
- PRD(`docs/product/prd.md`) Phase 18 항목 — 사용자 지적: "resize에 대한 기능이
  없어. 링크라든가 이미지의 사이즈를 조절하면 좋은데 무조건 editor의 가로 full
  사이즈로 설정이 돼. 컴포넌트의 오른쪽 하단이나 우측 경계에 사이즈 조절하는 바가
  있어서 작게, 크게, 폭이 좁게 넓게 움직이면서 사이즈 조절을 하면 좋을 것 같아."
- 원인: 이미지는 Tailwind Preflight 기본값(`img { max-width: 100%; height:
  auto; }`)이 유일한 폭 제약이라, 업로드된 사진 대부분이 편집기 폭보다 넓어 항상
  정확히 100%로 맞춰져 보인다 — 이보다 좁게 줄일 방법이 없다. 문서 링크 카드
  (`.document-link-card`)는 아예 `width: 100%`가 CSS로 고정돼 있어 마찬가지다.
  둘 다 크기를 조절할 UI 자체가 없다.

## 수용 기준 (Acceptance Criteria)
- [x] 이미지를 선택하면 우측 경계에 드래그 가능한 핸들이 보이고, 좌우로 드래그하면
      너비가 줄거나 늘어난다(높이는 종횡비를 유지하며 자동으로 맞춰진다).
- [x] 문서 링크 카드를 선택하면 마찬가지로 우측 경계에 드래그 핸들이 보이고, 좌우로
      드래그하면 카드 너비가 줄거나 늘어난다(높이는 내용 기준 자동).
- [x] 둘 다 편집기 본문 폭을 넘어 커지지 않는다(최대 100%로 clamp).
- [x] 둘 다 너무 작아지지 않게 최소 너비로 clamp된다.
- [x] 드래그를 마치면(mouseup) 그 시점의 너비가 노드 attrs(`width`, 이미지는
      `height`도)로 저장되어 `onChange`에 반영된다 — 문서를 다시 열어도 크기가
      유지된다.
- [x] 크기를 조절하지 않은 기존 이미지/카드는 이전과 동일하게(이미지는 100% 폭,
      카드는 100% 폭) 보인다 — 하위 호환.

## 결정이 필요한 사항
사용자에게 이미 확인했다(AskUserQuestion, 2026-09-17) — "이미지만 먼저" vs "이미지+
문서 링크 카드 둘 다"를 물었고 "둘다 다 가능했으면 좋겠어"라고 답해 **둘 다 이번에
함께 구현**하기로 확정했다.

## 범위 밖
- 문서 링크 카드의 높이 조절 — 카드는 내용(제목 길이) 기준 높이가 자연스럽다.
- 이미지 가로세로 개별(비율 무시) 조절 — 항상 원본 종횡비 유지.
- 크기 조절 핸들의 키보드 조작 — 마우스 드래그만 지원(대부분의 에디터가 같은
  범위로 다룬다).
- Confluence 게시(storage format) 시 크기 값 반영 — 이 앱 자체의 편집/저장/재로드
  왕복에서는 이미 TipTap JSON(`sourceDocument`)에 attrs가 그대로 남아 정상
  동작한다. Confluence storage export(`tiptap-to-storage.ts`)에 `ac:width`를
  추가하는 것은 이번 작업의 핵심(에디터 안에서 크기 조절)과 무관한 별도 개선이라
  범위 밖으로 둔다.
